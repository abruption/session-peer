# Issue #69 技术验证 — 2026-09-16

## 决策

设备配对、经过身份验证的直接传输以及不透明的公共 WebSocket 中继，
在 #47 的适配器/传输分离架构下是可行的。本实验是一个隔离的原型，
不是生产实现，也不建议部署当前代码。实验仅使用确定性的夹具适配器；
未涉及任何真实的 Claude/Codex 会话、队列、凭据或模型配额。

该工作树基于本地提交 `993d04d`。产品 CLI、依赖项、打包方式和版本均未更改。
本次试验不包含远程推送、PR 或发布。复现步骤和协议边界请参阅
[README](README.zh-CN.md)。

只在两台 Mac 上终止。这是在 WebSocket 上运行的应用层 E2EE，并非新部署的
WireGuard 隧道或 NAT 穿透实现。

临时公共主机名为 `relay-test.abruption.dev`。公共试验于
**2026-09-16 KST 21:13:09 至 21:20:33** 运行。通往 Cloudflare 的路由使用
普通网络接口（mini：en1；MacBook：en7），而不是 Tailscale。Tailscale 仍可用于

## 试验期间的发现

1. 第一次直接配对尝试超时，随后 TCP 探测和重试成功。当时没有任何对等方被提交。
   原因尚未得到确证；启动/就绪诊断需要改进。
2. MacBook Python 的默认 CA 文件/目录路径不存在。为测试进程设置
   `SSL_CERT_FILE=/etc/ssl/cert.pem` 后启用了外层 HTTPS 验证。验证从未被禁用，
   也没有更改任何全局设置。
3. urllib 的默认用户代理收到 Cloudflare HTTP 403。显式使用
   `session-peer-relay69-lab/1.0` 用户代理后成功，curl 对照也成功。未识别具体的
   Cloudflare 规则，也未更改任何 WAF 策略。
4. 后端重启后立即发出的客户端请求失败，稍后的请求成功。生产实现需要有界的重连/
   退避、就绪检查以及不泄露凭据的实用类型化错误。
5. 冷启动公共中继的建立过程占据了大部分延迟。在集成一次性 CLI 工作流之前，
   应测量持久身份验证通道的表现。

## 隔离、资源与清理

美国服务器进程使用临时 systemd 单元运行，配置包括 DynamicUser、无 capabilities、
只读代码、受限目录、私有 tmp/设备、30 分钟运行时限、MemoryMax 256 MiB、
CPUQuota 50% 和 TasksMax 64。预检确认其他 home 目录及选定的产品目录不可读。
Cgroup IP 策略允许韩国服务器访问该后端。Mac 夹具使用私有临时状态，
而不是 Linux 服务的操作系统沙箱。

观测到的美国服务器峰值内存为 26,189,824 字节（约 25 MiB）、一个任务，
两个后端进程合计约 1.002 CPU 秒。这些低流量观测无法验证在持续恶意负载下的限制。

本次试验仅在现有 Cloudflare 入口下添加了精确主机的 Caddy 块。未添加 DNS 记录、
全局防火墙规则、持久账户或全局 Python 软件包。更改前准备了定时回滚。
Caddy 重载可能影响现有 WebSocket 客户端；未测量对所有用户会话的影响。
现有聊天健康检查端点在试验前、试验中和试验后均返回 HTTP 200。

清理过程停止了 MacBook 接收器和美国中继，确认不存在试验监听器，删除了远程代码/
状态/凭据和精确 Caddy 块，并停止回滚计时器。Caddy 保持活动，且恢复了其原始
SHA-256：`60ae35627b82d65724ceac89421e1f92ba475b675fd146b4036129f352197ebb`。
之后，测试主机名恢复返回原来的 HTTP 301 重定向。仅保留经过清理的测量结果后，
本地试验密钥和凭据均已删除。

## 剩余边界与后续步骤

外层准入使用预配的房间/角色 bearer 凭据和短期 cookie；它不是与设备绑定的证明。
Cloudflare/Caddy 可以看到这些外层凭据和元数据。内部固定的双向 TLS 对对等方进行
身份验证并保护应用载荷。生产实现需要绑定来源的准入配置、凭据轮换、每设备配额
以及协议审查。

邀请传输使用可信的管理路径和私有文件。目前没有移动端 QR/SAS 用户体验、
硬件密钥存储、无缝证书续期、离线队列、生产级接收器生命周期或原生代理授权集成。
仅依靠文件系统权限并不等同于钥匙串。本实验中的证书有效期很短，轮换需要先撤销
再重新配对。

直接连接成功是指 tailnet TCP，而不是公共点对点 NAT 穿透。Windows、关闭 VPN 的
移动客户端、IPv6 源站策略、当前 OCI API 防火墙状态、大规模拒绝服务行为以及独立
安全审查仍未验证。从一个观测点对公共源站进行的直接探测发生了超时。

建议的下一阶段范围：定义稳定的设备/回执模式和生命周期；测量连接复用与重连行为；
加强外层准入和密钥存储；然后在启用任何真实代理适配器之前审查协议。在完成这些
决策之前，应让本实验保持可选且隔离。
