# Issue #69 技術検証 — 2026-09-16

## 決定事項

デバイスのペアリング、認証済み直接トランスポート、および不透明なパブリックWebSocketリレーは、#47のアダプター／トランスポート分離によって実現可能です。この実験は孤立したプロトタイプであり、本番向けの実装でも現在のコードのデプロイを推奨するものでもありません。決定論的フィクスチャアダプターのみを使用しており、実際のClaude/Codexセッション、キュー、認証情報、モデルクォータは一切関与していません。

ワークツリーはローカルコミット `993d04d` に基づいています。製品のCLI、依存関係、パッケージング、およびバージョンは変更されていません。リモートへのプッシュ、PR、リリースはいずれもこの試行には含まれません。再現手順およびプロトコルの境界については [README](README.ja.md) を参照してください。

## 実際のトポロジと測定値

Direct: tailnet TCP経由の Mac mini → MacBook。Relay: 各Macが独立してアウトバウンドのWSS接続を確立 → Cloudflare → KR Caddy → US tailnetバックエンド。内部TLS 1.3は2台のMacでのみ終端されます。これはWebSocket上のアプリケーションE2EEであり、新しくデプロイされたWireGuardトンネルやNATトラバーサル実装ではありません。

一時的なパブリックホスト名は `relay-test.abruption.dev` でした。パブリックな試行は **2026-09-16の21:13:09から21:20:33 KST** に実施されました。Cloudflareへのルートには、Tailscaleではなく通常のネットワークインターフェース（mini: en1、MacBook: en7）が使用されました。Tailscaleは管理／直接トラフィック用に引き続き利用可能でした。VPNを無効化したモバイルデバイスでのテストは行われませんでした。

パブリックペアリング、直接接続の優先、直接ルート利用不可時のリレーフォールバック、応答消失ステータスの整合、およびルート間の重複抑止はすべて成功しました。フィクスチャは23のエフェクト、重複ゼロ、保留エントリゼロを記録しました。ペアリングされたパブリッククライアントを失効させることで、その後の使用が防止されました。バックエンドの再起動後、新たなアドミッションと10件のウォームリレーリクエストは成功しましたが、再起動中の即時リクエストは失敗しました。中断のない復旧は実証されませんでした。

## 検証

- macOS Python 3.14/OpenSSL 3.6 および Ubuntu arm64 Python 3.12/OpenSSL 3.0 で、20件のラボ統合テストに合格しました。実機のMacBookでは Python 3.13/OpenSSL 3.0 が動作していました。
- リポジトリ全体の統合スイートは、オプションのMCPおよびラボ依存関係を含め、7.751秒で **335件のテスト** に合格しました。Ubuntuでのラボテストは4.701秒で合格しました。
- テストでは、実際のループバックTLS/WebSocketトラフィック、証明書の差し替え、TLSの改ざん／リプレイ、ペアリングの期限切れ／再利用、コミット応答の喪失、失効、クラッシュの曖昧性、重複ID、リクエストの境界、リレー認証、リソース制限、遅延転送、リダイレクトの拒否、および鍵ファイルの権限を検証しています。
- キャプチャされたローカルリレーフレームには、センチネルプレーンテキスト、招待シークレット、秘密鍵は含まれていませんでした。パブリックリレーのペイロードキャプチャは無効化されていたため、これはエッジ／プロキシの可観測性に関する完全な監査ではありません。
- Wheelおよびsdistのビルドは正常に完了し、この実験は除外されています。オプションのラボインポートによって、インストールされた製品に依存関係やリスナーが追加されることはありません。

意図ジャーナルは最大1回の実行試行をサポートします。エフェクトの発生後、レシートのコミット前にクラッシュした場合、結果は不明のままとなり、自動的な再実行は防止されます。これは意図的に厳密に1回のネイティブ配信を主張するものではありません。`submitted` と `consumptionConfirmed` は分離されたままです。

## 試行中に判明した事項

1. 最初の直接ペアリングの試行はタイムアウトしましたが、その後のTCPプローブと再試行は成功しました。ピアはコミットされていませんでした。原因は決定的に特定されておらず、起動／レディネス診断の改善が必要です。
2. MacBook PythonのデフォルトCAファイル／ディレクトリパスが存在しませんでした。テストプロセスに `SSL_CERT_FILE=/etc/ssl/cert.pem` を設定することで、外部HTTPS検証が有効になりました。検証が無効化されることはなく、グローバル設定も変更されていません。
3. デフォルトのurllibユーザーエージェントはCloudflareからHTTP 403を受信しました。明示的な `session-peer-relay69-lab/1.0` ユーザーエージェントおよびcurlでの比較は成功しました。特定のCloudflareルールは特定されておらず、WAFポリシーも変更されていません。
4. バックエンド再起動直後のクライアントリクエストは失敗しましたが、その後のリクエストは成功しました。本番向けの作業では、境界付きの再接続／バックオフ、レディネス、および認証情報を漏洩しない有用な型付けされたエラーが必要です。
5. コールドパブリックリレーのセットアップがレイテンシの大部分を占めています。ワンショットのCLIワークフローを統合する前に、永続的な認証済みチャネルの測定を行う価値があります。

## 隔離、リソース、およびクリーンアップ

USプロセスは、DynamicUser、ケーパビリティなし、読み取り専用コード、制限付きディレクトリ、プライベートtmp/デバイス、30分のランタイム制限、MemoryMax 256 MiB、CPUQuota 50%、TasksMax 64 を指定した一時的なsystemdユニットを使用しました。事前チェックにより、他のホームディレクトリおよび選択された製品ディレクトリが読み取り不可であることが確認されました。cgroup IPポリシーにより、KRからこのバックエンドへのアクセスが許可されました。Macフィクスチャは、LinuxサービスのOSサンドボックスではなく、プライベートな一時状態を使用しました。

観測されたUSのピークメモリは2つのバックエンドプロセス全体で 26,189,824 バイト（約25 MiB）、1タスク、約1.002 CPU秒でした。これらの低負荷の観測結果は、敵対的な持続負荷の下での制限を検証するものではありません。

この試行では、既存のCloudflareイングレス配下に完全一致ホストのCaddyブロックのみを追加しました。DNSレコード、グローバルファイアウォールルール、永続アカウント、グローバルPythonパッケージは追加されていません。変更前にはタイマー付きロールバックが準備されました。Caddyのリロードは既存のWebSocketクライアントに影響を与える可能性がありましたが、ユーザーセッションへの完全な影響は測定されませんでした。既存のチャットヘルスエンドポイントは、変更前、変更中、変更後を通じてHTTP 200を返しました。

クリーンアップでは、MacBookレシーバーとUSリレーを停止し、試行リスナーが存在しないことを確認し、リモートコード／状態／認証情報を削除し、該当のCaddyブロックを削除して、ロールバックタイマーを停止しました。Caddyはアクティブなままであり、元のSHA-256が復元されました:
`60ae35627b82d65724ceac89421e1f92ba475b675fd146b4036129f352197ebb`。
テスト用ホスト名はその後、元のHTTP 301リダイレクトを返しました。ローカルの試行鍵および認証情報は、サニタイズされた測定値のみを保持した後に削除されました。

## 残された境界と次のステップ

外部アドミッションには、プロビジョニングされたルーム／ロールのBearer認証情報と有効期間の短いCookieが使用され、デバイスにバインドされた証明ではありません。Cloudflare/Caddyはこれらの外部認証情報とメタデータを参照できます。内部のピン留めされた相互TLSがピアを認証し、アプリケーションペイロードを保護します。本番向けの作業には、オリジンにバインドされたアドミッション設定、認証情報のローテーション、デバイスごとのクォータ、およびプロトコルのレビューが必要です。

招待の転送には、信頼できる管理パスとプライベートファイルが使用されました。モバイル向けのQR/SAS UX、ハードウェア鍵ストレージ、シームレスな証明書更新、オフラインキュー、本番レシーバーのライフサイクル、ネイティブエージェントの認可統合はありません。ファイルシステムの権限だけではキーチェーンにはなりません。このラボの証明書は有効期間が短く、ローテーションには失効と再ペアリングが必要です。

直接接続の成功はtailnet TCPを意味し、パブリックなピアツーピアNATトラバーサルではありません。Windows、モバイルのVPN無効クライアント、IPv6オリジンポリシー、現在のOCI APIファイアウォールの状態、大規模なサービス拒否（DoS）動作、および独立したセキュリティレビューは未検証のままです。直接のパブリックオリジンプローブは、1つの観測点からのみタイムアウトしました。

推奨される次のスコープ: 安定したデバイス／レシートスキーマとライフサイクルの定義、接続再利用および再接続動作の測定、外部アドミッションと鍵ストレージの強化、その上で実際のエージェントアダプターを有効化する前のプロトコルレビューです。これらの決定が行われる間、このラボはオプションかつ孤立した状態を維持してください。
