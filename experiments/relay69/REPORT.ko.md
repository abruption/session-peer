## 결정

기기 페어링, 인증된 직접 트랜스포트 및 불투명한 공용 WebSocket 릴레이는 #47 어댑터/트랜스포트 분리를 통해 실현 가능합니다. 이 실험은 격리된 프로토타입이며, 프로덕션 구현이나 현재 코드를 배포하라는 권장 사항이 아닙니다. 결정론적 픽스처 어댑터만을 독점적으로 사용하며, 실제 Claude/Codex 세션, 큐, 자격 증명 또는 모델 쿼터는 관여되지 않았습니다.

작업 트리는 로컬 커밋 `993d04d`를 기반으로 합니다. 제품 CLI, 의존성, 패키징 및 버전은 변경되지 않고 유지됩니다. 원격 푸시, PR 또는 릴리스는 이 시험의 일부가 아닙니다. 재현 및 프로토콜 경계에 대해서는 [README](README.ko.md)를 참조하십시오.

## 실제 토폴로지 및 측정값

직접 연결: tailnet TCP 기반 Mac mini → MacBook. 릴레이: 각 Mac이 독립적으로 아웃바운드 WSS 연결 생성 → Cloudflare → KR Caddy → US tailnet 백엔드. 내부 TLS 1.3은 두 Mac에서만 종단됩니다. 이는 새로 배포된 WireGuard 터널이나 NAT 통과 구현이 아닌, WebSocket 기반 애플리케이션 E2EE입니다.

임시 공용 호스트 이름은 `relay-test.abruption.dev`였습니다. 공용 시험은 **2026-09-16 21:13:09부터 21:20:33 KST까지** 진행되었습니다. Cloudflare로의 경로는 Tailscale 대신 일반 네트워크 인터페이스(mini: en1, MacBook: en7)를 사용했습니다. Tailscale은 관리/직접 트래픽용으로 계속 사용할 수 있었습니다. VPN이 비활성화된 모바일 기기는 테스트되지 않았습니다.

## 검증

- macOS Python 3.14/OpenSSL 3.6 및 Ubuntu arm64 Python 3.12/OpenSSL 3.0에서 20개의 실험실 통합 테스트를 통과했습니다. 실제 MacBook에서는 Python 3.13/OpenSSL 3.0이 실행되었습니다.
- 결합된 저장소 제품군은 선택적 MCP 및 실험실 의존성을 포함하여 7.751초 만에 **335개의 테스트**를 통과했습니다. Ubuntu 실험실 테스트는 4.701초 만에 통과했습니다.
- 테스트는 실제 루프백 TLS/WebSocket 트래픽, 인증서 대체, TLS 변조/재생, 페어링 만료/재사용, 유실된 커밋 응답, 철회, 충돌 모호성, 중복 ID, 요청 경계, 릴레이 인증, 리소스 제한, 느린 전달, 리디렉션 거부 및 키 파일 권한을 실행하고 검증합니다.
- 캡처된 로컬 릴레이 프레임에는 센티널 평문, 초대 시크릿 또는 개인 키가 포함되지 않았습니다. 공용 릴레이 페이로드 캡처는 비활성화되었으며, 이는 엣지/프록시 관측 가능성에 대한 완전한 감사가 아닙니다.
- Wheel과 sdist는 성공적으로 빌드되며 해당 실험을 제외합니다. 선택적 실험실 import는 설치된 제품에 의존성이나 리스너를 추가하지 않습니다.

의도 저널은 최대 한 번(at-most-once) 실행 시도를 지원합니다. 효과 발생 후 영수증 커밋 전에 비정상 종료되면 알 수 없는 결과가 남으며 자동 재실행이 방지됩니다. 이는 의도적으로 네이티브의 정확히 한 번(exactly-once) 전달을 주장하지 않습니다. `submitted`와 `consumptionConfirmed`는 계속 분리되어 유지됩니다.

## 시험 중 발견 사항

1. 첫 번째 직접 페어링 시도는 이후의 TCP 프로브 및 재시도가 성공하기 전에 시간 초과되었습니다. 커밋된 피어는 없었습니다. 원인은 명확하게 규명되지 않았으며, 시작/준비 상태 진단 기능을 개선해야 합니다.
2. MacBook Python의 기본 CA 파일/디렉터리 경로가 존재하지 않았습니다. 테스트 프로세스에 `SSL_CERT_FILE=/etc/ssl/cert.pem`을 설정하여 외부 HTTPS 검증을 활성화했습니다. 검증은 결코 비활성화되지 않았으며 전역 설정도 변경되지 않았습니다.
3. 기본 urllib user agent는 Cloudflare HTTP 403을 수신했습니다. 명시적인 `session-peer-relay69-lab/1.0` user agent는 성공했으며 curl 비교 테스트도 성공했습니다. 구체적인 Cloudflare 규칙은 확인되지 않았으며 WAF 정책도 변경되지 않았습니다.
4. 백엔드 재시작 직후의 클라이언트 요청은 실패했고 이후의 요청은 성공했습니다. 프로덕션 작업에는 제한된 재연결/백오프, 준비 상태 확인, 자격 증명을 노출하지 않는 유용한 타입화된 오류가 필요합니다.
5. 콜드 공용 릴레이 설정이 지연 시간의 대부분을 차지합니다. 단일 실행(one-shot) CLI 워크플로를 통합하기 전에 영구 인증 채널을 측정해 볼 가치가 있습니다.

## 격리, 리소스 및 정리

US 프로세스는 DynamicUser, 권한(capabilities) 없음, 읽기 전용 코드, 제한된 디렉터리, 비공개 tmp/devices, 30분 실행 시간 제한, MemoryMax 256 MiB, CPUQuota 50%, TasksMax 64가 적용된 임시 systemd 유닛을 사용했습니다. 사전 점검을 통해 다른 홈 및 선택된 제품 디렉터리를 읽을 수 없음을 확인했습니다. Cgroup IP 정책은 이 백엔드에 대한 KR 접근을 허용했습니다. Mac 픽스처는 Linux 서비스의 OS 샌드박스가 아닌 비공개 임시 상태를 사용했습니다.

관측된 US 최대 메모리는 26,189,824 바이트(약 25 MiB), 1개 태스크, 2개 백엔드 프로세스에 걸쳐 약 1.002 CPU 초였습니다. 이러한 소규모 관측 데이터는 적대적인 지속 부하 상태에서의 제한 한계를 검증하지 못합니다.

이 시험은 기존 Cloudflare 인그레스 아래에 정확한 호스트(exact-host) Caddy 블록만을 추가했습니다. DNS 레코드, 전역 방화벽 규칙, 영구 계정 또는 전역 Python 패키지는 추가되지 않았습니다. 변경 전에 시간 제한 롤백이 준비되었습니다. Caddy 리로드는 기존 WebSocket 클라이언트에 영향을 미칠 수 있었으며, 전체 사용자 세션에 미친 영향은 측정되지 않았습니다. 기존 채팅 헬스 엔드포인트는 작업 전, 도중, 후에 모두 HTTP 200을 반환했습니다.

정리 작업에서는 MacBook 수신기와 US 릴레이를 중지하고, 시험 리스너가 없음을 확인하고, 원격 코드/상태/자격 증명을 제거하고, 정확한 Caddy 블록을 제거하고, 롤백 타이머를 중지했습니다. Caddy는 활성 상태를 유지했으며 원래의 SHA-256이 복원되었습니다:
`60ae35627b82d65724ceac89421e1f92ba475b675fd146b4036129f352197ebb`.
테스트 호스트 이름은 이후 원래의 HTTP 301 리디렉션을 반환했습니다. 로컬 시험 키와 자격 증명은 정제된 측정값만을 보관한 후 삭제되었습니다.

## 남은 경계 및 다음 단계

외부 입장은 프로비저닝된 룸/역할 베어러 자격 증명과 수명이 짧은 쿠키를 사용하며, 기기 바인딩 증명이 아닙니다. Cloudflare/Caddy는 이러한 외부 자격 증명과 메타데이터를 볼 수 있습니다. 내부 고정(pinned) 상호 TLS는 피어를 인증하고 애플리케이션 페이로드를 보호합니다. 프로덕션 작업에는 오리진 바인딩 입장 구성, 자격 증명 로테이션, 기기별 쿼터 및 프로토콜 검토가 필요합니다.

초대장 전달에는 신뢰할 수 있는 관리 경로와 비공개 파일을 사용했습니다. 모바일 QR/SAS UX, 하드웨어 키 스토리지, 매끄러운 인증서 갱신, 오프라인 큐, 프로덕션 수신기 수명 주기 또는 네이티브 에이전트 승인 통합은 제공되지 않습니다. 파일 시스템 권한만으로는 키체인이 될 수 없습니다. 이 실험실의 인증서는 수명이 짧으며, 로테이션하려면 철회 후 다시 페어링해야 합니다.

직접 연결 성공은 공용 피어 투 피어 NAT 통과가 아닌 tailnet TCP를 의미합니다. Windows, 모바일 VPN 미사용(VPN-off) 클라이언트, IPv6 오리진 정책, 현재 OCI API 방화벽 상태, 대규모 서비스 거부(DoS) 동작 및 독립적인 보안 검토는 여전히 검증되지 않았습니다. 직접 공용 오리진 프로브는 단 하나의 관측 지점에서만 시간 초과되었습니다.
