# Side Session experiment results — 2026-09-30

## Verdict

**Transport feasibility: PASS (one real request / one exact side-session ACK).**
**General-use safety and complete issue #245 acceptance: NOT PASS.**

This is a local opt-in proof of concept in an isolated worktree based on
session-peer 90489fccc87fe2588a2546aaaf7f285429d2bcfd. Canonical CLI, generated
runtime, packaging configuration, existing agent sessions and hosted services
were not changed. No PR, push, package publication or rollout was performed.

## Actual test, not a simulated fork

- macOS arm64; Codex CLI/server 0.159.2; Python 3.14 environment with websockets
  17.1. TUI-selected default model GPT-6.1-Sol/high; no model override.
- A dedicated local app-server exposed a private Unix-domain endpoint. A fresh
  native Codex TUI connected to that exact server. The new server/test thread
  was configured read-only/on-request; no existing permission settings changed.
- A short parent setup request returned `ACK SIDE245-PARENT-READY-20260930`.
- Native `/btw` was entered once through the dedicated terminal. Its rendered
  screen showed `Side from main thread`; the server inventory gained one
  ephemeral, idle, direct-input-capable thread. No artificial API fork was
  substituted for the real slash command.
- The experimental adapter's exact-target dry-run was validated with
  `submitted:false`. It then submitted one new input via `turn/start`, with
  no resume, fork, sandbox/model overrides or retry. Result:
  `status:accepted`, `submitted:true`, `consumptionConfirmed:false`.
- The rendered native **side** screen displayed the request separately from
  the response: `ACK SIDE245-ROUNDTRIP-A-20260930` (about 3 seconds of work,
  displayed completion 19:36 KST). This response was actually generated by the
  target, not inferred from submission.
- Parent history before/after: one turn, idle, identical serialized-turn hash:
  `e08cdef71e4c1c171bee1c793ef1958954ad070020ef001ce02960023c443d82`.
  The side request/ACK did not enter the parent transcript.

ACK observation used the dedicated terminal's rendered screen. The adapter did
**not** implement generic ACK waiting, structured Reply-To return routing, or
delivery back into the original working Codex conversation. Acceptance output
correctly remained `consumptionConfirmed:false`; the exact ACK is separate test
evidence. Side history was never exported/persisted by the adapter.

## Controls and limitations

| Check | Outcome |
| --- | --- |
| Actual side discovery, dry-run and one-shot ACK | PASS |
| Parent transcript unchanged | PASS |
| Persistent parent selected by side adapter | Refused before input: `ephemeral_target_required` |
| Native `thread/queue/add` on real side ID | Rejected: JSON-RPC -32600 |
| Target absent from loaded inventory | Unit-test refusal; no fallback |
| Busy target at preflight | Unit-test refusal; actual concurrent race not tested |
| Timeout, malformed response, internal error after attempt | Unit-test unknown, no retry |
| Side dismissed from TUI but retained in server | **Unmet safety gate:** dry-run still validated |

Two production blockers remain:

1. `turn/start` is backed by `start_or_steer_turn`. A preflight idle check cannot
   atomically prevent steering if another producer submits in between. The
   exclusive-test flag acknowledges a single-producer requirement, but does not
   enforce it against a native client. No adversarial concurrency test was run.
2. UI dismissal is not immediate server unload. Ctrl+C returned the TUI to its
   parent, but the old side ID remained ephemeral/idle in memory, and a dry-run
   still validated it. **No further message was sent after this finding.** An
   owner-cooperating active-registration/generation mechanism is needed.

`ephemeral` alone does not identify a `/btw` conversation. The experiment knew
its provenance because it controlled the dedicated TUI and observed creation.
Existing Orca-hosted private app servers, SSH, Linux, Windows, busy steering,
multi-client approval handling and normal automatic Reply-To are unverified.

## Verification and cleanup

- 13 scoped unit tests pass with `-X dev -W error::ResourceWarning`; no warnings.
  One explicitly models the loaded-but-UI-closed limitation, without sending.
- Native WebSocket-over-Unix initialize/read/start was exercised with the real
  server. Native stdio `app-server proxy` was not usable for the initial probe
  (no initialize response); direct WebSocket transport was used instead.
- Existing package rules exclude `experiments/`; no artifact is being released.
- The two dedicated Orca terminals were closed, with PTY shutdown confirmed.
- The one newly created persisted parent test thread was deleted through its
  owning server only after confirming exact cwd, one turn and unchanged hash.
  Existing session records were not deleted. This test record is not retained;
  its sanitized outcome is preserved here.
- Final checks: no Orca terminals in this worktree, no process whose command
  references the unique test endpoint, no Codex process with this test cwd, and
  no open physical test socket. Stale socket/rendezvous/startup-lock files created
  by this test were removed by exact path after verifying no open handles. The
  empty private scratch directory was removed. Unrelated daemon files and
  existing worktrees/processes were preserved; the implementation worktree remains.
