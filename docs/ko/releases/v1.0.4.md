# session-peer v1.0.4

2026-10-07 기준 준비 상태: v1.0.4는 v1.0.3 이후의 유지보수 후보이며 아직 공개되거나 운영 배포되지 않았습니다. 공개 상태는 GitHub/PyPI에서 확인해야 합니다. 공개 전에 아래 검토된 수정 여섯 건이 통합 main에 있어야 합니다. 로컬/SSH 코어 명령은 Python 3.9+에서 외부 의존성 없이 유지됩니다. Relay와 MCP는 선택 기능이며 Antigravity 브리지는 실험적입니다.

## 변경 사항

- MCP는 정규 호스트 옵션을 검증하여 유효한 파일 기반 SSH 정책을 다시 허용합니다 (#262). SSH 대상 제한, 허용 목록과 승인된 Codex 홈은 계속 적용됩니다.
- SSH는 실행됐으나 완료가 불확실한 전송을 `outcome_unknown`, `retryAllowed: false`로 분류하며 성공이나 안전한 재시도를 암시하지 않습니다. Codex 큐 시간 초과도 같은 불확실성을 유지합니다 (#263). 완전한 버전 명시 결과와 거절은 전송 계층 실패 후에도 보존됩니다. 레거시 전송 사전은 일반 종료 0/1/2에서 정확한 불리언 `ok`와 없거나 일치하는 command가 있을 때만 호환됩니다. 잘못된 사전과 비정상 레거시 종료는 완료 증거가 아닙니다.
- 페어링 기기 프레이밍은 발신자 봉투를 포함한 UTF-8 메시지 32 KiB, 이스케이프된 애플리케이션 JSON 64 KiB, 운영자 소유 바인딩을 포함한 네이티브 워커 JSON 256 KiB 예산을 일치시킵니다 (#264). 유니코드와 이스케이프가 많은 입력은 애플리케이션 쓰기, 네이티브 효과나 전송 의도 기록 전에 검사합니다. 확인된 초과 요청은 거절하며 이후 불확실한 I/O는 unknown으로 유지합니다. 경로 설정 후 애플리케이션 제출 전에 만료만 갱신하고 원래 요청 ID와 본문을 보존하며 재전송하지 않습니다.
- 부가 원격 버전 프로브 실패가 성공한 SSH 세션 목록을 버리지 않습니다 (#265). 세션, 호스트/탐색 메타데이터와 주 종료 상태를 유지하고 원시 진단 대신 제한된 버전 미확인 사유를 표시합니다. 주 실패와 엄격한 원격 업데이트 검증은 변하지 않습니다.
- Control 잠금 파일은 GHSA-68fv-2mgg-jv7q에 대응하여 source-map-js를 1.2.1에서 1.2.2로 갱신하고 런타임 의존성 감사 선행 조건을 복구합니다 (#266). 잠금 파일만의 패치이며 호스팅 Control 배포나 기기군 대응을 주장하지 않습니다.
- Claude 탐색과 doctor는 엄격한 UTF-8, JSON 객체 및 필드 타입 검증을 갖춘 1 MiB 제한 레지스트리 리더를 공유합니다 (#267). 심볼릭 링크, 비정규 파일, 식별자 교체와 크기 초과 증가를 거절하고 열린 디스크립터를 닫으며 정상 행과 권한 진단을 보존합니다. POSIX에서는 nonblocking/no-follow 열기 검사를 사용합니다. Python 3.9 호환 Windows 대체 경로는 동등한 POSIX 플래그나 모든 파일시스템 읽기의 시간 상한을 보장하지 않습니다.
- 호환성 스킬 스냅샷은 0.3.2이며 최소 런타임 0.9.1, 전체 기능 런타임 1.0.1을 유지합니다. 독립적인 호환성 버전은 공개된 1.0.3 보안 권고를 대체하지 않으며 Python 업그레이드는 별도로 관리되는 스킬을 갱신하지 않습니다.

## 설치·업그레이드 경계

공개 승인 후 기존 설치 관리자를 사용합니다. 이 준비 노트는 설치나 다른 설치를 조용히 대체할 권한을 부여하지 않습니다.

```bash
pipx upgrade session-peer
# New Unix / WSL installation with optional Relay and MCP, after publication:
pipx install 'session-peer[relay,mcp]==1.0.4'
```

코어는 Python 3.9+, MCP는 3.10+, Relay 수신기/서버는 Unix 또는 WSL과 Python 3.11+가 필요합니다. 서비스 관리 수신기는 서비스 PATH의 Codex 또는 운영자 소유 codexBin 바인딩이 필요합니다. dry run은 대상을 확인하며 네이티브 효과나 모델 ACK를 증명하지 않습니다. SSH, 페어링이나 운영자 바인딩 권한을 넓히지 않습니다. [v1.0.3 보안 노트](v1.0.3.md), 기존 허용 목록과 페어링 검토 요구 및 검증된 불변 단독 파일 자산은 계속 적용됩니다. 공개된 보안 권고/CVE 기록은 새로운 v1.0.4 공개나 상태 재검증이 아닙니다.

## 검증 및 알려진 한계

릴리스 게이트는 통합된 공개 main의 정확한 커밋 CI 성공, 생성 소스와 네 언어 문서 검사, 재현 가능한 아카이브 빌드, 깨끗한 wheel/sdist 설치, 선택 extras 검사와 현재 Python/Node 의존성 감사를 요구합니다. 로컬 준비 검사는 최종 통합 게이트, 불변 자산/출처 검증이나 필수 인간 PyPI 환경 검토를 대체하지 않습니다. 새로운 실시간 SSH/네이티브 메시지, OAuth/Relay 상태 캠페인이나 운영 재시작을 주장하지 않습니다.

과거 RC4 증거는 v1.0.4가 아닌 v1.0.0에 속합니다. 독립 ACK는 20/21이며 소유자의 #164 예외를 보존합니다. #161은 열려 있고 외부 지연의 근본 원인은 미확인입니다. `posted`, `queued`, `submitted`는 제출 증거이며 소비나 ACK가 아닙니다. 불확실한 결과는 자동 재전송을 허용하지 않습니다. 패키지 공개, 호스팅 대응, 기기군 설치와 운영 재시작은 별개의 작업입니다.
