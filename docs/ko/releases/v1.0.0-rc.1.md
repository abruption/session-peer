# session-peer v1.0.0-rc.1

첫 번째 1.0 릴리스 후보는 계획된 v1 구현을 완료하고 정식 릴리스 전에 마지막
호환성 및 패키징 피드백을 요청합니다.

## beta.1 이후 변경 사항

- durable reconciliation, control fencing, 명시적 peer 승인 및 새 identity를 갖춘
  fail-closed 분실 키·복원 기기 복구 workflow를 추가합니다.
- 유지보수 가능한 Python core를 소유권이 명확한 기능 segment로 분리하면서
  의존성 없는 단일 파일 SSH artifact를 결정론적으로 보존합니다.
- 하나의 완전한 gate, immutable action pin, 재현 가능한 archive, 정확한 내용 검사,
  provenance, attestation 및 runtime audit으로 릴리스를 강화합니다.
- test를 subsystem별로 재구성하고 private state와 개발 전용 tree를 제외하는 정확한
  wheel 및 source archive 계약을 요구합니다.
- 실제 Codex-to-Claude-to-Codex demo를 추가하고 PyPI 요약을 현행화하며 선택형 relay의
  cryptography 하한을 패치된 50.0.1 릴리스로 올립니다.

## 릴리스 후보 설치

Python package manager는 일반적으로 prerelease를 선택하지 않습니다. 명시적으로 선택하십시오:

```bash
pipx install 'session-peer[relay]==1.0.0rc1'
# or
uv tool install 'session-peer[relay]==1.0.0rc1'
```

페어링된 두 endpoint에서 같은 package version을 사용하십시오. core는 Python
3.9+를 지원하며, 선택형 relay runtime은 Unix 또는 WSL과 Python 3.11+가 필요합니다.

- [프로젝트 개요](https://abruption.dev/projects/session-peer/)
- [페어링 기기 안내서](https://github.com/abruption/session-peer/blob/v1.0.0-rc.1/docs/paired-devices.md)
- [v1 호환성 계약](https://github.com/abruption/session-peer/blob/v1.0.0-rc.1/docs/compatibility-v1.md)
- [보안 정책](https://github.com/abruption/session-peer/blob/v1.0.0-rc.1/SECURITY.md)

## 릴리스 후보 경계

- 명시적 tester를 위한 prerelease입니다. 일반 stable upgrade는 최종 1.0.0이
  공개될 때까지 계속 v0.9.1을 선택합니다.
- 후보에서는 v1 호환성 계약이 동결됩니다. 비호환성 발견은 조용히 수용하지 않고
  stable 승격을 차단합니다.
- 호스팅된 relay 가용성과 OAuth provider 정책은 package 게시와 별개의 운영
  service로 유지됩니다.
- Antigravity는 experimental 상태이며 receiver와 선택형 relay runtime은 Windows에서
  native로 실행되지 않습니다. 문서화된 WSL 경계를 사용하십시오.
- 기록된 운영 campaign은 중단된 24시간 결과와 명시적 면제를 그대로 보존합니다.
  이 후보는 uninterrupted service를 주장하지 않습니다.

버그는 GitHub issue로, 보안 문제는 저장소의 private advisory channel로 보고하십시오.
보고서에 token, device key, certificate, session ID 또는 conversation content를
포함하지 마십시오.
