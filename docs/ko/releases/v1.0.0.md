# session-peer v1.0.0

첫 번째 v1 안정판은 RC4에서 검증한 런타임을 패키지로 제공합니다. `v1.0.0-rc.4`와 런타임 동작은 같고 버전과 문서만 승격했습니다. 기본 로컬·SSH 메시징은 외부 의존성 없이 유지됩니다. 선택형 MCP, 종단간 암호화된 페어링 직접/Relay 메시징과 관리형 허가, 실험적 Antigravity 브리지는 명시적으로 선택해야 합니다.

## 검증과 변경 사항

- #162는 시도별 비식별 경로 진단과 제출 전 control/admission 단계의 제한된 1회 재시도를 제공합니다. 제출 후 결과가 불명확한 메시지는 자동 재전송하지 않습니다.
- #168은 정상 idle 만료 뒤 수신자 재연결 공백을 줄이고 Relay 레그에 10/10초 keepalive와 `receiverRoleBusy`/`clientRoleBusy` 지표를 추가합니다.
- 5개 호스트의 `rc4-rerun-02`는 14,436.65초 완료, 공개 health 241/241, probe 147/147, 제출 21/21, 예정된 Relay 재시작 복구 3.182초를 기록했습니다. 정확한 ACK는 20/21입니다. 원래 T120 Windows native Claude ACK는 TUI 종료로 미확인이며 같은 경로의 별도 신규 단발 시험은 정확한 ACK를 받았습니다. 사용자가 #164의 운영 예외를 수락했지만 원래 집계를 소급해서 바꾸지 않습니다.

## 설치

기존 패키지 관리자를 사용하고 설치 환경이나 기기 신원을 섞지 마십시오.

```bash
# Unix / WSL paired transport and MCP
pipx install 'session-peer[relay,mcp]==1.0.0'
# Native Windows core and MCP (Relay receiver runs in WSL)
pipx install 'session-peer[mcp]==1.0.0'
```

코어는 Python 3.9+, MCP는 3.10+, Relay 수신기/서버는 Unix 또는 WSL의 3.11+가 필요합니다. launchd/systemd로 시작하는 macOS·Linux 수신자 서비스 `PATH`에는 대상 TUI의 `codex` 실행 파일 디렉터리가 있어야 합니다(#171, #176). `codexBin`은 WSL 전용이며 같은 환경에서 `send --dry-run`으로 검사하십시오. Relay 기기 로그인은 만료돼 재승인이 필요할 수 있고 429/slow_down 처리는 #174에서 추적합니다.

## 한계

#161의 간헐적 Cloudflare↔KR 전송 정체 위치와 귀책은 미확정입니다. RC4는 증폭을 완화하지만 경로 자체를 고치지 않았고 #161은 v1.0.1 모니터링으로 열어 둡니다. 호스팅 Relay/OAuth 가용성은 패키지 발행과 별개입니다. Windows 검색에는 종료된 Claude 기록이 남을 수 있습니다(#173). Antigravity는 실험적입니다. 제출 또는 queued는 소비나 ACK의 증거가 아니며 결과 불명확 메시지를 자동 재전송하지 마십시오.
