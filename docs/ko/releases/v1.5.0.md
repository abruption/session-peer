# v1.5.0 릴리스 준비

공개된 v1.4.2([GitHub](https://github.com/abruption/session-peer/releases/tag/v1.4.2), [PyPI](https://pypi.org/project/session-peer/1.4.2/))를 기준으로 2026-11-09에 준비했습니다. 이 날짜의 점검에서 v1.5.0은 미공개 소스 후보였습니다. 통합 소스 기준은 `a622dc0d9f04a252af65147eb36188998bf0c8b4`이며 버전 준비 전의 값이지 최종 공개 커밋이 아닙니다. 소유자의 요청은 이 릴리스 준비 PR까지입니다. 이번 준비는 해당 준비 PR의 병합·태그·초안 생성·워크플로 실행·발행·운영 변경을 승인하지 않습니다.

## 후보 범위

- #390 / #389는 안정판 SDK 1.x의 1.30 이상을 유지하면서 안정판 SDK 2.x의 2.3 이상을 받는 MCP SDK 호환성을 추가합니다. extra는 `mcp>=1.30,<3,!=2.0.*,!=2.1.*,!=2.2.*`이며 SDK 2.0–2.2, 사전 공개판과 개발판은 계속 제외합니다. SDK 2.3+는 `MCPServer(subscriptions=False)`를 사용하며 구독·listen·상태 조회·대기 인터페이스를 추가하지 않습니다. 공개 도구 6개, 프로젝트 결과 데이터 스키마 버전 1, 정책 버전 1/2, 권한, 호스트 승인, 불확실한 결과 처리와 자동 재시도 금지 원칙은 유지됩니다. SDK 2의 Python 속성과 camelCase 전송 별칭을 맞추되, 프로토콜 버전 사이에서 SDK의 봉투까지 바이트 단위로 같다고 주장하지 않습니다.
- 의존성 유지보수에는 #386 GitHub Actions 갱신, #383 Hatchling 1.33.0, #385 Vitest 5.1.0, #382 Vite 8.3.6과 @rolldown/pluginutils 1.0.1이 포함됩니다. 빌드·CI·개발 도구는 외부 의존성이 없는 기본 CLI 및 실행 중인 서비스의 환경과 구분합니다.
- #379는 테스트 의존성 Paramiko 5.1.0과 그에 맞는 테스트 단언만 갱신합니다. Paramiko는 시험용 의존성으로 유지되며 운영 SSH 동작은 바뀌지 않습니다.
- #381은 Better Auth/core 1.7.18, jose 6.2.15, React/React DOM 19.3.1, tsx 4.23.15를 갱신하고 의존성 기준 및 기존 핵심 계약 검사를 포함합니다. 애플리케이션 세션 정책과 런타임 인증 코드는 그대로이며, 업스트림 의존성 변경이 실제 OAuth 흐름이나 기존 운영 데이터베이스의 호환성을 검증했다는 뜻은 아닙니다.

## 호환성과 검증 범위

기본 Python 3.9, 선택형 MCP Python 3.10, Relay Python 3.11 하한은 유지합니다. Node 엔진은 `^22.13.0 || ^24.0.0`, `@types/node`는 24, `better-sqlite3`는 12.6.2를 유지합니다. Control은 비공개 버전 0.1.0이며 Python wheel/sdist에 포함되지 않습니다. 서비스 배포는 별개입니다.

빌드 인터프리터 경계: [Hatchling 1.32.4](https://pypi.org/pypi/hatchling/1.32.4/json)와 [Hatchling 1.33.0](https://pypi.org/pypi/hatchling/1.33.0/json)의 공개 메타데이터는 모두 Python 3.10+을 요구합니다. 기존 빌드 도구의 요건이며 기본 런타임 하한을 새로 올리는 것이 아닙니다. Python 3.9의 기본 설치는 범용 wheel 또는 독립 실행 파일 경로를 사용하며, sdist를 직접 빌드하려면 Python 3.10+ 빌드 인터프리터가 필요합니다. 이번 준비는 Python 3.9의 sdist 빌드 검증을 주장하지 않습니다.

MCP 후보는 macOS/Linux의 Python 3.10/3.13/3.14에서 네 프로필(`minimum`, `latest1`, `minimum2`, `latest2`)을 구성하므로 CI 조합은 24개입니다. 프로필별로 선택된 버전과 런타임 의존성 감사 보고서를 보관하며, 모든 전이 패키지의 개별 최소 버전을 시험하는 것은 아닙니다. 이는 검사 구성이며 대기 중인 CI가 통과했다는 주장이 아닙니다. 정확한 준비 HEAD와 최종 보호된 main 커밋의 결과가 필요합니다. 클라이언트·프로토콜 시험과 제한은 [MCP 가이드](../mcp.md#sdk2-compatibility-candidate)를 참고하십시오.

64 KiB 결과 한도는 상한이며 그보다 작은 모든 결과를 받는다는 보장이 아닙니다. SDK 2는 기존 프로토콜 연결에서도 새 서버 식별 메타데이터를 크기 계산에 넣으므로, 한도에 가까운 결과를 보수적으로 거부할 수 있습니다. 프로젝트 내부 결과 JSON과 승인·제출·소비·ACK의 구분은 그대로입니다. 새로운 실제 에이전트·SSH·Windows·실제 OAuth·기존 데이터베이스 검증은 주장하지 않습니다. #387/#388 및 연구 Draft #246/#248은 이번 범위 밖입니다.

## 독립 스킬과 불변 이력

예정된 `SKILL.md` 지원 자산은 독립적으로 공개된 스킬 v0.5.1, 소스 `95cf5e1dd92654775b2f0ea86c1cb4b6107f49c3`, UTF-8 31688바이트, SHA-256 `922512869577cc3d8b9d305641479e2dd659f0e669298584ca06f1ca15de1d31`를 유지합니다. 메타데이터는 최소 런타임 0.9.1 / 문서에 안내된 전체 사용 흐름의 기준 1.4.0이며, 수신측 `codexBin` 하한은 1.0.1입니다. 스킬 버전·하한·소스 고정값·설치된 스킬을 바꾸지 않습니다. 지원 자산은 wheel/sdist 밖에 있습니다.

[v1.4.2 공개 기록](v1.4.2.md#v142-publication-record), 과거 날짜의 SDK 1 보안·CI 기록, 기존 태그·자산을 보존합니다. 과거 SDK 1 조건이나 CI 조합 수를 SDK 2 검증으로 소급해 고치지 않습니다. 패키지 공개가 전역 MCP 환경 설치, 전체 기기 갱신, 수신기 재시작이나 Node Control 배포를 수행하지는 않습니다.

## 남은 발행 조건

현재 HEAD의 리뷰·검사와 최종 보호된 main CI 통과가 필요합니다. 이후 별도로 승인된 발행은 `SHA256SUMS`와 `release-provenance.json`을 포함한 고정 자산 7개, 인증된 증명, 정확한 태그·소스, 최신 의존성 감사와 새 환경의 wheel/sdist 독립 설치를 검증해야 합니다. PyPI 환경의 필수 사람 승인은 유지하며, 비공개 로그인·연결 재확인을 생략해도 이 절차가 면제되거나 보호 우회가 허용되지는 않습니다. 이번 준비에서는 태그·초안·워크플로 실행·발행을 수행하지 않습니다. 날짜별 준비 기록은 고정하고 실제 공개 근거는 별도로 추가하며, 문구를 바꾸려고 기존 불변 자산을 재빌드하거나 교체하지 마십시오.
