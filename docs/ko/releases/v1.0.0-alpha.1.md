# session-peer v1.0.0-alpha.1

첫 번째 옵트인 1.0 알파 버전은 v0.9.0의 의존성 없는 로컬 및 SSH 워크플로를 유지하면서 인증된 공개 릴레이 경로를 추가합니다.

## Highlights

- 고정된 내부 TLS 1.3을 통해 기기를 페어링하고 직접 TCP 또는 블라인드 공개 WSS를 통해 전송합니다. 릴레이는 라우팅 메타데이터를 볼 수 있지만 애플리케이션 메시지를 복호화할 수는 없습니다.
- 검증된 GitHub 또는 Google OAuth로 로그인하고, 브라우저 기기 코드로 네이티브 CLI를 승인하며, 모든 릴레이 진입을 등록된 기기 키에 바인딩합니다.
- 이전/신규 키 증명, 내구성 있는 작업 영수증 및 알 수 없는 응답 후 복구 기능을 통해 기기 키를 순환합니다. 해지 시 활성 관리 연결이 종료됩니다.
- 재시작 전반에 걸쳐 사용된 티켓과 공개 상태 리비전 하이워터마크를 유지합니다. KR 배포에는 조정된 부팅, 워치독 복구 및 암호화된 복구 스냅샷이 포함됩니다.
- Claude, Codex 및 Antigravity 네이티브 전달을 지원합니다. 제출, 중복 억제 및 독립적으로 관찰된 에이전트 확인 응답은 별개의 결과 상태로 유지됩니다.
- 초대나 사용자 수 제한 없는 검증된 공개 가입을 제공합니다. 운영자는 커밋된 신원을 제거하지 않고도 신규 가입을 마감할 수 있으며, 운영자 전용 집계 지표 페이지에는 사용자 또는 기기 식별자가 노출되지 않습니다.

## Install the alpha

Python 패키지 관리자는 일반적으로 시험판을 선택하지 않습니다. 명시적으로 옵트인하십시오:

```bash
pipx install 'session-peer[relay]==1.0.0a1'
# or
uv tool install 'session-peer[relay]==1.0.0a1'
```

페어링된 양쪽 엔드포인트에서 동일한 패키지 버전을 사용하십시오. 코어는 여전히 Python 3.9+를 지원합니다. 선택적 릴레이 런타임에는 Unix 및 Python 3.11+가 필요합니다.

- [Project overview](https://abruption.dev/projects/session-peer/)
- [Paired-device guide](https://github.com/abruption/session-peer/blob/v1.0.0-alpha.1/docs/paired-devices.md)
- [CLI reference](https://github.com/abruption/session-peer/blob/v1.0.0-alpha.1/docs/cli-reference.md)
- [Security policy](https://github.com/abruption/session-peer/blob/v1.0.0-alpha.1/SECURITY.md)

버전이 고정된 저장소 링크는 태그가 생성되면 사용할 수 있습니다.

## Compatibility changes

이 alpha는 버전형 회신 URI, JSON schema 1 결과, 기기 backup manifest와 relay/control
protocol state를 추가합니다. 제안된 안정성과 migration 규칙은 이제
[v1 호환성 계약](../compatibility-v1.md)에서 관리합니다. 이 alpha에는 deprecation이 없으며,
영속 control upgrade는 stable v1 전에 명시적 migration 경로를 사용해야 합니다.

## Alpha boundaries

- 이것은 명시적 테스터를 위한 시험판입니다. 일반적인 안정 버전 업그레이드는 계속 v0.9.0을 선택합니다.
- 공개 릴레이 가용성 및 OAuth 제공자 정책은 패키지 설치와 분리된 운영 서비스입니다.
- Google OAuth는 제공자의 테스트/게시 정책에 의해 제한될 수 있습니다.
- 페어링 및 OAuth만으로는 네이티브 에이전트 액세스 권한이 부여되지 않습니다. 수신 엔드포인트는 여전히 로컬 정책을 강제하며 사용자가 실제 에이전트 응답을 확인합니다.
- 완료된 검증 증거는 독립적인 Linux/macOS 테스트, 실제 공개 WSS 페어링, 재생 거부, 실시간 해지, 실제 에이전트 ACK, 워치독 복구, KR 재부팅 및 격리된 백업 복원을 포괄합니다. 중단된 침지 테스트는 24시간 통과로 주장되지 않습니다.
- Windows는 로컬 및 SSH 지원을 유지합니다. 선택적 수신자/릴레이 런타임은 Unix 전용입니다.

버그는 GitHub issue를 통해 보고하고 보안 문제는 저장소의 비공개 보안 권고 채널을 통해 보고하십시오. 보고서에 토큰, 기기 키, 인증서, 세션 ID 또는 대화 내용을 포함하지 마십시오.
