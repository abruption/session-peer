# v1.1.0 릴리스 후보

## 상태와 선행 조건

2026-10-09에 준비한 미발행 후보입니다. 현재 공개 안정판은 1.0.4입니다. 이 문서는 준비 초안이며 기능 브랜치의 병합이나 릴리스 발행을 증명하지 않습니다. PR #261과 기능 PR #283–#290을 정상 보호 절차에 따라 이 준비 PR보다 먼저 병합하고, 공개 전에 정확한 통합 main을 검증하여 초안을 갱신해야 합니다.

## 예정된 변경

- #242 / #283: Bash/zsh와 PowerShell 5.1의 선택적 `sp` 셸 별칭은 정식 `session-peer` 명령을 통해 인자, 표준 입력과 종료 코드를 보존합니다. wheel/sdist에는 수동 활성화용 파일이 포함됩니다. PowerShell 기본 별칭을 포함하여 기존 별칭·함수·실행 파일과 충돌하면 거부합니다. 프로필/PATH 수정, 자동 활성화, Python/TypeScript 선택기는 없습니다. 독립형 설치에는 별도로 검토한 파일이 필요합니다.
- #268 / #284: 상속된 `CODEX_SQLITE_HOME`이나 검사한 설정의 최상위 `sqlite_home`이 있으면 검색·큐 제출·wake 전에 차단합니다. 제한된 저장 경로 보호이며 이동된 DB를 지원하거나 Codex의 모든 실효 설정을 증명하지 않습니다.
- #232 / #285: 외부 메시지 본문을 인용하고 발신·회신 경로 주장을 미검증으로 표시합니다. 페어링 수신기의 인증된 신원은 기기 키이지 사람이나 모델이 아닙니다. 본문 구분은 모든 프롬프트 주입을 막는 방어가 아닙니다. 추가된 문구도 용량 제한에 포함되며 `chars`는 구분 처리를 마친 텍스트를 나타냅니다.
- #180 / #286: 선택적 Claude `targetGeneration` 검색과 `--target-generation`은 원래 프로세스·접속 지점을 고정하고 쓰기 전에 연결된 상대를 재확인합니다. 오래된 대상은 실행 전에 거부합니다. Codex, Antigravity와 페어링 기기의 세대 보장은 미지원이며 writer 재시작으로 미지원 상태가 지원 상태로 바뀌지 않습니다.
- #183 / #287: 선택적 `--ssh-identity`는 연결의 호스트 키 증거를 보고하며 `--require-ssh-host-key`는 인증·원격 실행 전에 실제 연결의 키를 고정합니다. POSIX의 일반 Ed25519/RSA/ECDSA 키를 지원하지만 호스트 인증서와 보안 키 유형은 지원하지 않습니다. 호스트 키는 에이전트 신원·세션 세대·ACK를 증명하지 않습니다.
- #238 / #288: 협력적 wake 깊이·발신 식별자 전달과 대상별 호출 제한이 기존 보호를 보완합니다. 환경 변수가 걸러지거나 사라지면 새 발신 식별자로 시작할 수 있으며 공유 MCP의 시작 환경은 호출별 문맥이 아닙니다. 네이티브 wake는 이전에 검증한 Codex 0.154.0 경로로 제한됩니다.
- #211 / #289: `session-peer setup`은 로컬/SSH/Relay 읽기 전용 점검과 명시적으로 승인한 작업을 제공합니다. 기본 점검은 키나 DB를 생성하지 않고 설치 관리자 안내는 자동 설치하지 않습니다. 기존 정책을 확대하지 않으며 원래 등록 요청을 영속적으로 보존하고 준비 점검에서는 메시지를 보내지 않습니다. 전경 수신기 설정은 서비스 설치가 아닙니다.
- #181 / #290: 실험적 선택 기능인 handoff는 송신자의 영속 전송 제한, 시간·용량이 제한된 표준 입력/프로세스 처리와 수신 확인 전용 상태·대기·ACK 작업을 추가합니다. 로컬 POSIX Claude는 검증한 원래 세대의 수신 확인 경로를 지원합니다. 로컬 Codex와 단일 대상 POSIX 소스 스트리밍 SSH는 상관관계 식별자 기반 제출만 지원하며 관찰·ACK는 미지원입니다. 필수 delivered/acknowledged 대기는 미지원 경로에서 실행 전에 거부됩니다. 원격 수신 확인, Windows, 페어링 handoff, 다중 호스트 선택 기능, 본문을 읽지 않는 Codex 관찰과 전체 복원 검증은 별도 조건으로 남습니다.

## 호환성과 안전 경계

코어에는 Python 3.9 이상, MCP에는 3.10 이상, Unix/WSL Relay에는 3.11 이상이 필요합니다. 선택 기능을 끈 일반 결과는 네이티브 선택 필드를 유지합니다. `posted`, `queued`, `submitted`는 소비를 증명하지 않으며 불확실한 결과는 자동 재전송을 허가하지 않습니다. 실험적 대기는 대상별 기본 30초, 정수 1–60초의 총 시간과 정리용 5초를 사용합니다. 상태·수신 확인 작업은 네이티브 메시지를 제출하지 않습니다. 수신 확인 권한은 토큰 보유를 증명할 뿐 모델 신원을 증명하지 않습니다. 수신자의 네이티브 기록에 위임 권한이 남을 수 있습니다.

본문 구분을 마친 전체 내용에 Codex/페어링 32 KiB, 페어링 애플리케이션 JSON 64 KiB(JSON 이스케이프 포함), worker 256 KiB, 큐 레코드 1 MiB 제한을 적용합니다. 일반 SSH에는 90,000자와 명령 131,071바이트 제한이 유지됩니다. 완전하고 유효한 네이티브 응답은 전송 오류 뒤에도 보존할 수 있지만 불완전하거나 프로토콜 용량을 초과한 출력은 불확실합니다.

포함된 스킬은 0.3.2이며 최소/전체 런타임 호환성은 0.9.1/1.0.1입니다. 별도의 스킬 PR #30은 미발행 상태입니다. 새 안내에는 해당 PR 병합·발행·정확한 스냅샷 동기화가 선행되어야 하며 이번 후보에 포함되지 않습니다. #180, #181과 #268의 명시적 미지원 검증 조건은 유지되고 이 초안으로 이슈를 종료하지 않습니다.

## 검증과 공개 조건

로컬 통합 후보 검증은 격리된 테스트와 설치를 대상으로 하며 새로운 실제 에이전트/SSH/Relay 검증이 아닙니다. 버전 변경 뒤 정확한 통합 main의 새 CI, 독립 실행 파일 재생성, 네 언어 문서 검사, 격리 wheel/sdist 설치, 수동 활성화 파일 검사와 최신 의존성 감사가 필요합니다. 과거 20/21 ACK 기록과 열린 #161은 그대로이며 1.1.0 검증으로 간주하지 않습니다. 남은 플랫폼·기능 검증 조건을 명시합니다.

패키지 공개에는 운영 배포가 포함되지 않습니다. 태그, 불변 릴리스 파일, GitHub/PyPI 공개, 사람의 PyPI 환경 검토, 전체 기기 설치와 Control/Relay 배포는 기존 승인이 필요한 별도 단계입니다. 이 문서는 발행·서비스 재시작·새 가용성을 증명하지 않습니다.
