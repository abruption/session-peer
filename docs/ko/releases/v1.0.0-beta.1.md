# session-peer v1.0.0-beta.1

첫 번째 1.0 베타는 의존성 없는 로컬 및 SSH 작업 흐름을 유지하면서 인증
릴레이를 안정적인 계약에 더 가깝게 발전시킵니다.

## 주요 변경 사항

- 회신 URI, JSON 결과, 릴레이와 control 프로토콜, 백업 manifest, migration
  및 폐기 정책을 위한 v1 호환성 계약을 동결합니다.
- 암묵적인 control 데이터베이스 초기화를 순서가 정해진 transactional 일차
  제공 migration과 적용된 schema revision을 기록하는 백업 metadata로 대체합니다.
- 사용자, 기기, token, session 또는 message 식별자 없이 제한된 relay capacity,
  admission 거부 및 rate-limit metric을 노출합니다.
- 수신 측 정책과 소유권 검사를 유지하면서 네이티브 Windows Codex를 명시적으로
  대상으로 삼는 WSL relay receiver를 지원합니다.
- 재사용 가능한 배포 예제와 운영자 전용 artifact를 재구성하여 source
  distribution에서 private 운영 설정을 제외합니다.

## 베타 설치

Python package manager는 일반적으로 prerelease를 선택하지 않습니다. 명시적으로 선택하십시오:

```bash
pipx install 'session-peer[relay]==1.0.0b1'
# or
uv tool install 'session-peer[relay]==1.0.0b1'
```

페어링된 두 endpoint에서 같은 package version을 사용하십시오. core는 Python
3.9+를 지원하며, 선택형 relay runtime은 Unix 또는 WSL과 Python 3.11+가 필요합니다.

- [프로젝트 개요](https://abruption.dev/projects/session-peer/)
- [페어링 기기 안내서](https://github.com/abruption/session-peer/blob/v1.0.0-beta.1/docs/paired-devices.md)
- [v1 호환성 계약](https://github.com/abruption/session-peer/blob/v1.0.0-beta.1/docs/compatibility-v1.md)
- [보안 정책](https://github.com/abruption/session-peer/blob/v1.0.0-beta.1/SECURITY.md)

## 베타 경계

- 명시적 tester를 위한 prerelease입니다. 일반 stable upgrade는 계속 v0.9.1을
  선택합니다.
- 호스팅된 relay 가용성과 OAuth provider 정책은 package 게시와 별개의 운영
  service로 유지됩니다.
- WSL 지원은 네이티브 Windows Codex를 대상으로 하는 Unix relay receiver를
  다루며, receiver와 선택형 relay runtime은 Windows에서 네이티브로 실행되지 않습니다.
- Control migration은 forward-only입니다. upgrade 또는 rollback 전에 persistent
  state를 backup하고 문서화된 호환성 계약을 따르십시오.
- Pairing과 OAuth만으로 native agent 접근 권한이 생기지 않습니다. 수신 endpoint는
  여전히 local policy를 적용하며 사용자는 실제 agent 결과를 확인합니다.

버그는 GitHub issue로, 보안 문제는 저장소의 private advisory channel로 보고하십시오.
보고서에 token, device key, certificate, session ID 또는 conversation content를
포함하지 마십시오.
