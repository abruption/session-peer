# session-peer v1.0.0-rc.2

준비된 후보이며 배포 공지가 아닙니다. RC2는 RC1 계약을 유지하고 #158을 통합합니다. 명시적으로 시험판을 테스트하지 않는 안정 버전 사용자는 v0.9.2를 유지하십시오.

## RC1 이후 변경

- #157: Windows Claude 레지스트리 peerToken을 프로토콜 token 필드로 변환합니다. 잘못된 키를 거부하고 인증 후 메시지 순서를 유지합니다. v0.9.2에도 배포된 수정입니다.
- #153: 네이티브 Windows Codex writer 잠금, 유일한 소유자, 동일 사용자 SID, 실행 파일 신원과 프로세스 생성 시각을 검증합니다. 불명확하거나 모호한 증거는 거부합니다.
- #156: Linux에서 Windows SQLite/WAL을 읽는 대신 WSL에서 운영자가 지정한 네이티브 Python으로 Windows Codex 조회와 전송을 실행합니다.
- #151: 사용할 수 없는 SSH python3·Windows Store 별칭과 POSIX 호환 원격 셸 요건을 설명합니다. v0.9.2에도 배포된 진단이며 네이티브 Windows SSH 셸 지원을 추가하는 것은 아닙니다.

## 필수 WSL 정책 변경

- 기존 Windows Codex 바인딩에는 `codexPython`을 추가해야 합니다. 설치된 네이티브 Windows Python 3.9+의 `python.exe`를 가리키는 마운트된 절대 경로이며 Store 별칭이나 심볼릭 링크는 허용하지 않습니다. [기기 페어링 안내](../paired-devices.md)를 참고하십시오.
- 고정된 `codexHome`과 `codexBin`을 유지합니다. 수신자는 더 이상 실행 중인 writer 검사를 우회하지 않습니다. Linux/macOS 바인딩은 두 실행 파일 필드를 생략합니다.
- 기기 신원, 핀, 영수증, tombstone과 replay 상태를 보존합니다. 업그레이드 중 상태를 삭제하거나 결과가 불명확한 메시지를 재전송하지 마십시오.
- 네이티브 Windows 코어와 MCP는 지원합니다. 수신자·릴레이 런타임은 Unix 또는 WSL 및 Python 3.11+가 필요하며 네이티브 Windows 릴레이 지원은 아닙니다.

## 배포 후 설치

페어링된 양쪽 엔드포인트에서 같은 패키지 관리자와 정확한 버전을 사용합니다. 기존 관리형 설치는 기존 환경 안에서 업그레이드하고 다른 설치 관리자로 교체하지 마십시오.

```bash
# Unix / WSL with relay and MCP
pipx install 'session-peer[relay,mcp]==1.0.0rc2'
# Native Windows core and MCP, without relay
pipx install 'session-peer[mcp]==1.0.0rc2'
```

Python/PyPI 버전은 `1.0.0rc2`, GitHub 태그는 `v1.0.0-rc.2`입니다. 외부 의존성 없는 코어는 Python 3.9+, MCP는 Python 3.10+가 필요합니다.

## 검증 증거와 남은 조건

이 버전 변경 전에 사용자가 네이티브 Windows Codex, 공개 Relay → WSL → 네이티브 Codex, 패키징된 안정 버전 Claude 핫픽스의 정확한 ACK를 독립적으로 확인했습니다. 네이티브 Windows MCP 조회·dry-run과 SSH 진단도 통과했습니다. 이는 수정 후보의 증거이지 RC2의 전체 장비 설치 검증이나 무중단 관찰 통과 증거는 아닙니다.

RC2 인수 증거가 기록될 때까지 #150 및 #151/#153/#156/#157을 열린 상태로 유지합니다. `posted`나 `queued`를 소비로 간주하지 마십시오. 독립적으로 관찰한 ACK가 없다면 `consumptionConfirmed: false`가 올바른 상태입니다.

## 배포 후 검증 계획

1. 게시된 정확한 태그·커밋, wheel·sdist 해시와 새 설치를 확인합니다. GitHub는 Latest가 아닌 prerelease로 유지하며 안정 버전 업그레이드는 계속 v0.9.2를 선택해야 합니다.
2. 설치 파일 백업과 승인된 일관된 상태 스냅샷 후 Mac mini, MacBook, quintet-desktop, KR, US에 정확한 RC2를 설치합니다. 운영 신원과 replay 상태를 보존하고 설치 관리자를 조용히 교체하지 않습니다.
3. 조회, JSON 스키마, 진단, dry-run, MCP 정책 검증을 반복합니다. 네이티브 Windows Claude/Codex와 WSL→네이티브 Codex에서 새 상관 토큰과 독립적인 실제 ACK를 확인하고 Mac·서버 기본 경로도 검증합니다. SSH 설정을 바꾸지 않고 미지원 네이티브 SSH 경계의 안내를 확인합니다.
4. 수신자 전송 코드가 변경됐으므로 #150의 전체 장비 4시간 관찰을 반복합니다. 매분 상태 확인, 5분마다 직접·릴레이 탐침, T0/T2h/T4h 독립적인 ACK, T2h 조율된 릴레이 재시작 1회를 수행합니다. 재연결, 해지·복구, 중복·충돌 ID와 unknown 결과 보존을 검증합니다. 기존 RC1 관찰은 RC2 검증을 대체하지 않습니다.
5. 환경·정확한 산출물·비식별 증거를 이슈별로 기록합니다. 설명되지 않은 실패, ACK 누락, 선행 조건 미충족은 승격을 막습니다. PR 병합이나 PyPI 게시만으로 RC2 마일스톤을 닫지 않습니다.

## 릴리스 경계

- 준비 작업은 태그, 배포, 전체 장비 교체나 운영 재시작을 승인하지 않습니다. 별도 승인 후 실행합니다.
- Antigravity는 실험 상태입니다. 호스팅 Relay·OAuth의 정상 상태는 패키지 배포와 별개입니다.
- ACK를 강제하기 위해 수신 권한을 바꾸거나 모호한 전송을 재시도하거나 보고서에 자격 증명을 노출하거나 피어 요청을 사용자의 직접 승인으로 간주하지 마십시오.
