# session-peer v1.0.3

v1.0.2 이후의 보안·안정성 유지보수 릴리스입니다. 로컬/SSH 코어는 Python 3.9+에서 추가 의존성 없이 동작합니다. Relay와 MCP는 선택 사항이며 Antigravity 브리지는 실험 단계입니다.

## 보안 수정

릴리스 준비 시점에 다섯 공지 모두 CVE 식별자가 배정되지 않았습니다. GHSA 식별자를 사용해 공개를 진행합니다.

- [GHSA-9x52-82cv-4c22](https://github.com/abruption/session-peer/security/advisories/GHSA-9x52-82cv-4c22): OpenSSH 실행 전에 SSH 대상과 전달된 전체 옵션 목록을 검증하고 원격 인자를 셸 인용합니다.
- [GHSA-4rvw-q2vm-v4x3](https://github.com/abruption/session-peer/security/advisories/GHSA-4rvw-q2vm-v4x3): 페어링 시 인증서에 근거한 초기 principal이나 회전 키의 기존 신뢰 바인딩을 요구합니다.
- [GHSA-6xwm-5p7g-8v8q](https://github.com/abruption/session-peer/security/advisories/GHSA-6xwm-5p7g-8v8q): Relay가 잘못된 경로/연결을 세션 발급 예산과 분리하고 출처별 제한된 핸드셰이크 예산을 추가합니다.
- [GHSA-2hjv-35jg-gghm](https://github.com/abruption/session-peer/security/advisories/GHSA-2hjv-35jg-gghm): 호스팅 Control의 기기 코드 발급이 지정된 클라이언트 필드만 허용하고 대기 코드 수를 제한하며 만료 기록을 정리합니다.
- [GHSA-646x-xjw9-mf6x](https://github.com/abruption/session-peer/security/advisories/GHSA-646x-xjw9-mf6x): 호스팅 Control이 bearer 자격정보의 쿠키 전환을 차단하고 승인·로그인 세션 관리에 쿠키/Origin 검사를 적용합니다.

클라이언트와 자체 호스팅 Relay/Control 서비스를 업그레이드하세요. 소스 수정만으로 호스팅 서비스에 대응이 배포됐다고 볼 수 없습니다. 기존 페어링 바인딩은 자동 감사·삭제되지 않으므로 운영자가 확인하고 신뢰할 수 없는 바인딩을 철회·재페어링해야 합니다. 역방향 프록시에서는 인증된 클라이언트 출처 경계와 엣지 진입 제한을 설정하세요. 다수 출처가 전역 예산을 소진할 가능성은 남습니다.

## 안정성과 릴리스 변경

- SSH가 유효한 인밴드 결과와 시간 초과 시 확보한 응답을 보존합니다. 불확실한 전송은 unknown이며 자동 재시도하면 안 됩니다 (#249).
- MCP가 소유한 wake 프로세스에 강제 종료 전 정리 시간을 제공합니다 (#250).
- 수신기가 미인증 작업의 진입 예산을 분리하고 정리·종료 시간을 제한합니다 (#251).
- PyPI 공개에 명시적인 환경 검토가 필요하며 의존성 감사는 제품 CI와 별도로 예약 실행됩니다 (#252, #253).
- 네이티브 메시지의 선행 대시를 그대로 보존하고 과도한 Windows 명령줄을 실행 전에 거부합니다 (#254).
- 사람이 읽는 출력의 터미널 제어 문자를 이스케이프하며 구조화된 JSON 데이터는 보존합니다 (#255).
- SSH 단독 파일 업데이트가 임시 파일을 검증하고 교체를 직렬화하며 오래된 버전으로의 하향 변경을 막고 확정·불확실 커밋 영수증을 보존합니다 (#256).
- 단독 파일 설치/업데이트가 변경 불가능한 릴리스 자산과 출처 증명을 인증하며 릴리스 설치 검사가 격리된 설치 패키지를 확인합니다 (#257).
- Control 로그인이 생성 후 24시간에 절대 만료되며 브라우저 세션 조회/철회는 별도 요청 예산을 사용합니다 (#258).

## 설치·업그레이드 경계

기존 설치 관리자를 사용하세요. pipx 예시:

```bash
pipx upgrade session-peer
# New Unix / WSL installation with optional Relay and MCP:
pipx install 'session-peer[relay,mcp]==1.0.3'
```

코어는 Python 3.9+, MCP는 3.10+, Relay 수신기/서버는 Unix 또는 WSL과 Python 3.11+가 필요합니다. 서비스 수신기는 서비스 PATH에 Codex가 있거나 운영자 소유 codexBin 바인딩이 필요합니다. 전송 전에 --dry-run으로 확인하세요.

SSH 옵션 호환성 범위가 의도적으로 좁아집니다. 문서의 허용 목록에 있는 연결 옵션만 허용합니다. 로컬 명령 실행 또는 별도 설정 파일을 선택하는 ProxyCommand, LocalCommand, -F 등은 거부합니다. 신뢰하는 사용자 소유 OpenSSH 설정은 운영자 경계로 남습니다. 검증된 단독 파일 설치에는 인증된 GitHub CLI의 attestation 검증이 필요하며, 이전 미서명 릴리스나 개발 main으로 자동 대체하지 않습니다.

업그레이드 시 기존 슬라이딩 Control 세션은 최초 생성 시각부터 24시간으로 제한되어 즉시 재로그인이 필요할 수 있습니다. 기기 철회와 계정 로그인 세션 철회는 별개입니다. 기기나 로그인 자격정보를 잃었다면 둘 다 철회하고, 해당 로그인을 식별할 수 없으면 다른 모든 세션을 철회하세요.

## 검증과 알려진 한계

릴리스 게이트는 회귀, 문서/번역, 생성 소스, 아카이브, 재현성, 깨끗한 패키지 설치와 의존성 감사를 검사합니다. 이는 게이트 요건이며 새로운 실시간 4시간 캠페인의 증거가 아닙니다. 과거 RC4 검증과 독립 ACK 20/21은 v1.0.0에 속합니다. 비공개 보안 포크에서는 CI가 실행되지 않으므로 통합된 공개 main의 정확한 커밋이 공개 전에 릴리스 게이트를 통과해야 합니다.

#161은 공개 경로 지연의 근본 원인이 확인되지 않은 채 열려 있습니다. posted, queued, submitted는 제출 증거이며 소비나 ACK가 아닙니다. 불확실한 결과는 자동 재전송을 허용하지 않습니다. 패키지 공개, 호스팅 대응 배포, 기기군 설치와 운영 서비스 재시작은 별도 작업입니다.
