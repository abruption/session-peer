# session-peer v1.0.1

v1.0.0 이후의 유지보수 릴리스입니다. 로컬·SSH 메시지는 타사 Python 의존성 없이 사용할 수 있습니다. Relay, MCP, Antigravity 통합의 선택형 경계는 유지됩니다.

## 변경 사항

- POSIX 설치기가 별도로 관리되는 Claude Code와 Codex 스킬 경로를 존중하며 독립 설치된 스킬을 덮어쓰지 않습니다(#187).
- KR 스냅샷 도우미는 명시적 실행 플래그를 요구하므로 도움말이나 잘못된 인자로 스냅샷이 실행되지 않습니다(#175).
- 기기 승인 폴링은 429와 slow_down 응답에서 즉시 종료하는 대신 대기 시간을 늘립니다(#174).
- macOS·Linux Relay 수신기는 Codex 실행 파일을 지정할 수 있고, 실제 전달 전 실패는 전달 결과 미확정이 아닌 거부로 분류합니다(#171, #176).
- Windows Claude 탐색은 종료되거나 재사용된 PID를 제외하며(#173), Codex 탐색은 저장 전의 활성 writer와 없는 스레드를 구분합니다(#166).
- 업데이트 확인은 별도 설치된 session-peer 스킬의 구버전·비호환 상태를 알릴 수 있지만 이를 조용히 변경하지 않습니다(#167).
- 선택형 Relay 진단은 수신기 수명주기에 시간을 붙이고 시도와 연결하며 메시지 본문 없이 레그별 프레임 진행을 기록합니다(#172, #197).
- Relay control은 추가된 메트릭 카운터를 수용합니다. Dependabot 버전 업데이트 PR 생성은 껐습니다(#189).

## 설치

기존 패키지 관리자 설치는 `pipx upgrade session-peer`와 같은 일반 업그레이드 명령을 사용하세요. MCP를 포함한 Unix·WSL 기기 페어링 신규 설치는 `pipx install 'session-peer[relay,mcp]==1.0.1'`을 사용하세요. 코어만 설치하면 Python 3.9 이상에서 외부 의존성이 없고, Relay는 Unix 또는 WSL과 Python 3.11 이상이 필요합니다.

서비스로 실행하는 macOS·Linux 수신기에는 대상 Codex 실행 파일이 보이도록 하거나 새 명시적 실행 파일 옵션을 설정해야 합니다. 전송 전 `--dry-run`으로 대상을 확인하세요.

## 알려진 제한

- Cloudflare에서 KR Relay까지의 간헐적 정체(#161)는 근본 원인과 책임 구간이 여전히 미확정입니다. 새 진단은 이후 조사를 돕지만 네트워크 문제가 해결됐음을 뜻하지 않습니다.
- 제출·큐잉은 ACK가 아닙니다. 제출 후 결과가 미확정이면 자동 재전송하지 마세요.
- 패키지 발행은 호스팅 Relay나 OAuth의 가용성을 보장하지 않습니다. Antigravity 브리지는 계속 실험 단계입니다.
