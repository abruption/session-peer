# session-peer 0.8.0

이번 릴리스는 Claude와 Codex를 함께 조회하고, 제한된 기본/Orca/사용자 지정 홈 전반에서 Codex 세션을 검색하며, 선택형 MCP 도구, Codex 플러그인, 명시적 제한형 Codex wake를 추가합니다. 이제 메시지 입력과 결과 서식 지정에 별도의 명명된 옵션이 제공됩니다.

## 변경 사항

- #76: `list`의 기본값이 두 에이전트 모두로 설정됩니다. 각 세션에는 `agent`가 포함됩니다. 필터링하려면 `--agent claude` 또는 `--agent codex`를 사용하십시오. 검색은 독립적인 결과를 보고하며, 다른 소스가 실패하더라도 성공한 행을 보존합니다.
- #77: stdio `list_sessions` 및 `send_message` 도구를 사용하려면 `session-peer[mcp]`를 설치하십시오. Codex 플러그인 및 마켓플레이스 파일은 저장소에 있습니다. 기본 MCP 정책은 로컬 목록 조회만 허용합니다. 전송 및 SSH 목적지에는 명시적인 기능과 클라이언트 승인이 필요합니다.
- #78: 선택형 `send --wake`는 두 번째 프롬프트를 추가하지 않고 네이티브 app-server를 통해 비활성 Codex 스레드를 재개합니다. 별도의 wake 결과는 활성화가 실패하더라도 큐 제출 세부 정보를 보존합니다.
- #80: Codex 목록 조회는 기본 홈, `CODEX_HOME`, 제한된 macOS Orca 계정 홈 및 `SESSION_PEER_CODEX_HOMES`를 집계합니다. 행에는 정규 `codexHome` 및 `stateDb`가 포함됩니다. 서로 다른 홈의 동일한 UUID는 구분된 상태로 유지됩니다. 명시적 `--codex-home`은 해당 홈으로 목록 조회를 제한합니다.
- #82: `send --message TEXT` / `-m TEXT`는 메시지 입력을 명시적으로 선택합니다. `--output-format text|json`은 결과 서식 지정을 선택합니다. 위치 지정 메시지, stdin, `--b64`, `--json`은 계속 호환됩니다. 충돌하는 입력 소스 또는 출력 선택기는 전송 전에 거부됩니다.

## 호환성 및 제한 사항

- 필터링되지 않은 `list`의 소비자는 각 행의 `agent`를 사용해야 합니다. 다중 홈 결과에서는 해당 행의 `codexHome`을 사용하십시오. 둘 이상의 후보 홈이 관련된 경우 최상위 스칼라는 생략됩니다. 자동으로 감지되지 않는 Codex 설치는 빈 `not_installed`를 생성합니다. 명시적으로 구성된 홈이 누락된 경우는 오류입니다.
- 독립형 CLI는 Python 3.9+에서 의존성 없이 유지됩니다. 선택형 MCP 연동에는 Python 3.10+ 및 MCP extra가 필요합니다.
- Wake는 Codex CLI **0.154.0**이 설치된 macOS/Linux만 지원합니다. 다른 버전은 wake에 대해 안전하게 실패합니다. 일반적인 큐 전용 전송은 기존 동작을 유지합니다. Wake는 기존 정책에 따라 모델 사용량을 발생시키고 대상 세션의 프로젝트를 수정할 수 있습니다. 영구 워커가 아니라 1~60초로 제한되므로 타임아웃으로 인해 부분적인 작업이 중단될 수 있습니다. [wake 상세](../wake.md)를 참조하십시오.
- 큐 수락 및 wake 완료가 특정 메시지의 수신을 확인하는 것은 아닙니다. `consumptionConfirmed`는 계속 false로 유지됩니다. Wake 또는 SSH 실패 후 제출된 메시지를 절대 자동으로 재전송하지 마십시오.
- 홈 검색은 범위가 제한되어 있으며 읽기 전용입니다. 목록 조회가 세션을 깨우거나 작성기 잠금을 해제하지 않으며, 이번 릴리스에서는 릴레이 트랜스포트가 도입되지 않습니다.

## 업그레이드

해당 설치의 패키지 관리자를 사용하십시오(`pipx upgrade session-peer`, `uv tool upgrade session-peer`, 또는 `python -m pip install --upgrade session-peer`). MCP의 경우 `session-peer[mcp]` extra를 설치하거나 업그레이드하십시오. 독립형 설치는 `session-peer update`를 실행할 수 있습니다. 번들된 스킬을 새로고침하려면 v0.8.0 체크아웃에서 `install.sh`를 다시 실행하십시오. 플러그인 구성에 대해서는 [MCP 설정](../mcp.md)을 참조하십시오.

## 검증

- MCP SDK가 설치된 상태에서 301개의 테스트를 통과했습니다. 독립형 명시적 및 기본 unittest 검색은 각각 301개의 테스트를 성공적으로 실행했으며, 2개의 선택형 SDK 테스트는 건너뛰었습니다.
- Wheel 및 sdist를 새로운 환경에 각각 독립적으로 빌드하고 설치했습니다. 모듈 및 배포 메커니즘 메타데이터는 0.8.0을 보고합니다. 격리된 홈의 Codex 목록 조회는 성공적인 빈 `not_installed`를 반환합니다. Wheel의 MCP extra 및 엔트리 포인트도 설치되어 확인되었습니다.
- 두 배포판 모두 MCP 어댑터를 포함하고 동결된 레거시 `cc_peer.py`를 제외합니다. sdist에는 플러그인 및 연동 문서가 포함됩니다.
- 모든 기능 PR은 순차적 병합 전에 CI를 통과했습니다. 릴리스 CI는 Ubuntu/macOS의 핵심 Python 3.9/3.13 및 Windows의 3.13을 다룹니다. 선택형 MCP는 Ubuntu/macOS의 Python 3.10/3.13과 패키지/설치/셸 검사를 사용합니다.
- 릴리스 준비 중에 실시간 메시지나 wake 활성화는 제출되지 않았습니다. 이전의 실시간 wake 근거는 macOS의 Codex 0.154.0으로 제한됩니다. Linux 수명 주기 동작은 픽스처로 테스트되었습니다. [검증 근거](../wake.md#validation-evidence)를 참조하십시오.
