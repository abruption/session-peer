# session-peer 0.6.2

이번 릴리스에서는 중복 저장된 스레드에 명확한 실시간 작성기가 하나 있을 때 활성 Codex 홈을 선택하며, SSH 계정 선택 및 연결 실패를 호출자에게 표시합니다.

## 변경 사항

- 대상 UUID를 포함하는 알려진 모든 Codex 홈을 정확한 스레드 작성기 잠금, 커널 권고 잠금(advisory-lock) 프로브 및 두 번의 안정적인 `lsof` 소유자 관찰로 검증합니다. 동일 사용자의 실시간 작성기 정확히 하나만이 대상을 선택할 수 있습니다. 경쟁하거나, 불완전하거나, 변경되는 증거는 큐 추가 전에 실패합니다.
- `codex queue`를 호출하기 직전에 모든 경쟁 홈 후보를 재검증하고, 스키마 버전이 지정된 결정 및 제한된 증거를 `codexHomeResolution` JSON에 노출합니다.
- 자동으로 감지된 반환 경로가 전송 머신을 다시 가리킬 때 로컬 회신 명령어를 생성하여 불필요한 자체 SSH 로그인을 방지합니다.
- 원격 전달 시 명시적인 `USER@HOST`에 우선순위를 부여합니다. 그렇지 않은 경우 연결에 사용된 것과 동일한 별칭 및 옵션으로 `ssh -G`를 통해 유효 계정을 확인하고, JSON에 `sshUser` 및 그 소스를 보고합니다.
- SSH 인증, 호스트 키, 타임아웃 및 기타 트랜스포트 실패를 분류합니다. 인증 실패는 `USER@HOST` 또는 별칭의 SSH `User` 설정을 가리키며, session-peer는 계정을 추측하거나 다른 사용자 이름으로 재시도하지 않습니다.
- 모든 연결 실패를 설치 부재로 보고하는 대신 원격 독립형 버전을 프로빙할 때 SSH 실패 세부 정보를 보존합니다.

## 호환성 및 제한 사항

- 명시적인 `--codex-home`은 가장 강력한 대상 선택자로 유지되며 자동 멀티 홈 활동 확인을 우회합니다. 검색은 선택된/기본 홈, 구성된 홈 및 지원되는 Orca 계정 홈으로 제한됩니다.
- 자동 실시간 작성기 선택에는 대상 시스템의 POSIX 권고 잠금 및 `lsof`가 필요합니다. 중복 저장된 홈을 해결해야 할 때 도구 누락, 권한 실패 또는 상충되는 증거는 안전하게 실패(fail closed)합니다.
- 확인된 SSH 사용자는 구성 증거일 뿐 인증이 성공할 것이라는 증거는 아닙니다. session-peer는 자격 증명을 찾거나 SSH 구성을 변경하지 않습니다.
- 큐에 들어간 메시지가 여전히 소비나 확인을 증명하지는 않습니다. 회신 대기, 원격 경로 검증 및 더 광범위한 진단은 v0.7 로드맵에 남아 있습니다.

## 업그레이드

설치를 관리하는 패키지 관리자를 사용하세요:

```bash
pipx upgrade session-peer
uv tool upgrade session-peer
python -m pip install --upgrade session-peer
```

독립형 설치는 `session-peer update`를 실행할 수 있습니다. 번들된 Claude 스킬도 새로고침해야 하는 경우 v0.6.2 체크아웃에서 `install.sh`를 다시 실행하세요.

## 검증

- 명시적 `tests/` 검색과 기본 unittest 검색 모두에서 198개의 단위/통합 테스트를 통과했습니다.
- CI는 Ubuntu 및 macOS(Python 3.9/3.13), Windows(Python 3.13), 패키지 빌드 및 격리된 설치, 독립형 설치 스모크 테스트, shellcheck 및 시크릿 스캐닝을 다룹니다.
- Wheel 및 sdist 빌드를 검사하고 독립적으로 설치했습니다. CLI, 모듈 및 패키지 메타데이터는 v0.6.2를 보고하며 어떤 아카이브도 동결된 레거시 `cc_peer.py`를 포함하지 않습니다.
- 릴리스 준비 과정에서 실제 Claude 또는 Codex 메시지를 제출하지 않았습니다.
