# v1.6.0 릴리스 준비

준비일은 2026-11-15이며 기준은 이미 공개된 v1.5.0([GitHub](https://github.com/abruption/session-peer/releases/tag/v1.5.0), [PyPI](https://pypi.org/project/session-peer/1.5.0/))입니다. 이 날짜의 점검에서 v1.6.0은 미공개 소스 후보였습니다. 통합 소스 기준은 `0c5bd4243d76ac951dd70bca2b56c8a103fa4231`이며 버전 준비 전 커밋이지 최종 릴리스 커밋이 아닙니다. 프로젝트 소유자는 릴리스 준비 PR만 요청했습니다. 병합·태그/초안 생성·워크플로 실행·발행·운영 변경에는 별도 승인이 필요합니다. 제공 여부는 실제 릴리스와 패키지 기록에서 확인하십시오.

## 후보 범위

- #393 / [PR #396](https://github.com/abruption/session-peer/pull/396)은 일곱 번째 MCP 도구로 `list_sessions_page`를 추가합니다. macOS/Linux에서 기존 `list` 정책 권한을 사용하며 목적지 하나와 허용된 에이전트 하나를 명시합니다. 엄격한 JSON 인자 검사, 정확한 경로·정책 재검증, 별도 호스트 승인을 유지합니다. 프리셋·기기·복수 에이전트 선택자·임의 경로·자동 대체 경로는 추가하지 않습니다.
- #394 / [PR #395](https://github.com/abruption/session-peer/pull/395)는 정상 Claude 행을 유지하면서 실제 기록 읽기 권한 오류를 기존 탐색 오류 필드로 보고합니다. 기본 다중 에이전트 목록을 포함해 탐색이 불완전하면 CLI는 종료 코드 1을 반환합니다. 기존 MCP 목록은 부분 행을 유지하고 `isError=true`를 보고합니다. 자동 chmod·삭제·복구는 하지 않습니다. 정상 성공 출력은 바뀌지 않습니다. 스크립트와 MCP 클라이언트는 종료 코드 0을 가정하거나 정상인 부분 행을 버리지 말고 불완전한 결과를 명시적으로 처리해야 합니다.

## 페이지 제한과 증거

수집은 stdout 4 MiB와 stderr 64 KiB까지 보관하며 실행 예산은 10초입니다. 이후에는 별도로 제한된 기존 소유 프로세스 정리가 적용됩니다. 이는 엄격한 전체 경과 시간 제한이 아니며 상위 파일 시스템·SQLite 작업, 분리된 원격 프로세스, OS 스케줄링을 모두 제한하지 않습니다. 동기식 투영·검증·직렬화에는 별도 경과 시간 제한이 없어 다른 요청과 취소 처리를 지연시킬 수 있습니다. 네이티브 버전 추가 조회·모델 활성화·전송·깨우기는 도입하지 않습니다. 기존 CLI의 보조 검사와 운영자 SSH 설정의 명령 실행은 가능할 수 있습니다.

캐시는 스냅샷 4개, 스냅샷당 20,000행, 직렬화 기준 8 MiB 한도를 적용하며 RSS를 보장하지 않습니다. 권한을 확인하고 페이지를 정상 구성한 후속 조회는 30초 유휴 기한을 갱신하되 절대 수명 600초를 넘기지 않습니다. 만료 데이터는 나중에 정리하므로 백그라운드 삭제를 약속하지 않습니다. 커서·필터·정책 불일치, 만료·축출·재시작은 재수집 없이 거부합니다. 후속 조회에서는 `limit`을 포함한 모든 필터를 유지해야 하며, 결과의 64 KiB 한도로 요청보다 적은 행을 반환할 수 있습니다. 수집 진입 슬롯 하나로 무제한 대기열을 피합니다. 텍스트·구조화 데이터·보수적으로 계산한 SDK 2 메타데이터를 포함한 전체 인코딩 도구 결과는 64 KiB 이하이며 JSON-RPC는 제외합니다. 정확한 ID는 자르거나 합치지 않습니다. 선택 표시 이름에는 `nameTruncated=true` 또는 `nameOmitted=true`를 사용합니다. Claude ID는 1보다 큰 네이티브 PID를 정확히 십진 문자열로 나타낸 것이며 세대 토큰이 아닙니다.

유효한 부분 페이지는 `ok=true`, `complete=false`, `isError=false`로 허용된 행과 후속 조회를 유지합니다. 고정 거부 응답은 `ok=false`, `type="refusal"`, `isError=true`, `retryAllowed=false`입니다. 완전성은 소스가 보고한 증거를 뜻하며 모든 네이티브 세션의 탐색, 준비 상태나 이후 전송의 안전을 보장하지 않습니다. 알 수 없는 증거를 완전한 성공으로 바꾸지 않습니다. 빈 부분 페이지도 불완전 상태입니다. 자동 재시도는 허용하지 않으며 새로 명시적으로 승인된 조회는 별개입니다. [MCP 계약](../mcp.md#bounded-session-listing-393)을 참조하십시오. Windows는 새 도구의 수집을 시작하기 전에 거부하며 Windows 네이티브 에이전트 수용 범위를 확대하지 않습니다. 호출자 신원·소비·ACK·실효 저장소 증명·원자적 대상 세대 보장은 추가하지 않습니다.

## 소스 검토와 남은 검증

PR #395의 병합 커밋은 `0fc38ee0f3af7e34d86316902008d927c6f9f76b`, PR #396은 `0c5bd4243d76ac951dd70bca2b56c8a103fa4231`입니다. 최종 PR HEAD는 각각 `9410607`, `91fad69`이며 검사 57개씩 성공했습니다. PR #395의 이전 지적 해결은 새 HEAD의 코드 검토 실행을 뜻하지 않습니다. PR #396의 완료된 코드·보안 검사와 미해결 인라인 지적 부재는 한정된 검토 근거이지 인증이 아닙니다. 통합 기준 0c5bd4243d76ac951dd70bca2b56c8a103fa4231의 [CI](https://github.com/abruption/session-peer/actions/runs/43677746976) 작업 49개와 [CodeQL](https://github.com/abruption/session-peer/actions/runs/43677746980) 작업 3개가 모두 성공했습니다. 이 통합 기준 결과는 정확한 준비 HEAD와 최종 보호된 main 소스의 검사를 대신하지 않습니다.

정확한 HEAD 검사·독립 검토·재현 가능한 빌드·최신 감사·새 wheel/sdist 설치가 필요합니다. 소유한 메타데이터 픽스처와 읽기 전용 목록 확인은 모델·전송·ACK나 일반 네이티브·플랫폼 수용을 입증하지 않습니다. chmod 픽스처는 커널의 실제 읽기 거부를 확인해야 하며 root가 읽을 수 있다면 권한 거부 단언을 건너뛰어야 합니다. 외부 의존성 없는 기본 Python 3.9, 선택 MCP의 Python 3.10, `mcp>=1.30,<3,!=2.0.*,!=2.1.*,!=2.2.*`는 유지됩니다. #367, 의존성 PR #380/#387/#388, 연구 초안은 제외하며 Control·배포 변경도 없습니다.

준비 CI는 선택 SDK 없이 실행할 Windows 전용 미지원 플랫폼 거부 회귀 검사를 추가로 구성합니다. 실제 실행은 릴리스 PR HEAD에서 확인해야 합니다. 위 통합 기준 CI에서는 이 검사를 실행하지 않았으며 Windows MCP·네이티브 에이전트 지원을 추가하지 않습니다.

예정된 `SKILL.md` 지원 자산은 독립 공개된 스킬 v0.5.1, 소스 `95cf5e1dd92654775b2f0ea86c1cb4b6107f49c3`, 31688 UTF-8 바이트, SHA-256 `922512869577cc3d8b9d305641479e2dd659f0e669298584ca06f1ca15de1d31`를 유지합니다. 최소 런타임 0.9.1, 문서상 전체 워크플로 범위 1.4.0, 수신측 `codexBin` 하한 1.0.1은 그대로입니다. 스킬 버전·하한·소스 고정값·설치된 스킬은 변경하지 않으며 자산은 wheel/sdist 밖에 둡니다. [v1.5.0 공개 기록](v1.5.0.md#v150-publication-record), 날짜가 있는 준비 기록·앵커·기존 불변 자산을 보존합니다.

나중에 별도로 승인된 발행에서는 `SHA256SUMS`와 `release-provenance.json`을 포함한 동결 자산 7개, 정확한 태그·소스, 인증된 증명, 새 감사·설치, 필수 PyPI 환경 담당자 승인을 확인해야 합니다. 준비 단계는 태그·초안·워크플로 실행·발행을 수행하거나 보호를 우회하지 않습니다. 이전 자산을 교체하지 말고 실제 공개 기록을 별도로 남기십시오. 패키지 공개, 전역·전체 기기 설치, Node Control 배포, 독립 관리 스킬 전파는 별개입니다.
