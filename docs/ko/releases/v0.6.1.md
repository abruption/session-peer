# session-peer 0.6.1

이번 릴리스에서는 에이전트 간 메시지의 귀속을 더 쉽게 확인하고, 암시적 Codex 전송이 중복 세션 홈 중에서 조용히 선택하지 않도록 방지합니다.

## 변경 사항

- 선택된/기본 홈, macOS Orca 계정 홈 및 명시적으로 구성된 `SESSION_PEER_CODEX_HOMES` 전반에서 중복된 Codex 스레드 UUID를 감지합니다. 모호한 암시적 전송은 큐 추가 전에 실패하며, `--codex-home`은 명시적인 대상 선택자로 유지됩니다.
- 선택, 큐 제출 및 소비가 혼동되지 않도록 `codexHome`, `submitted` 및 `consumptionConfirmed` 필드를 추가합니다.
- 기본 메시지 엔벨로프에서 감지된 발신자를 `claude:<session>` 또는 `codex:<thread-uuid>`로 식별하고 일치하는 회신 대상을 생성합니다.
- 알려진 Tailscale SSH 대상을 `tailscale status --json`을 통해 확인합니다. 온라인 피어는 현재 MagicDNS FQDN을 통해 라우팅되고, 오프라인 피어는 SSH 전에 실패하며, 일치하지 않는 대상은 일반 SSH 호스트로 유지됩니다.
- 제공된 대상을 SSH 별칭으로 유지하고, `HostName`을 검증된 MagicDNS로 재정의하며, `HostKeyAlias`를 통해 제공된 호스트를 유지함으로써 기존 SSH 구성 및 호스트 키를 보존합니다. 결과에는 둘이 다를 때 정규 `host`와 원래 `sshHost`가 보고됩니다.
- 표준 라이브러리 테스트 스위트를 `tests/` 아래로 정리하고 CI 검색을 업데이트합니다.

## 호환성 및 제한 사항

- 기존 Claude/Codex 대상, 억제 플래그, 일반 SSH 대상 및 패키지/독립형 설치 경로가 계속 지원됩니다.
- 발신자 엔벨로프는 최선의 메타데이터이며 인증된 신원이 아닙니다.
- 큐에 들어간 메시지가 소비나 확인의 증거는 아닙니다. 이번 릴리스에서는 세션을 깨우거나, 회신을 기다리거나, 역방향 SSH 연결 가능성을 확인하지 않으며, 이들은 v0.7 로드맵에 남아 있습니다.
- 둘 이상의 Codex 홈을 사용하는 사용자는 list, dry-run 및 send에 동일한 명시적 `--codex-home`을 전달해야 합니다.

## 업그레이드

설치를 관리하는 패키지 관리자를 사용하세요:

```bash
pipx upgrade session-peer
uv tool upgrade session-peer
python -m pip install --upgrade session-peer
```

독립형 설치는 `session-peer update`를 실행할 수 있습니다. 번들된 Claude 스킬도 새로고침해야 하는 경우 v0.6.1 체크아웃에서 `install.sh`를 다시 실행하세요.

## 검증

- 명시적 `tests/` 검색과 기본 unittest 검색 모두에서 174개의 단위/통합 테스트를 통과했습니다.
- CI는 Ubuntu 및 macOS(Python 3.9/3.13), Windows(Python 3.13), 패키지 빌드, 독립형 설치 스모크 테스트, shellcheck 및 시크릿 스캐닝을 통과했습니다.
- Wheel 및 sdist 빌드와 격리된 아티팩트 설치가 검증되었습니다.
- 로컬 Codex 목록 조회 및 명시적 홈 dry-run이 제출 없이 완료되었습니다.
- Tailscale IP로 제공된 읽기 전용 SSH 목록 조회가 원래 호스트 키 별칭을 보존하면서 검증된 MagicDNS 이름을 통해 연결되었습니다.
