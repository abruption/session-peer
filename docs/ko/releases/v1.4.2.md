# v1.4.2 유지보수 릴리스 준비

공개된 v1.4.1([GitHub](https://github.com/abruption/session-peer/releases/tag/v1.4.1), [PyPI](https://pypi.org/project/session-peer/1.4.1/))을 기준으로 2026-11-05에 준비했습니다. 이 날짜의 확인 시점에서 v1.4.2는 미공개 유지보수 후보입니다. 통합 유지보수 기준은 버전 준비 이전의 `c265861d5251f8bab65229521444168e23bc13a9`이며, 최종 릴리스 커밋이 아닙니다. 소유자의 요청은 발행 준비이며, 병합·태그·초안 생성·워크플로 실행·발행·운영 배포를 승인하는 것은 아닙니다.

## 범위

- PR #372는 handoff watch 테스트 코드의 #370을 보완합니다. 파이프 관찰에 마감 시간을 두고, 중단 종료 구간에 들어가기 전에 보조 프로세스의 출력을 확인하며, 프레임 누락·준비 단계 실패 회귀 사례로 제한 시간 내 실패와 보조 프로세스 정리를 검증합니다. CI는 POSIX 테스트 행렬의 각 작업을 15분, 그 안의 핵심 테스트 단계를 5분으로 제한하며 치명 신호 발생 시 스택을 추적하도록 faulthandler를 활성화합니다. 이는 테스트·CI 보완이며, 제품 런타임 결함 수정이나 원래 CI 정지 원인의 입증이 아닙니다.
- PR #374는 한국어·일본어·중국어 간체 README와 운영 가이드의 #373을 보완합니다. handoff의 수신 확인·ACK 정보, 저장된 페어링 요청 처리 결과, 과거 Control 관리 작업 결과, SSH 호스트 키 확인 기록을 구분합니다. 관련 운영 용어를 바로잡고 기존 영문 탐색·설정 설명을 명확히 하며, 제목 계층과 줄바꿈이 있는 인라인 코드 검사를 강화합니다. 기존 queued/submitted, 소비와 ACK의 구분은 유지합니다.
- 버전 값 외의 런타임 동작은 바뀌지 않습니다. 동결된 [영문 handoff 계약](../../contracts/handoff-v1.md)과 해당 계약의 [고정된 시험 데이터](https://github.com/abruption/session-peer/blob/c265861d5251f8bab65229521444168e23bc13a9/tests/fixtures/handoff-v1.json)는 그대로입니다. PR #372는 별도의 watch 테스트 보조 코드를 수정했습니다. 새 기능, 새로운 네이티브·SSH 전달, Windows 3.14·free-threaded Python, 소비·ACK 보장이나 플랫폼 지원 검증을 주장하지 않습니다.
- #316의 Relay 테스트·종료 진단 모니터링, #367의 페어링 기기 전체 조회와 Long-term 연구는 별도입니다. 재실행 성공만으로 과거 장애의 원인이나 해결이 입증되지는 않습니다.

## 호환성과 독립 스킬

기본 Python 3.9, MCP Python 3.10+ 및 SDK 요구사항 `mcp>=1.30,<2`는 그대로입니다.

예정된 `SKILL.md` 지원 자산은 공개된 [스킬 v0.5.1](https://github.com/abruption/session-peer-skill/releases/tag/v0.5.1), 소스 `95cf5e1dd92654775b2f0ea86c1cb4b6107f49c3`, UTF-8 31688바이트, SHA-256 `922512869577cc3d8b9d305641479e2dd659f0e669298584ca06f1ca15de1d31`을 유지합니다. 메타데이터는 스킬 0.5.1 / 최소 런타임 0.9.1 / 문서에 안내된 전체 사용 흐름의 기준(full) 1.4.0이며, 수신측 `codexBin` 하한은 1.0.1입니다. 이번 런타임 패치는 이 하한을 올리거나 새 스킬을 발행하지 않습니다. 정확한 소스·해시 고정만으로 GitHub의 불변성 보장을 주장하지 않습니다. 지원 스킬은 wheel/sdist에 포함되지 않습니다.

기존 태그·불변 자산과 날짜별 준비·공개 기록을 보존합니다. 패키지 발행은 별도로 관리되는 스킬이나 다른 전역 MCP 환경을 갱신하거나, 수신기를 재시작하거나, Node Control 서비스를 배포하지 않습니다.

## 발행 조건

정확한 준비 HEAD와 최종 보호된 main 소스의 검사·리뷰 통과가 필요합니다. 이후 별도로 승인된 발행에서는 고정 자산 7개(`SHA256SUMS`와 `release-provenance.json` 포함)와 인증된 증명을 정확한 태그·소스에 대조하고, 최신 의존성 감사와 새 환경의 wheel/sdist 설치 검사를 수행하며, PyPI 환경의 필수 사람 승인을 유지해야 합니다. 이는 남은 조건이며, 이번 준비에서 완료를 주장하는 결과가 아닙니다. 비공개 로그인·연결 재확인을 생략해도 사람 승인을 면제하거나 보호 절차를 우회할 수는 없습니다.

이후 승인된 빌드 전에 공개를 미리 단정하지 않는 이 날짜별 노트를 고정합니다. 실제 GitHub/PyPI 공개 근거는 별도로 남깁니다. 공개를 미리 발표하거나, 버전을 재사용하거나, 기존 태그를 옮기거나, 불변 자산을 교체하지 않습니다. 릴리스 준비와 운영 배포는 별개입니다.
