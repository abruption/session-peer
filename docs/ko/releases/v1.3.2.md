# v1.3.2 유지보수 릴리스

공개된 v1.3.1을 기준으로 2026-10-28에 준비했습니다. Direct 기능 소스 기준은 `dac1c30b1553136b9379be0c6d94eef34ccbad51`이며 최종 통합 릴리스 커밋은 아닙니다. 이 문서는 준비 범위를 설명하며, 실제 공개 기록은 [GitHub Releases](https://github.com/abruption/session-peer/releases)와 [PyPI](https://pypi.org/project/session-peer/)에서 확인하십시오.

PR #345의 게이트 수정 소스 기준은 `a68c6cf16c234cd3fe72926e519e4178c093081a`입니다. 병합된 PR #347 이후 통합 준비 기준은 버전 준비 커밋 이전의 `ef7748a78e6b466f67074708f5c14decf37f31d7`입니다. 최종 발행 증거에서 릴리스 커밋을 별도로 식별합니다.

## 변경 사항

- #341 / #342: 수신기 시작 출력의 `ready:true`를 유지하고 `directReadyConfirmed:false`를 추가해 로컬 리스너 구성과 원격 도달 가능성을 구분합니다. TLS 완료만으로 페어링·네이티브 대상 접근·ACK를 증명하지 않습니다.
- 명시적으로 선택하는 `--diagnostic-events`에 Direct 콜백·TLS 관측과 상한이 있는 수신기별 `accepted`, `tlsCompleted`, `tlsFailed` 카운터를 추가합니다. `accepted`와 `peer_tls` 단계는 합계로 60초에 최대 2개를 기록하며, TLS 성공·실패는 후자의 단계 제한을 공유합니다. 정상 종료 시에는 0회도 포함한 `summary`의 기록을 1번 더 시도하고, 종료 처리를 반복해도 재시도하지 않습니다. 고정 필드에는 주소·피어/세션 ID·메시지 데이터·예외 원문을 포함하지 않습니다. 로깅 실패는 원래 핸드셰이크 예외를 대체하지 않습니다. 기존의 동기식 stderr 출력에는 출력 대상이 막혔을 때 강제 시간 제한이 없습니다.
- 실험용 TCP 프로브는 Python 3.9/3.10의 `asyncio.TimeoutError`를 처리하며, Python 3.9/3.13에서 응답이 지연되는 루프백 회귀 시험을 수행했습니다. 수동 두 Mac·tailnet 실험은 CI와 별개이며 `experiments/`는 wheel/sdist에서 제외됩니다. [실험 기록](https://github.com/abruption/session-peer/blob/dac1c30b1553136b9379be0c6d94eef34ccbad51/experiments/macos-direct-listener/README.md)을 참고하십시오.
- #343 / #345: Node Control의 `better-auth`와 `@better-auth/core` 고정 버전을 1.7.5에서 1.7.7로 올리고 어댑터·telemetry 버전도 맞춥니다. 업스트림은 [GHSA-965c-763c-88jm](https://github.com/advisories/GHSA-965c-763c-88jm)(치명적), [GHSA-r4xp-prcw-77qf](https://github.com/advisories/GHSA-r4xp-prcw-77qf)(높음), [GHSA-44jh-23m7-hpcf](https://github.com/advisories/GHSA-44jh-23m7-hpcf)(낮음)의 최초 수정 버전을 1.7.7로 명시합니다.
- #344 / #345: 보호된 읽기 구간에 들어간 뒤에만 READY를 알리도록 SIGINT 시험을 동기화합니다. macOS Python 3.13에서 관측한 시그널 종료(-2)와 기대한 처리 후 종료 130 사이의 경합에 대응하며, 제품의 시그널 동작이 아닌 시험 동기화를 바꿉니다. 고정 sleep이나 약화된 단언으로 이 경계를 대체하지 않으며, 과거 CI 실패의 정확한 원인이 확정된 것은 아닙니다.

- #346 / #347: 선택적 MCP SDK 요구 사항을 `mcp>=1.30,<2`로 올립니다. 코어의 Python 3.9 하한과 MCP의 Python 3.10+ 마커는 그대로입니다. POSIX CI는 Mac/Linux, Python 3.10/3.13, 정확한 하한 `1.30.0` 또는 최신 호환 `1.x`의 SDK 프로필 2개를 조합한 8개 셀로 구성합니다. 간접 의존성은 일반 규칙으로 해석하며, 하한 프로필이 모든 패키지의 최소 버전을 검증하는 것은 아닙니다. 설치된 SDK의 표준 입출력(`stdio`) 계약 검사는 HTTP/OAuth 노출이나 악용 가능성을 입증하지 않습니다.

PR #345의 두 게이트 수정은 별도로 검토된 커밋으로 병합됐고, PR #347의 MCP 하한·CI 프로필도 병합됐습니다. 검토한 PR #347 커밋은 MCP 8개 셀을 포함한 검사 32개를 통과했으며, 자동 Codex 코드·보안 리뷰도 별도로 지적 없이 완료됐습니다. 이 PR 결과는 보호된 최종 main 검증이나 발행 증거를 대신하지 않습니다. 릴리스 준비 PR 병합 전 현재 main 검사의 성공을 확인해야 합니다.

## 원인과 호환성 범위

소유자가 Python.app의 들어오는 연결을 허용한 뒤, 두 Mac 모두 공개된 원래 v1.3.1의 Homebrew Python 3.14.9 런타임, 각 Mac에서 같은 tailnet 바인딩 주소와 포트로 Direct 페어링과 인증된 probe를 완료했습니다. 새 시험 신원을 사용했고 네이티브 호출은 0회였습니다. 중계기나 대체 인터프리터는 필요하지 않았습니다. 이 결과는 이번 사례의 차단 원인이 macOS 애플리케이션 방화벽의 승인 대기였음을 뒷받침합니다. 진단 코드가 연결을 복구한 것은 아닙니다. 이전의 연결 실패·코드 서명·중계 대조시험은 과거 실측 기록이며 필수 해결책이나 macOS·Tailscale·Python의 보편적인 원인 판정이 아닙니다.

Direct의 바인딩, TLS·인증 검사, 시간 제한, 페어링 상태와 자동 재시도 금지 동작은 유지합니다. 방화벽·접근 정책·런타임 선택을 자동화하지 않으며 새 플랫폼이나 일반 ACK 지원을 추가하지 않습니다. 기존 사용자의 pending 상태는 재시도하거나 초기화하지 않았습니다. 네이티브 세대 식별·handoff·저장소·시작 시점 수락 조건(#180/#181/#268/#304/#306/#307)과 Side Session·steering 연구는 별도 과제입니다.

선택적 Relay 수신기 모듈의 변경은 wheel/sdist에 포함되며 독립 실행형 `session_peer.py`에 내장되지 않습니다. 진단 기능을 적용하려면 수신기 자체의 패키지·환경을 갱신하고 해당 프로세스를 명시적으로 재시작해야 합니다. 독립 실행 파일만 갱신해서는 이 모듈이 갱신되지 않습니다. 이번 발행에서는 운영 갱신이나 재시작을 수행하지 않습니다.

검토한 Control 소스는 SQLite와 `bearer`, `deviceAuthorization` 플러그인을 사용하며, 권고문에 나온 Magic Link/OAuth Proxy/PostgreSQL 경로는 사용하지 않습니다. 운영 환경의 악용 가능성은 입증하지 않았습니다. Node Control 의존성 수정은 Python wheel/sdist에 포함되지 않으며 별도로 승인된 서비스 배포가 필요합니다. 업스트림의 OAuth 검증 식별자 접두어 변경을 검토하고, 검증 저장소를 공유하는 서버들의 갱신을 조율하십시오. 업데이트 뒤 진행 중이던 OAuth 로그인은 처음부터 다시 시작해야 할 수 있습니다. 이 준비에서는 운영 배포·세션 취소·데이터 마이그레이션을 수행하지 않습니다.

호환 스킬은 v0.4.0, 최소 런타임 0.9.1 / 문서의 CLI 기능 기준 1.3.0을 유지하며 수신 측 `codexBin`의 최소 버전은 1.0.1입니다. 변경되지 않은 SHA-256은 `debedd472e3b0c0c6844fb63f7fb2f17cb6c6cc8c3e981e9afd2531a35327af7`입니다. 런타임 발행은 별도로 관리되는 스킬을 갱신하거나 실행 중인 서비스를 배포하지 않습니다.

## 릴리스 검증

게이트 수정의 로컬 검증에서는 Control 테스트 123개, Node/Python 연동 테스트 11개, 취약점 0건을 보고한 의존성 감사가 기록됐고, Python 3.9/3.13 각각의 stdin 테스트 17개와 통제된 시그널 시도 400회도 통과했습니다. 이 로컬 결과는 보호된 main의 CI나 실제 OAuth 수락 시험을 대신하지 않습니다.

로컬 Mac MCP 검증은 SDK·Python 프로필 4개 각각에서 MCP 테스트 28개를 통과했고, 의존성 감사에서 보고된 취약점은 0건이었습니다. 현재 문서 검사도 69개를 통과했습니다. 이 로컬 결과는 CI 매트릭스 8개 셀, 최종 main 검사나 HTTP/OAuth 수락 시험을 대신하지 않습니다.

#342의 검증 기록에는 Relay 테스트 354개, 문서 테스트 65개, Python 3.9/3.13에서 시험한 프로브 회귀 테스트 1개가 포함됩니다. 이는 구현 검증 자료이며 이번 준비의 새로운 네이티브 에이전트 수락 시험은 아닙니다. 최신 준비 리뷰, 보호된 main의 CI, 의존성 감사, 생성기 일치, 재현 가능한 산출물과 신규 설치 검증을 완료해야 합니다. 준비가 성공한 뒤에는 `SHA256SUMS`와 `release-provenance.json`을 포함한 불변 자산 7개 및 해당 자산의 인증된 attestation을 정확한 태그·소스와 대조한 후 공개하십시오. 사람이 수행하는 필수 PyPI 환경 승인은 유지합니다. 이 준비는 기존 v1.3.1 자산이나 운영 설치본을 교체하지 않습니다.
