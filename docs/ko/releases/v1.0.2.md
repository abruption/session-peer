# session-peer v1.0.2

v1.0.1 이후 안정성에 집중한 유지보수 릴리스입니다. 로컬/SSH 코어 명령은 Python 3.9+에서 외부 의존성 없이 유지됩니다. Relay와 MCP는 선택형이며 Antigravity 브리지는 실험 상태입니다.

## 변경 사항

- Control은 거부되거나 실패한 변경 뒤에도 상태 확인과 공개 상태의 일관성을 유지합니다(#200). 공개 상태 용량을 커밋 전에 판독기의 1 MiB UTF-8 제한으로 검사하며 폐기 기록을 누락하지 않습니다(#208).
- Control은 속도 제한을 위해 루프백 역방향 프록시가 전달하는 클라이언트 신원을 인증할 수 있습니다. 임의의 전달 헤더는 신뢰하지 않습니다(#202).
- 복구는 완료된 저널 항목을 전달 증거로 간주하지 않고 네이티브 결과가 불명확하면 미해결로 유지합니다(#201). 승인 스키마 v2는 `peerGeneration`을 서명하고 키 교체 세대를 보존합니다(#203).
- 독립형 설치기는 다운로드를 준비하고 CLI를 검증한 뒤 런타임을 원자적으로 교체합니다. 다운로드·검증 실패 시 기존 설치를 보존합니다(#204).
- 명시적 Codex wake와 MCP CLI 정리는 TERM에 저항하는 자손을 포함해 소유한 POSIX 프로세스 그룹을 회수합니다(#205, #206).
- SSH는 인코딩·봉투 비용을 포함한 셸 인용 UTF-8 명령의 크기를 검사해 SSH 실행 전에 초과 요청을 거부합니다(#207).
- SQLite 백업 fixture가 연결을 명시적으로 닫습니다(#209). Relay 설정 실패는 허용된 사유별 안내를 제공하며 의존성 설치·로그인·페어링·재전송을 자동 수행하지 않습니다(#210).
- 호환 스킬 스냅샷을 v0.3.1로 동기화하고(#199) 고정된 GitHub Actions를 갱신했습니다. 별도 설치 스킬은 원래 업데이트 관리자를 유지합니다.

## 설치 및 업그레이드 경계

기존 설치 관리자를 사용하며 다른 설치를 조용히 대체하지 마십시오.

```bash
pipx upgrade session-peer
# New Unix / WSL installation with optional Relay and MCP:
pipx install 'session-peer[relay,mcp]==1.0.2'
```

코어는 Python 3.9+, MCP는 3.10+, Relay 수신기/서버는 Unix 또는 WSL의 Python 3.11+가 필요합니다. 서비스로 실행하는 macOS/Linux 수신기는 서비스 PATH의 Codex 실행 파일이나 운영자가 관리하는 `codexBin` 설정이 계속 필요합니다. 전송 전에 `--dry-run`으로 대상을 확인하십시오.

- v2 승인을 생성하기 전에 복구를 커밋할 기기를 업그레이드하십시오. 이전 릴리스는 v1만 허용합니다. 보관된 키 세대를 알 수 있으면 기존 승인을 사용할 수 있으며 교체된 키 세대를 추측하지 않습니다. 활성화 전에 기존 복구 계획을 보관 영수증과 대조하십시오. 재개 시 과거 계획을 다시 쓰지 않습니다.
- 인증된 프록시 신원에는 `SESSION_PEER_TRUSTED_PROXY_TOKEN_FILE` 및 두 전용 헤더를 덮어쓰는 프록시의 별도 운영 설정이 필요합니다. 기본값은 소켓 주소 기준 속도 제한입니다. 패키지 설치는 프록시 설정을 바꾸거나 임의 CDN 헤더를 신뢰하지 않습니다.
- 이미 용량을 초과한 Control DB는 안전하게 용량 문제를 해결할 때까지 비정상 상태로 남습니다. 새 제한은 역사 기록을 삭제하지 않습니다. Control 배포는 Python CLI 설치와 별개입니다.
- 원자적 교체는 런타임 파일에 한정되며 모든 파일의 트랜잭션이나 이후 스킬 관리자 실패의 롤백이 아닙니다. POSIX 정리는 소유 그룹을 벗어난 프로세스와 원격 SSH 프로세스를 포함하지 않으며 Windows MCP 정리는 직접 자식만 대상으로 합니다.

## 검증 및 알려진 한계

릴리스 준비 게이트에는 회귀 테스트, 문서·번역 검사, 생성 소스 검사, 아카이브 검사, 재현 가능한 빌드, 깨끗한 wheel/sdist 설치가 포함됩니다. 이는 새로운 실환경 4시간 캠페인이나 호스팅 Relay/OAuth 가용성 보장이 아닙니다. 과거 RC4 근거는 v1.0.0에 속하며 이번 유지보수 릴리스의 근거로 소급하지 않습니다.

#161은 열려 있습니다. 간헐적인 공개 경로 정체의 근본 원인과 귀책은 미확정이며 이번 릴리스가 해당 네트워크 경로를 고쳤다고 주장하지 않습니다. `posted`, `queued`, `submitted`는 제출 증거이지 소비나 ACK가 아닙니다. 불명확한 결과를 자동 재전송해서는 안 됩니다. 패키지 발행, 기기 설치, 운영 재시작은 별도 작업입니다.
