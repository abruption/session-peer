# 실험적 Handoff 런타임

드라이런은 새로 발견한 다른 대상이 아니라 원래 준비한 대상을 검증합니다. Claude는 원래 PID·세대 검사를 유지하고, Codex는 원래 홈·실행 프로세스 정보를 다시 검사하고 대조합니다. 정보가 바뀌면 실제 전송 없이 거부하며, 준비한 대상 기록을 바꾸지 않습니다.

이 문서는 [#181](https://github.com/abruption/session-peer/issues/181)을 위해 2026-10-09 공개 Python v1.1.0에 포함된 제한적인 실험적 handoff 구현을 설명합니다. [확정된 Handoff v1 설계](contracts/handoff-v1.md)와 합성 검증 자료는 변경하지 않았습니다. 공개는 모든 설계 수락 조건의 완료나 모든 플랫폼·실제 에이전트 경로의 검증을 뜻하지 않습니다.

## 지원하는 실험적 경로

같은 POSIX 기기의 Claude 수신함에 전송할 때, 사용자가 명시적으로 초기화한 개인 기록과 별도의 비공개 수신 확인 수집기를 사용할 수 있습니다. 연결된 수신함의 PID, 원래 프로세스 생성 정보와 등록된 연결 경로가 선택한 세대와 일치해야 합니다. 같은 POSIX 기기의 Codex는 연관 ID가 있는 큐 제출을 지원하되 확인 권한을 발급하지 않고 대상 세대는 null로 유지합니다. 전달·수신 확인을 요구하는 대기는 큐 호출 전에 거부하며, 최선형 확인·관찰 요청은 unsupported와 실제 제출 사실을 함께 반환합니다. 모델이나 세션을 시작하지 않습니다. 단일 POSIX SSH 대상으로는 아래 설명과 같이 소스를 전달해 Claude·Codex에 연관 ID 전용 제출을 수행합니다. 본문을 읽지 않는 Codex 관찰, Windows의 시간 제한 파이프, 페어링 기기와 SSH 수신 확인 준비 경로는 아직 지원하지 않습니다. 기존 일반 로컬·SSH 전송과 Codex wake 버전 제한은 유지합니다.

```sh
session-peer handoff init --json
session-peer handoff prepare --to worker --message-file ./private-message.txt --json
session-peer send --to worker --message-file ./private-message.txt --correlation-id PREPARED_UUID --request-ack --wait-for acknowledged --wait-timeout 30 --json
session-peer handoff status --correlation-id PREPARED_UUID --json
session-peer handoff wait --correlation-id PREPARED_UUID --wait-for acknowledged --wait-timeout 30 --json
session-peer ack --receipt - --json
session-peer handoff confirm --receipt - --json
```

메시지 파일은 소유자만 접근할 수 있는 일반 UTF-8 파일이어야 합니다. 예시 문자열 대신 prepare가 반환한 ID를 사용합니다. 수신 확인·수동 확인 JSON은 비공개 표준 입력으로만 전달합니다. 수신자는 자신의 일반 권한 절차에 따라 확인을 보낼지 결정합니다. 위임된 확인 권한은 다른 도구 실행, 메시지 전송, 모델 시작이나 대화 기록 열람의 승인이 아닙니다. 자동 응답을 추정하지 않습니다.

실험적 핸드오프 전송은 이름 있는 옵션·위치 인자 메시지, 비공개 메시지 파일 또는 시간 제한이 있는 POSIX 원시 표준 입력을 받습니다. 표준 입력은 원래 전송 마감 하나를 사용하고 UTF-8을 엄격하게 검증하며, 원시 400만 바이트·100만 코드포인트로 제한합니다. 끝나지 않는 파이프나 SIGINT는 전송 기록 생성 전에 거부하며 가짜 epoch·제출 결과를 만들지 않습니다. 수신·수동 확인 표준 입력은 별도의 크기·시간 제한 API입니다. 선택적 다중 호스트 전송은 남은 구현 조건입니다. 기존 일반 전송의 표준 입력과 다중 호스트 동작은 유지합니다. 실제 전송에는 공통 외부 메시지 경계를 적용해 본문의 모든 줄을 인용하며, 최종 문자 수 제한에는 이 경계와 확인 권한도 포함합니다.

Codex 준비는 정규화한 스레드·저장 경로와 크기가 제한된 원래 저장 경로·쓰기 프로세스 판단을 비공개로 기록합니다. 준비한 ID를 재사용할 때 판단이 바뀌면 대상에 다시 연결하지 않고 거부합니다. 이는 원자적인 프로세스 세대나 소비 증명이 아닙니다. 기존 활성 쓰기 프로세스·명시적 비활성 경로 선택 규칙을 유지하고, 단 한 번의 큐 호출 직전에 원래 판단을 다시 확인합니다. 버전 조회와 큐는 #268의 공통 저장 경로 검사·환경 정규화를 사용하지만 네이티브 설정 계층·데몬에 대한 보장은 해당 이슈의 미해결 조사 범위입니다. 전용 POSIX 자식 프로세스의 원시 출력·진단 크기를 제한하고 원래 마감·정리 예산을 사용합니다. 완전한 대상 일치 큐 응답은 시간 초과·비정상 종료 뒤에도 queueId·제출 사실을 유지할 수 있습니다. 응답 부재·다른 대상·불완전한 응답·잘못된 UTF-8·한도 초과 출력은 종료 코드가 0이어도 미확정이며 재전송하지 않습니다. stderr 진단은 제출 증거가 아니고 app-server·본문·대화 기록 API를 호출하지 않습니다.

확인 권한을 발급하기 전에 정확한 보호된 스크립트·인터프리터와 그 스크립트의 ACK 명령을 검사합니다. 비공개 전송 입력에는 검증되지 않은 PATH의 session-peer가 아니라 해당 격리 Python 확인 처리기와 기록 경로를 명시하며, 원본 권한 토큰은 표준 입력에만 넣습니다. 수신·수동 확인 입력은 EOF까지 총 5초와 4096바이트로 제한합니다. 실제 제출 뒤 저장이 실패하면 독립적으로 확인한 대상·문자 수·dry-run 사실은 유지하고, 증명할 수 없는 handoff·ACK는 생략하고 재시도를 금지합니다. 명시적 대기가 없다면 확인된 제출은 성공·종료 코드 0과 고정된 기록 진단을 유지합니다. 증명할 수 없는 명시적 대기는 종료 코드 1/130으로 실패하되 대기 결과를 만들지 않습니다.

Codex의 연관 ID 전용 전송에는 진행 중인 명시적 대기가 없습니다. 유효하고 완전한 큐 응답 뒤 SIGINT가 오면 성공·종료 코드 0과 wait not_requested를 유지하며, 불완전한 증거는 미확정·종료 코드 130입니다. 버전 사전 조회 중 중단하면 큐 호출 없이 거부·종료 코드 130을 반환합니다. stderr 진단 한도 초과는 stdout 한도 초과와 구분하므로 이미 받은 유효한 stdout 응답을 지우지 않습니다. 프로토콜 stdout이 한도를 넘으면 항상 미확정입니다. 실패한 제출의 기록은 고정된 오류 사유만 허용하며, 손상된 성공·비밀 필드는 조회 결과에 복사하지 않고 ledger_corrupt로 거부합니다. 잘못된 공개 연관 ID는 메시지 입력 전에 사용법 오류·종료 코드 2를 반환합니다. 비공개 수신 확인 검증은 별도 작업 실패입니다.

## 소스 전달 방식의 SSH 연관 ID 전용 경로

구조화된 SSH 자기 주소가 로컬로 확인되면 준비된 ID 재사용과 시험 실행에서도 로컬 메시지 한도를 유지합니다. 실제 SSH 대상에는 명령 인자 한도인 90,000자가 적용됩니다. 보호된 메타데이터 자식 프로세스는 UTF-8 인코딩과 JSON 이스케이프를 포함한 입력·출력 JSON 프레임 각각을 1 MiB로 제한하므로, 로컬 문자 한도에 맞는 입력도 제출 전에 거부될 수 있습니다.

송신 측은 메타데이터, 전송 없는 대상 확인, 영속적인 제출 의도 기록, 단 한 번의 실제 제출과 정리에 대상별 원래 예산을 사용합니다. 보호된 메타데이터 자식 프로세스는 탐지 시간을 새로 부여하지 않고 From·Reply와 구조화된 SSH 자기 주소의 로컬 변환을 유지합니다. 이미 시도한 의도는 새 조회 전에 거부합니다. 원격 전달·수신 확인이 필수인 대기는 SSH 제출 전에 거부하고, 최선형 요청은 unsupported를 반환하며 권한이나 원격 기록·수집기를 만들지 않습니다. 실제 제출은 원래 Claude 세대 또는 정규화한 Codex 홈·쓰기 프로세스 정보를 다시 검사합니다. Codex 세대 고정 요청은 지원하지 않으며 조용히 제거하지 않습니다. 상태 조회·대기는 SSH 제출을 수행하지 않습니다.

예비 확인은 회신 전에 원격 부팅에 연결된 단조 시계 기준점을 기록합니다. 송신 측은 응답을 엄격히 검증한 뒤 원래 시계를 한 번 읽어 남은 두 시간을 계산합니다. 원격 제출은 과거 기준점과 남은 시간을 사용하고 총예산 안에 정확히 5초의 정리 시간을 둡니다. 부팅 변경, 미래·만료된 기준점이나 잘못된 요청은 실제 제출 전에 거부합니다. UTC나 기기별 시계 원점을 비교하지 않습니다. SSH 종료는 원격 제출이나 소비 취소의 증거가 아닙니다. 홈 대응은 신뢰된 원격 처리기가 실제로 expanduser·resolve한 결과이며 전용 심볼릭 링크도 포함합니다. 송신 측에서 독립 검증한 inode, 원자적인 프로세스 세대나 보편적인 저장 경로 보장이 아닙니다.

실제 명령은 설정·소스·SSH 자식 프로세스가 시작되기 전에 제한된 비공개 처리기로 연결되어야 합니다. 숨겨진 옵션은 인증이 아니며, 수신 측은 외부 본문을 줄마다 한 번 인용합니다. 엄격한 네이티브 형식과 요청·대상·홈·상태 검증은 연결 종료, 시간 초과, 진단 한도 초과나 중단 뒤에도 완전한 제출 증거를 유지합니다. 프로토콜 stdout이 넘치면 남은 정상 접두부만으로 성공 처리하지 않습니다. 같은 연결에서 검증된 SSH 신원과 안전한 회신 메타데이터는 네이티브 사실과 구분해 유지합니다. 비공개 증거, 본문, 시계 기준점과 내부 네이티브 상태는 공개 출력에 포함하지 않습니다. 전용 가짜 SSH·소스 전달·SQLite·큐 시험은 이 구현 범위를 검증할 뿐 실제 원격 서버, 모델 소비나 설치된 역방향 SSH 수신 확인 준비의 증거가 아닙니다.

## 요청 한 건의 상태 조회

```sh
session-peer handoff status --correlation-id PREPARED_UUID
```

이미 준비한 ID를 사용합니다. 사람이 읽는 화면은 로컬 소유자의 기록을 한 번 조회해 확인된 제출 사실, 주입 관측, ACK의 확인 근거와 지연 여부, 마지막으로 저장된 대기, 재시도 금지와 지원되는 다음 조치를 보여줍니다. ACK와 대기는 별도로 표시하므로 늦은 ACK가 만료된 대기를 다시 쓰지 않습니다. 마지막으로 저장된 대기는 전체 대기 이력이 아닙니다. ACK 지연 여부는 첫 대기를 기준으로 하며 마지막으로 저장된 대기와는 다를 수 있습니다. 만료되거나 격리된 기록의 수신 확인·주입 상세는 확인 불가로 표시하며, 대기 계속 조치가 지원되지 않는 대기 중 ACK는 추가 대기가 가능하다는 뜻이 아닙니다. JSON 필드 구조와 종료 코드의 의미는 유지합니다. 조회 성공은 0, 실패는 1이며, 조회 성공은 수신의 증거가 아닙니다.

상태 조회는 전송·깨우기, 기록 초기화·복구, 수신 확인 권한 발급, 대기 변경을 수행하지 않습니다. 읽기 전용 기록 경로에서는 변경을 저장하지 않지만, 메모리에서 보존 기간을 적용한 결과 상세 정보가 없는 보존 표식(tombstone)이 표시될 수 있습니다. 복원 후 명시적 격리는 제출 상태를 unknown으로 바꾸고 종료된 대기를 디스크에 보존합니다. 화면은 유효한 공개 결과를 구성할 수 있을 때만 마지막 대기를 보여줍니다. 알려진 수명주기 한계로, 격리 시 ACK 상세가 지워지면 보존된 satisfied 대기는 기존 공개 검증 조건을 충족하지 못해 상태 조회가 invalid_handoff(종료 코드 1)로 거부됩니다. 기록을 복구하거나 다시 쓰지는 않으며, 이는 #181의 남은 수명주기 검증 항목입니다. 기존 상태 조회 로직은 다음 조치를 판단할 시계 근거를 얻기 위해 실행 중인 수집기에 질의할 수 있지만 수집기를 시작하지는 않습니다. 이 화면은 대화 기록이나 메시지 본문을 읽거나 원본 권한 토큰을 노출하지 않습니다.

수집기의 시계 조회도 읽기 전용입니다. 이전 수집기는 이 조회를 거부할 수 있어 가능한 다음 조치에 `keep_waiting`이 없을 수 있습니다. 이때 상태 조회는 기록을 쓰는 질의로 전환하거나 수집기를 재시작하지 않습니다. 기록 스냅샷과 선택적 수집기 시계 관측은 별도이며, 원자적으로 함께 관측한 증거가 아닙니다. 대기가 history_unavailable로 실패한 뒤 수집기 시계를 다시 확인할 수 있게 된 경우, 이제 상태 조회는 확인된 제출과 실패한 대기를 보존하면서 keep_waiting을 안내하지 않습니다. 다른 대기 생성 의미는 바꾸지 않습니다. 보존 표식의 최신 대기 상세는 만료된 기록으로 인해 확인 불가로 표시하며, 대기를 요청하지 않았다는 증거로 해석하지 않습니다.

상태 조회는 로컬 단일 조회를 유지합니다. v1.3 후보에는 아래의 시간 제한 로컬 감시가 추가되며, Windows handoff와 Codex ACK는 여전히 미지원입니다. [#296](https://github.com/abruption/session-peer/issues/296)은 검토·병합 전까지 열어두며 이 후보는 배포된 릴리스가 아닙니다.

## 요청 한 건을 정해진 시간 동안 감시

```sh
session-peer handoff watch --correlation-id PREPARED_UUID --watch-timeout 30 --interval-ms 1000 --json
```

감시는 기존 로컬 소유자의 POSIX 기록만 반복 조회합니다. 시간 제한은 ASCII 정수 1..60초(기본 30), 간격은 ASCII 정수 1000..5000밀리초(기본 1000)입니다. 최대 61번 조회하고 예산 안에 유효한 공개 결과를 구성할 수 있을 때만 최초 스냅샷을 출력하며 이후 공개 메타데이터나 historyPhase가 바뀔 때만 출력합니다. 스냅샷을 하나도 출력하지 못할 수 있으므로 모든 이벤트를 빠짐없이 전달하는 스트림은 아닙니다. 확인된 제출, ACK 근거, 첫 대기를 기준으로 한 ACK 지연, 최신 저장 대기는 상태 화면과 같은 별도의 의미를 유지합니다. 로컬 UTC 관측 시각은 ACK 도착 시각이나 순서의 증거가 아닙니다. historyPhase는 prepared, attempted, terminal, tombstone 또는 quarantined이며 attempted는 영속적인 시도 방지 기록을 뜻하고 실행 중이라는 의미는 아닙니다.

JSON 출력은 watch 전용 필드를 포함한 공통 schemaVersion 1 봉투의 NDJSON이며 operation은 watch, event는 snapshot 또는 end입니다. 스냅샷은 바뀌지 않은 공개 handoff 객체를 포함하며 기존 status JSON은 유지합니다. 기한 종료는 0으로 반환하고 감시 종료만 뜻하며 ACK 도착이나 대기 성공을 의미하지 않습니다. SIGINT는 130, 기록·출력 실패는 1입니다. 기록 부재·손상이나 ledgerEpoch 변경 시 handoff나 epoch를 만들지 않고 감시를 종료합니다. 격리된 satisfied 대기의 기존 거부는 위에 설명한 #181 수명주기 조건으로 유지합니다.

출력 프레임은 각각 16 KiB, 전체는 256 KiB이며 종료 프레임용 2 KiB를 남깁니다. 실제 파일 디스크립터 표준 출력은 전용 격리 Python 출력 보조 프로세스 하나를 사용하며, 이 프로세스는 크기가 제한된 직렬화된 공개 바이트만 받아 공유 디스크립터 플래그를 바꾸거나 기록·네이티브 데이터를 읽지 않습니다. 부모는 보조 프로세스 IPC까지 원래 총 기한으로 제한하고 새 기록 읽기·검증 단계 전에도 기한을 확인합니다. 총 시간 안에서 최종 출력·정리에 100 ms를 남기므로 조회는 더 일찍 끝날 수 있습니다. 시간 초과·SIGINT·오류 시 부모는 자신이 시작한 보조 프로세스를 종료하고 회수합니다. 중단할 수 없는 OS 작업 때문에 엄격한 실시간 보장은 아닙니다. 쓰기가 부분적이거나 완료 응답이 없으면 종료를 포함한 후속 프레임을 보내지 않습니다. 소비자는 잘린 마지막 NDJSON 줄을 거부해야 합니다. 보조 프로세스의 완료 응답은 OS 쓰기 완료만 뜻하며 수신자의 소비를 증명하지 않습니다. 감시는 네이티브 본문·대화 기록을 읽거나 권한이나 페이로드·권한 다이제스트를 노출하지 않으며 공개 targetGeneration의 기존 계약은 유지합니다. 의도·대기·수신 확인 생성, 제출, 깨우기, 초기화, 복구나 기록 쓰기를 수행하지 않습니다. 실행 중인 로컬 수집기의 기존 읽기 전용 시계 조회만 사용할 수 있으며 수집기나 네이티브 메시지 프로세스를 시작하지 않습니다. 호스트·기기 라우팅과 Windows 감시는 지원하지 않으며 Codex ACK 지원도 추가하지 않습니다. 읽기 전용 기록은 불변 스냅샷 바이트를 읽은 뒤 파싱·검증 전에 공유 잠금을 해제합니다. 중단 시 최종 출력·정리는 남은 총예산 안에서 최대 100 ms로 제한합니다. 전체 성공에는 완전한 성공 종료 프레임과 종료 코드 0이 모두 필요합니다. 해당 프레임 뒤에도 정리가 실패할 수 있습니다. 0이 아닌 종료는 전체 실패이며 ACK를 상향 해석하거나 독립적으로 유효한 제출 사실을 버리거나 재시도해도 된다는 뜻은 아닙니다.

## 증거·개인정보·시간 제한

수신함 쓰기의 완료는 제출이며, 실제 소비나 대화 차례의 완료가 아닙니다. 인증된 연관 수신 확인 또는 시간 관계를 증명할 수 있는 별도의 명시적 운영자 확인만 acknowledged를 만듭니다. 쓰기·응답 정리 중 빠르게 도착한 확인은 크기가 제한된 미분류 증거로 보관합니다. 실제 제출과 원래 시계의 순서를 확인한 뒤 분류하며, 확인을 새로 만들거나 시각을 소급하지 않습니다. 확정된 확인은 수집기 재시작 후에도 유지하지만 사용하지 않은 권한은 보수적으로 만료합니다. 만료 후 중복 확인도 원래 토큰 해시 증명이 필요합니다. 수동 확인은 기존 대기 이력을 바꾸지 않습니다.

Python Claude의 기존 선택 필드는 없는 상태를 유지하며 false/null로 채우지 않습니다. 대기가 실패해도 확인된 제출 사실을 보존합니다. 진행 중 대기를 중단하면 stopped를 기록하고 완전한 구조화 결과와 종료 코드 130을 반환합니다. 이후 상태 조회는 종료 코드 0으로 성공할 수 있습니다. 상태 조회·대기·수신 확인·수동 확인은 실제 메시지를 전송하지 않습니다. 기록이 없거나 손상됐거나 ID를 모르면 가짜 epoch 없이 별도의 handoffQuery 오류를 반환합니다. 자동 재전송·대체 경로 전송은 금지합니다.

기기별 총 시간은 준비 전부터 시작합니다. 기본값은 30초이며 ASCII 정수 1..60만 허용합니다. 총 시간 안에서 정확히 5초를 정리에 남겨두므로 관찰·전송은 총 시간에서 5초를 뺀 시점까지입니다. 진단용 마감 시각도 이 경계를 나타냅니다. 5초 이하이면 전송 전에 거부합니다. Python에서 파일시스템·신원 확인·fsync를 강제 취소할 수 없으므로 모든 환경의 엄격한 실시간 지연 보장은 아닙니다.

원본 토큰은 승인된 실제 메시지 입력과 비공개 IPC·표준 입력에만 나타납니다. 발신자·수집기의 일반 출력, 명령 인자, URI, 환경 변수와 자체 기록에는 넣지 않으며 해시만 저장합니다. 수신자의 큐·대화 이력에는 토큰이 남을 수 있고 같은 사용자 권한의 다른 프로세스가 읽을 수도 있습니다. token_possession은 독립적인 모델 신원 인증이 아닙니다. 수신자 대화 기록을 읽지 않습니다.

## 저장 방식과 남은 조건

2026-10-09 시계 조사: [CPython 3.9.25의 Darwin 구현](https://github.com/python/cpython/blob/0bbaf5de9744ae1acea3e2c9ad2257d1cc68e847/Python/pytime.c#L823)은 프로세스마다 다른 시작 틱을 뺍니다. 런타임은 Darwin의 발신자·기록·수집기에 타입을 확인한 mach_absolute_time/mach_timebase_info 나노초를 공통 적용하고, 다른 플랫폼에서는 네이티브 단조 시계 나노초를 사용합니다. 수신함 처리기에는 저장된 시각이 아니라 해당 처리기의 시계로 변환한 남은 시간만 전달합니다. 시계 증명이 없거나 잘못되면 거부하며, 이전 후보의 다른 시계 기록을 조용히 재해석하지 않습니다. 실제 부모·자식 프로세스의 값을 대조하고, macOS Python 3.9 검증은 CI에서 별도로 확인합니다.

POSIX 개인 경로는 ~/.local/share/session-peer/handoff입니다. 원자적 저장·fsync와 고정 잠금 파일로 실제 전송 전에 첫 시도 권한을 소모합니다. 그 뒤 중단되면 실제 쓰기가 시작되지 않았더라도 unknown이며 재전송하지 않습니다. 향후 수신 확인·대기·제출 정보의 크기를 미리 예약합니다. 10,000개 기록·32 MiB 제한에는 폐기 기록과 예약량도 포함하며, 전송 방지 기록을 자동으로 지우지 않습니다. 한 요청의 대기는 최대 64회입니다.

네이티브 부팅 정보와 단조 시계의 연속성을 증명할 때만 30일 뒤 상세 정보를 대상에 묶인 폐기 기록으로 축약합니다. 증명이 없으면 보수적으로 보존하므로 용량이 더 빨리 찰 수 있으며, 재부팅 후 보존 정책은 추가 검토 대상입니다. 복원된 기록은 재사용 전에 운영자가 HandoffLedger.quarantine_restored()를 명시적으로 실행해 격리해야 합니다. CLI 복원·대조 도구는 아직 남은 조건입니다. 보관·새 초기화는 운영자의 명시적 작업이며 자동 복구하지 않습니다. 표시되지 않은 롤백·복제를 확실히 감지할 수 없습니다. 오래된 수집기 소켓을 자동 삭제하거나 재연결하지 않습니다. 수집기는 최대 24시간 유지하며 토큰 유효 시간은 원래 전송 의도의 영속 저장부터 24시간입니다. 재시작은 사용하지 않은 권한을 폐기합니다. 전체 설계와의 수명주기·만료 정합성을 지원 범위를 확대하기 전에 검토해야 합니다.

시험은 전용 로컬 Unix 수신함, 실제 연결 PID·프로세스 생성 정보, 비공개 수집기·확인 전송 프로세스, 전용 SQLite·가짜 Codex 큐 자식 프로세스, 시간 제한 원시 표준 입력과 엄격한 JSON·동시 시작·중단 방지·지연·중복·만료·SIGINT 사례를 사용합니다. 가짜 큐·버전 메타데이터는 실제 Codex 세션이나 모든 버전의 호환성을 증명하지 않습니다. 실제 Claude 모델의 소비, Codex 관찰기, 원격 초기화나 Windows 정리를 증명하지 않습니다. 남은 수락 조건을 해결할 때까지 #181은 열어두며, 확정된 설계 자료를 런타임 인증으로 간주하지 않습니다.
