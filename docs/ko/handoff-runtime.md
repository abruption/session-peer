# Handoff 런타임 후보

드라이런은 새로 발견한 다른 대상이 아니라 원래 준비한 대상을 검증합니다. Claude는 원래 PID·세대 검사를 유지하고, Codex는 원래 홈·실행 프로세스 정보를 다시 검사하고 대조합니다. 정보가 바뀌면 실제 전송 없이 거부하며, 준비한 대상 기록을 바꾸지 않습니다.

이 문서는 [#181](https://github.com/abruption/session-peer/issues/181)의 미발행 구현 후보를 설명합니다. 공개 Python v1.0.4의 기능이 아닙니다. [확정된 Handoff v1 설계](contracts/handoff-v1.md)와 합성 검증 자료는 변경하지 않았으며, 모든 설계 수락 조건을 완료한 것은 아닙니다.

## 후보가 지원하는 경로

같은 POSIX 기기의 Claude 수신함에 전송할 때, 사용자가 명시적으로 초기화한 개인 기록과 별도의 비공개 수신 확인 수집기를 사용할 수 있습니다. 연결된 수신함의 PID, 원래 프로세스 생성 정보와 등록된 연결 경로가 선택한 세대와 일치해야 합니다. 같은 POSIX 기기의 Codex는 연관 ID가 있는 큐 제출을 지원하되 확인 권한을 발급하지 않고 대상 세대는 null로 유지합니다. 전달·수신 확인을 요구하는 대기는 큐 호출 전에 거부하며, 최선형 확인·관찰 요청은 unsupported와 실제 제출 사실을 함께 반환합니다. 모델이나 세션을 시작하지 않습니다. 단일 POSIX SSH 대상으로는 아래 설명과 같이 소스를 전달해 Claude·Codex에 연관 ID 전용 제출을 수행합니다. 본문을 읽지 않는 Codex 관찰, Windows의 시간 제한 파이프, 페어링 기기와 SSH 수신 확인 준비 경로는 아직 지원하지 않습니다. 기존 일반 로컬·SSH 전송과 Codex wake 버전 제한은 유지합니다.

```sh
session-peer handoff init --json
session-peer handoff prepare --to worker --message-file ./private-message.txt --json
session-peer send --to worker --message-file ./private-message.txt --correlation-id PREPARED_UUID --request-ack --wait-for acknowledged --wait-timeout 30 --json
session-peer handoff status --correlation-id PREPARED_UUID --json
session-peer handoff wait --correlation-id PREPARED_UUID --wait-for acknowledged --wait-timeout 30 --json
session-peer ack --receipt - --json
session-peer handoff confirm --receipt - --json
```

메시지 파일은 소유자만 접근할 수 있는 일반 UTF-8 파일이어야 합니다. 예시 문자열 대신 prepare가 반환한 ID를 사용합니다. 수신 확인·수동 확인 JSON은 비공개 표준 입력으로만 전달합니다. 수신자는 자신의 일반 권한 절차에 따라 확인을 보낼지 결정합니다. 위임된 확인 권한은 다른 도구 실행, 메시지 전송, 모델 시작이나 대화 기록 열람의 승인이 아닙니다. 자동 응답을 추정하지 않습니다.

핸드오프 전송 후보는 이름 있는 옵션·위치 인자 메시지, 비공개 메시지 파일 또는 시간 제한이 있는 POSIX 원시 표준 입력을 받습니다. 표준 입력은 원래 전송 마감 하나를 사용하고 UTF-8을 엄격하게 검증하며, 원시 400만 바이트·100만 코드포인트로 제한합니다. 끝나지 않는 파이프나 SIGINT는 전송 기록 생성 전에 거부하며 가짜 epoch·제출 결과를 만들지 않습니다. 수신·수동 확인 표준 입력은 별도의 크기·시간 제한 API입니다. 선택적 다중 호스트 전송은 남은 구현 조건입니다. 기존 일반 전송의 표준 입력과 다중 호스트 동작은 유지합니다. 실제 전송에는 공통 외부 메시지 경계를 적용해 본문의 모든 줄을 인용하며, 최종 문자 수 제한에는 이 경계와 확인 권한도 포함합니다.

Codex 준비는 정규화한 스레드·저장 경로와 크기가 제한된 원래 저장 경로·쓰기 프로세스 판단을 비공개로 기록합니다. 준비한 ID를 재사용할 때 판단이 바뀌면 대상에 다시 연결하지 않고 거부합니다. 이는 원자적인 프로세스 세대나 소비 증명이 아닙니다. 기존 활성 쓰기 프로세스·명시적 비활성 경로 선택 규칙을 유지하고, 단 한 번의 큐 호출 직전에 원래 판단을 다시 확인합니다. 버전 조회와 큐는 #268의 공통 저장 경로 검사·환경 정규화를 사용하지만 네이티브 설정 계층·데몬에 대한 보장은 해당 이슈의 미해결 조사 범위입니다. 전용 POSIX 자식 프로세스의 원시 출력·진단 크기를 제한하고 원래 마감·정리 예산을 사용합니다. 완전한 대상 일치 큐 응답은 시간 초과·비정상 종료 뒤에도 queueId·제출 사실을 유지할 수 있습니다. 응답 부재·다른 대상·불완전한 응답·잘못된 UTF-8·한도 초과 출력은 종료 코드가 0이어도 미확정이며 재전송하지 않습니다. stderr 진단은 제출 증거가 아니고 app-server·본문·대화 기록 API를 호출하지 않습니다.

확인 권한을 발급하기 전에 정확한 보호된 스크립트·인터프리터와 그 스크립트의 ACK 명령을 검사합니다. 비공개 전송 입력에는 검증되지 않은 PATH의 session-peer가 아니라 해당 격리 Python 확인 처리기와 기록 경로를 명시하며, 원본 권한 토큰은 표준 입력에만 넣습니다. 수신·수동 확인 입력은 EOF까지 총 5초와 4096바이트로 제한합니다. 실제 제출 뒤 저장이 실패하면 독립적으로 확인한 대상·문자 수·dry-run 사실은 유지하고, 증명할 수 없는 handoff·ACK는 생략하고 재시도를 금지합니다. 명시적 대기가 없다면 확인된 제출은 성공·종료 코드 0과 고정된 기록 진단을 유지합니다. 증명할 수 없는 명시적 대기는 종료 코드 1/130으로 실패하되 대기 결과를 만들지 않습니다.

Codex의 연관 ID 전용 전송에는 진행 중인 명시적 대기가 없습니다. 유효하고 완전한 큐 응답 뒤 SIGINT가 오면 성공·종료 코드 0과 wait not_requested를 유지하며, 불완전한 증거는 미확정·종료 코드 130입니다. 버전 사전 조회 중 중단하면 큐 호출 없이 거부·종료 코드 130을 반환합니다. stderr 진단 한도 초과는 stdout 한도 초과와 구분하므로 이미 받은 유효한 stdout 응답을 지우지 않습니다. 프로토콜 stdout이 한도를 넘으면 항상 미확정입니다. 실패한 제출의 기록은 고정된 오류 사유만 허용하며, 손상된 성공·비밀 필드는 조회 결과에 복사하지 않고 ledger_corrupt로 거부합니다. 잘못된 공개 연관 ID는 메시지 입력 전에 사용법 오류·종료 코드 2를 반환합니다. 비공개 수신 확인 검증은 별도 작업 실패입니다.

## 소스 전달 방식의 SSH 연관 ID 전용 경로

송신 측은 메타데이터, 전송 없는 대상 확인, 영속적인 제출 의도 기록, 단 한 번의 실제 제출과 정리에 대상별 원래 예산을 사용합니다. 보호된 메타데이터 자식 프로세스는 탐지 시간을 새로 부여하지 않고 From·Reply와 구조화된 SSH 자기 주소의 로컬 변환을 유지합니다. 이미 시도한 의도는 새 조회 전에 거부합니다. 원격 전달·수신 확인이 필수인 대기는 SSH 제출 전에 거부하고, 최선형 요청은 unsupported를 반환하며 권한이나 원격 기록·수집기를 만들지 않습니다. 실제 제출은 원래 Claude 세대 또는 정규화한 Codex 홈·쓰기 프로세스 정보를 다시 검사합니다. Codex 세대 고정 요청은 지원하지 않으며 조용히 제거하지 않습니다. 읽기 전용 상태·대기는 SSH 제출을 수행하지 않습니다.

예비 확인은 회신 전에 원격 부팅에 연결된 단조 시계 기준점을 기록합니다. 송신 측은 응답을 엄격히 검증한 뒤 원래 시계를 한 번 읽어 남은 두 시간을 계산합니다. 원격 제출은 과거 기준점과 남은 시간을 사용하고 총예산 안에 정확히 5초의 정리 시간을 둡니다. 부팅 변경, 미래·만료된 기준점이나 잘못된 요청은 실제 제출 전에 거부합니다. UTC나 기기별 시계 원점을 비교하지 않습니다. SSH 종료는 원격 제출이나 소비 취소의 증거가 아닙니다. 홈 대응은 신뢰된 원격 처리기가 실제로 expanduser·resolve한 결과이며 전용 심볼릭 링크도 포함합니다. 송신 측에서 독립 검증한 inode, 원자적인 프로세스 세대나 보편적인 저장 경로 보장이 아닙니다.

실제 명령은 설정·소스·SSH 자식 프로세스가 시작되기 전에 제한된 비공개 처리기로 연결되어야 합니다. 숨겨진 옵션은 인증이 아니며, 수신 측은 외부 본문을 줄마다 한 번 인용합니다. 엄격한 네이티브 형식과 요청·대상·홈·상태 검증은 연결 종료, 시간 초과, 진단 한도 초과나 중단 뒤에도 완전한 제출 증거를 유지합니다. 프로토콜 stdout이 넘치면 남은 정상 접두부만으로 성공 처리하지 않습니다. 같은 연결에서 검증된 SSH 신원과 안전한 회신 메타데이터는 네이티브 사실과 구분해 유지합니다. 비공개 증거, 본문, 시계 기준점과 내부 네이티브 상태는 공개 출력에 포함하지 않습니다. 전용 가짜 SSH·소스 전달·SQLite·큐 시험은 이 구현 범위를 검증할 뿐 실제 원격 서버, 모델 소비나 설치된 역방향 SSH 수신 확인 준비의 증거가 아닙니다.

## 증거·개인정보·시간 제한

수신함 쓰기의 완료는 제출이며, 실제 소비나 대화 차례의 완료가 아닙니다. 인증된 연관 수신 확인 또는 시간 관계를 증명할 수 있는 별도의 명시적 운영자 확인만 acknowledged를 만듭니다. 쓰기·응답 정리 중 빠르게 도착한 확인은 크기가 제한된 미분류 증거로 보관합니다. 실제 제출과 원래 시계의 순서를 확인한 뒤 분류하며, 확인을 새로 만들거나 시각을 소급하지 않습니다. 확정된 확인은 수집기 재시작 후에도 유지하지만 사용하지 않은 권한은 보수적으로 만료합니다. 만료 후 중복 확인도 원래 토큰 해시 증명이 필요합니다. 수동 확인은 기존 대기 이력을 바꾸지 않습니다.

Python Claude의 기존 선택 필드는 없는 상태를 유지하며 false/null로 채우지 않습니다. 대기가 실패해도 확인된 제출 사실을 보존합니다. 진행 중 대기를 중단하면 stopped를 기록하고 완전한 구조화 결과와 종료 코드 130을 반환합니다. 이후 상태 조회는 종료 코드 0으로 성공할 수 있습니다. 상태 조회·대기·수신 확인·수동 확인은 실제 메시지를 전송하지 않습니다. 기록이 없거나 손상됐거나 ID를 모르면 가짜 epoch 없이 별도의 handoffQuery 오류를 반환합니다. 자동 재전송·대체 경로 전송은 금지합니다.

기기별 총 시간은 준비 전부터 시작합니다. 기본값은 30초이며 ASCII 정수 1..60만 허용합니다. 총 시간 안에서 정확히 5초를 정리에 남겨두므로 관찰·전송은 총 시간에서 5초를 뺀 시점까지입니다. 진단용 마감 시각도 이 경계를 나타냅니다. 5초 이하이면 전송 전에 거부합니다. Python에서 파일시스템·신원 확인·fsync를 강제 취소할 수 없으므로 모든 환경의 엄격한 실시간 지연 보장은 아닙니다.

원본 토큰은 승인된 실제 메시지 입력과 비공개 IPC·표준 입력에만 나타납니다. 발신자·수집기의 일반 출력, 명령 인자, URI, 환경 변수와 자체 기록에는 넣지 않으며 해시만 저장합니다. 수신자의 큐·대화 이력에는 토큰이 남을 수 있고 같은 사용자 권한의 다른 프로세스가 읽을 수도 있습니다. token_possession은 독립적인 모델 신원 인증이 아닙니다. 수신자 대화 기록을 읽지 않습니다.

## 저장 방식과 남은 조건

2026-10-09 시계 조사: [CPython 3.9.25의 Darwin 구현](https://github.com/python/cpython/blob/0bbaf5de9744ae1acea3e2c9ad2257d1cc68e847/Python/pytime.c#L823)은 프로세스마다 다른 시작 틱을 뺍니다. 후보는 Darwin의 발신자·기록·수집기에 타입을 확인한 mach_absolute_time/mach_timebase_info 나노초를 공통 적용하고, 다른 플랫폼에서는 네이티브 단조 시계 나노초를 사용합니다. 수신함 처리기에는 저장된 시각이 아니라 해당 처리기의 시계로 변환한 남은 시간만 전달합니다. 시계 증명이 없거나 잘못되면 거부하며, 이전 후보의 다른 시계 기록을 조용히 재해석하지 않습니다. 실제 부모·자식 프로세스의 값을 대조하고, macOS Python 3.9 검증은 CI에서 별도로 확인합니다.

POSIX 개인 경로는 ~/.local/share/session-peer/handoff입니다. 원자적 저장·fsync와 고정 잠금 파일로 실제 전송 전에 첫 시도 권한을 소모합니다. 그 뒤 중단되면 실제 쓰기가 시작되지 않았더라도 unknown이며 재전송하지 않습니다. 향후 수신 확인·대기·제출 정보의 크기를 미리 예약합니다. 10,000개 기록·32 MiB 제한에는 폐기 기록과 예약량도 포함하며, 전송 방지 기록을 자동으로 지우지 않습니다. 한 요청의 대기는 최대 64회입니다.
