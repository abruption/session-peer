# ADR: 내부 에이전트 및 실행 트랜스포트 계약

상태: v0.8 이후 리팩터링(#47)을 위해 승인됨. 이는 내부 소스 계약이며, 공개 외부 플러그인 ABI가 아닙니다. 패키지 버전은 별도로 준비된 릴리스 전까지 0.8.0으로 유지됩니다.

## 결정

의존성이 없는 `session_peer.py` 독립형 아티팩트를 유지하고 해당 파일 내에 계약을 정의합니다. SSH는 소스를 대상 측 `python3 -`로 스트리밍하므로, 일반적인 원격 작업에는 여전히 설치된 session-peer 서비스나 패키지가 필요하지 않습니다. 지금 런타임을 임포트 가능한 파일로 분할하려면 번들 빌더, 원격 모듈 설치 또는 제2의 배포 메커니즘이 필요합니다. 에이전트/트랜스포트 경계를 검증하는 데는 어느 것도 필요하지 않습니다.

에이전트는 네이티브 신원, 검색, 검증, 제출, 진단, 에이전트별 명령 옵션 및 표시를 소유합니다. 트랜스포트는 해당 작업이 실행되는 위치를 소유합니다. `LocalTransport`는 등록된 어댑터를 호출합니다. `SshTransport`는 대상을 확인하고 안전하게 인용된 기존의 단일 소스 SSH 프로토콜을 호출합니다. 수신자는 동일한 CLI를 구문 분석하고 로컬 어댑터를 호출합니다. SSH는 에이전트가 아닙니다.

초기 레지스트리에는 Claude에 이어 Codex가 명시적으로 포함됩니다. CLI 선택지, 목록 조회, 전송, doctor, Reply-To 검증 및 MCP 에이전트 정책은 이 레지스트리를 사용합니다. MCP는 여전히 정책을 강제하는 CLI의 하위 프로세스 클라이언트로 남습니다. 등록이 전송/wake 권한을 부여하지는 않습니다. 업데이트 배포는 여전히 에이전트 제출과 구분됩니다.

## 근거 및 호환성

- Claude 검색은 PID/이름/수신함 근거를 생성하고 네이티브 소켓에 게시합니다. 쓰기 완료가 소비의 증거는 아닙니다.
- Codex는 네이티브 큐 및 app-server 인터페이스를 사용합니다. 하나의 UUID가 여러 홈에 존재할 수 있으므로, 신원은 UUID로 축약되지 않고 호스트와 홈을 보존합니다. 다중 홈 인벤토리, 모호성 검사 및 활성 작성기 검증은 Codex 구현 내에 유지됩니다. 호출자 측 기본값은 원격 수신자의 활성 홈에 대한 증거가 아닙니다.
- 네이티브 큐 수락이 실패한 wake보다 앞설 수 있습니다. 큐 ID, 제출 및 wake 상태를 포함한 네이티브 페이로드를 보존하십시오. 절대 자동으로 재시도하지 마십시오.
- Wake는 선택 사항이며 이전에 확인된 런타임 및 수명 주기로 제한됩니다. 대기 및 확인 응답은 두 어댑터 모두에서 지원되지 않습니다.
- 호스트 신원, 발신자 봉투 및 반환 경로 정규화는 에이전트와 무관합니다. 발신자에서 메시지 봉투를 한 번 구성하고 기존 base64 표현을 SSH를 통해 전송합니다.

기존 옵션, 유선 필드, 응답 봉투 schemaVersion, 순서 및 종료 코드는 변경되지 않고 유지됩니다. 추가적인 예외는 `doctor.capabilities.agents`로, 등록된 이름을 불리언 `list`, `send`, `wake`, `wait`, `ack` 지원 여부에 매핑합니다. 이는 현재 자격 증명, 수신함 가용성, 모델 준비 상태 또는 대상 권한이 아니라 구현된 메커니즘을 설명합니다. `doctor.capabilities.replyObservation`은 이전의 의미를 유지합니다.

원격 목록 조회의 부분 실패는 `not_installed` 검색 상태도 수용합니다. 그렇지 않으면 누락된 선택형 Codex 설치로 인해 다른 에이전트의 오류 진단이 삭제될 수 있습니다. `submitted: true`인 실패한 원격 제출 역시 ID를 버리는 대신 네이티브 결과를 유지합니다. Reply-To는 다른 에이전트의 등록된 접두사를 대상으로 삼으면서 한 에이전트를 주장할 수 없습니다.

## 계약 및 신뢰 경계

`ADAPTER_CONTRACT_VERSION = 1`은 JSON 응답 schemaVersion과 무관합니다. 레지스트리는 등록 전에 이름, 정확한 계약 버전, 기능 및 메서드를 검증하며, 중복은 거부됩니다. `SessionIdentity`는 에이전트, 호스트, 식별자 및 선택적 Codex 홈을 기록합니다. `ExecutionContext`는 대상 신원과 구문 분석된 옵션을 제공합니다. 이는 프로세스 로컬 값이며 새로운 유선 프로토콜이 아닙니다. 검색 및 제출은 네이티브 결과 필드가 평탄화되지 않도록 타입이 지정된 딕셔너리 계약을 유지합니다.

`AdapterError`는 기존 CLI 오류에서 파생되며 agent/reason 필드를 추가합니다. 계약 오류는 `invalid_adapter_contract`, `duplicate_agent`, `unknown_agent`, `unsupported_capability` 또는 `invalid_target`을 사용합니다. 잘못된 형식의 검색 및 진단은 `invalid_adapter_result`를 사용합니다. 예기치 않은 작업 예외는 예외 텍스트를 출력하지 않고 `adapter_failed`로 격리됩니다. 네이티브 제출이 이미 발생했을 수 있으므로, 예기치 않은 제출 오류나 잘못된 형식의 제출 결과는 재시도 없이 `outcome_unknown`이 됩니다. 기존의 의도적인 CLI/네이티브 오류와 그 구조화된 세부 정보는 그대로 유지됩니다.

검색은 집계 전에 각 어댑터의 결과를 검증합니다. 한 어댑터의 실패로 인해 다른 어댑터의 성공적인 행이나 진단이 삭제되어서는 안 됩니다. 어떤 어댑터도 트랜스포트가 반환되었다는 이유만으로 소비를 주장할 수 없습니다.

엔트리 포인트 검색, 이름 기반 임포트, 플러그인 디렉터리 검사 또는 메시지 기반 로딩은 없습니다. 메시지, CLI 인자, URI 또는 MCP 정책의 이름으로 인해 코드가 설치되거나 실행될 수 없습니다. 알 수 없는 명시적 에이전트는 실패합니다. 일반 대상 문자열의 등록되지 않은 접두사는 호환성을 위해 리터럴 Claude 이름으로 유지됩니다. `claude:` 접두사 역시 마찬가지로 리터럴 Claude 이름의 일부입니다. Codex 및 새로 등록된 어댑터는 등록된 접두사를 사용합니다.

향후 외부 플러그인은 별도의 설계가 필요합니다: 명시적 운영자 설치 및 허용 목록 등록, 패키지 소유권 및 의존성 격리, 버전 협상, 오류 격리, 프로세스 내 Python 플러그인이 신뢰할 수 있는 코드를 실행한다는 사실에 대한 문서화. 이번 변경에는 샌드박스나 외부 로딩 플래그가 제공되지 않습니다.

## 검증

`tests/adapters/test_adapters.py`는 공통 Claude/Codex/픽스처 계약, 제3 에이전트 CLI 및 Reply-To 라우팅, 기능, 호환되지 않는 등록, 잘못된 형식의 결과, 예외 격리, MCP 정책 및 네이티브 제출 횟수를 검증합니다. 소스 등록된 픽스처는 스트리밍되는 프로그램의 테스트 복사본에만 삽입되며 기존 SSH 직렬화기를 통해 새로운 Python 하위 프로세스에서 실행됩니다. 해당 테스트에는 프로덕션 디스패치 편집, 외부 플러그인 로더, 라이브 모델 계정, SSH 연결 또는 메시지 전달이 필요하지 않습니다.

기존 트랜스포트, 네이티브 소켓, 큐, 다중 홈, 회신, MCP 및 wake 테스트 모음은 호환성 기준선으로 유지됩니다. 패키지 및 독립형 설치 테스트를 통해 단일 파일 및 선택형 extra 배포 경계가 온전하게 유지되는지 확인합니다.
