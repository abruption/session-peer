# #85 Antigravity 어댑터 개발 검증

2026-09-17; 로컬 브랜치 `feat/85-antigravity-adapter`, 격리된 작업 트리 `/tmp/session-peer-85`, #47 `993d04d` 기반. 릴레이 의존성, 릴리스, 원격 푸시 또는 PR 없음. 개발 메타데이터로서 버전은 0.8.0으로 유지되며, 이 기능은 배포된 0.8.0 배포판에 포함되지 않습니다. 이슈: https://github.com/abruption/session-peer/issues/85

## 구현 내용

독립형 소스의 옵트인 등록 세션 어댑터, 로컬/SSH list 및 send, doctor 기능, 정확한 UUID/홈/프로세스 신원 및 세대 검사, 비공개 동일 UID 프레임 소켓, 제한된 요청/수명/네이티브 하위 프로세스, 세대 내 요청 중복 제거/충돌 처리, 시그널 정리 및 만료된 항목 재시작. 발신자 감지에는 고유하게 등록된 조상이 필요합니다. MCP 목록 조회는 세 번째 내장 어댑터가 추가될 때 명시적인 에이전트 허용 목록을 보존합니다.

## 증거

- macOS Python 3.14: 선택적 MCP SDK가 설치된 상태에서 332개 테스트 통과(실제 MCP stdio 테스트 포함). SDK 제외 시: 332개 테스트, 2개 선택적 건너뛰기.
- KR Ubuntu Python 3.12: 17개 어댑터 테스트 통과. 실제 Unix 소켓, 가짜 네이티브 실행 파일, SIGTERM 정리 및 만료된 재시작 픽스처 사용, 모델 호출 없음.
- Wheel/sdist 빌드 및 격리된 가상 환경에 독립적으로 설치됨. CLI 브리지 도움말 및 등록 전용 목록 조회 스모크 테스트 완료. 전역 설치 없음.
- 실제 KR agy 1.2.4 TUI: 사용자가 도구 실행기를 통해 제한된 브리지를 실행함. 소스 스트리밍된 SSH `list`는 작업 공간이 다른 사용자의 디렉터리 아래에 있음에도 불구하고 올바른 ubuntu 홈을 찾음. 두 개의 서로 다른 통합 마커가 각각 하나의 SYSTEM 수신 레코드와 하나의 정확한 MODEL ACK를 생성함. 중복 요청은 억제되었고, 동일한 ID에 본문이 변경된 경우와 이전 세대는 거부됨. Dry-run은 네이티브 전달을 호출하지 않음. 구조화된 `consumptionConfirmed`는 false로 유지된 반면, 독립적인 트랜스크립트 관찰을 통해 이러한 테스트 ACK를 확인함.
- 명시적인 브리지 중지로 소켓과 등록이 제거됨. 이후 SSH list는 등록된 세션 없음을 반환함. 사용자 TUI는 원래 cwd에서 계속 활성 상태로 유지됨. 원격 테스트 소스/테스트가 제거됨. 분할 잠금 경쟁을 방지하기 위해 비공개 UID별 런타임 디렉터리에 하나의 빈 잠금 파일이 의도적으로 유지됨. 활성 브리지/소켓/등록은 남아 있지 않음.

상세하게 정제된 증거는 로컬 `/tmp/session-peer-85-evidence/`에 있습니다: `list.json`, `send.json`, `observation.json`, `cleanup.json`, `linux-tests.log`, `full-tests.log`. 첫 번째 실시간 테스트의 트랜스크립트 마커는 `cleanup.json`에서 두 번째 테스트 마커와 함께 유지되며, `send.json`에는 두 번째 실행 내용이 포함되어 있습니다. 원시 환경, 토큰, 자격 증명 또는 무관한 트랜스크립트는 수집되지 않았습니다.

## 제한 사항 / 다음 단계

이것은 실험적인 명시적 등록 워크플로입니다. CLI 사이드카 자동 시작, 헤드리스 작성기 대체, 무인 등록, 내구성 있는 아웃박스, 자동 ACK/wait/wake, 교차 UID 액세스 또는 정확히 한 번 전달 주장은 없습니다. 네이티브 발신자는 TUI의 agentapi 신원이며 설명적인 From 헤더가 암호화된 발신자 증명은 아닙니다. 새 구현의 실시간 네이티브 테스트는 Linux에서 수행되었으며, macOS에는 프로토콜/수명 주기 픽스처와 이전 네이티브 PoC가 있지만 이 브랜치의 실시간 네이티브 테스트는 아닙니다. Windows 브리지는 지원되지 않으며, Windows CI 및 Python 3.9 실행은 로컬에서 실행되지 않았습니다. SIGKILL은 동기식으로 정리할 수 없으며, 재시작은 독점 잠금을 획득한 후에만 만료된 항목을 제거합니다. PID 폴링은 검증과 agentapi 호출 사이의 모든 프로세스 종료 경쟁 상태를 제거할 수 없습니다.

이전 KR PoC는 7개의 메시지로 바쁜 전달, SSH 연결 해제, 브리지 및 TUI 재시작을 시연했습니다. 해당 결과는 이번 구현에 참고가 되었지만 이 브랜치의 실시간 실행으로 간주되지는 않습니다. 제품 수준의 재연결 내구성, 장시간 실행 작업 및 페어링/릴레이 통합은 별도의 v0.9/RC 작업으로 남아 있습니다.

## 2026-10-13: CLI 1.3.3 수락 시험 (#304)

이 기록은 위의 2026-09-17 개발 브랜치 검증과 별개입니다.
기준은 공개 session-peer 1.1.1, 커밋 b48144bdf2ad1569031562136f5a60e33780020e입니다.
두 기기의 native CLI는 1.3.3이며 전용 TUI는 Gemini 3.8 Flash (Low)를 사용했습니다.
어댑터는 실험 상태를 유지합니다. 이번 시험은 릴리스 발행이나 일반적인 버전 호환,
Windows·sidecar 자동 시작·가용성 보장을 뜻하지 않습니다.

### 확인한 증거

- macOS 27.0.1 arm64 / Python 3.15.0, Ubuntu 24.04.5 arm64 / Python 3.12.3에서
  Antigravity 어댑터 테스트가 각각 23개 통과했습니다. owner와 native 실행을 모의한
  테스트 및 실제 Unix socket·자식 프로세스 fixture는 실제 모델 통합 시험과 다릅니다.
- 설치된 CLI의 인자 파서 시험은 플랫폼마다 7개 통과했습니다. 앞쪽 대시, 구분자,
  여러 줄 한국어 본문 및 수신 대상·제목 보존을 확인했습니다. 빈 HOME, 최소 환경,
  제한된 loopback 모의 서버를 사용해 자격증명이나 성공한 실제 전달을 이용하지 않았습니다.
- 전용 수신 TUI의 일반 터미널 도구에서 제한된 bridge를 등록했습니다.
  macOS 로컬, Linux 로컬, macOS→Linux source-streamed SSH 제출은 native exit zero를
  반환했고, 각 TUI에서 서로 다른 정확한 회신 토큰을 확인했습니다.
- 제한된 합성 응답을 생성하며 TUI가 작업 중 상태를 표시할 때 추가 전송했습니다.
  그 응답 뒤 각각의 회신을 확인했습니다. 특정 날짜의 UI 관찰이며 스케줄링·지연 시간이나
  모든 busy 상태에 대한 보장은 아닙니다.
- macOS dry-run은 native 제출 없이 끝났습니다. 원래 ID·본문을 반복하면 캐시된 중복
  결과를 반환했고, 같은 ID의 다른 본문은 거부했습니다. SSH 경로에서 다른 generation을
  지정한 요청도 native 실행 전에 거부했습니다.
- 두 기기에서 bridge를 명시적으로 중지한 후 등록이 목록에서 사라졌습니다.
  살아 있는 두 TUI에서 재등록하자 generation이 바뀌었으며, 원래 generation에 고정한
  요청은 로컬과 SSH 경로에서 거부했습니다.
  fixture에서는 SIGTERM·SIGINT·SIGHUP 정리, 재시작 후 generation 변경과 동일한
  lock inode 보존도 검사합니다.
- 실제 시험 bridge에 SIGKILL을 보낸 뒤 남은 등록·소켓은 발견 목록에서 제외됐습니다.
  소유 TUI에서 다시 등록하자 기존 lock inode는 유지되고 generation은 바뀌었습니다.
  두 플랫폼에서 실제 owner 종료 후 정리를 확인했으며, native TUI 재시작 후 이전
  generation 요청은 거부되고 새 generation 전송에는 정확한 별도 회신이 관찰됐습니다.
- Mac→Linux와 Linux→Mac 양쪽에서 native TUI의 일반 도구로 실제 CLI 전송을 실행하고
  각 방향의 서로 다른 회신을 확인했습니다. 본문의 회신 주소는 인증이나 전송 권한이 아닙니다.
- 실제 SSH 자식 프로세스의 연결을 끊는 제한된 장애 주입 시험에서 완전한 원격 JSON
  응답은 제출 증거를 유지했고, 12바이트만 전달한 응답은 unknown으로 남았습니다.
  두 경우 모두 수신 TUI에서 회신을 관찰했지만 요청을 재전송하지 않았습니다.
  이는 통제된 연결 단절 시험이며 모든 네트워크 장애의 결과를 보장하지 않습니다.
- MCP SDK 1.30의 로컬 정책 경로에서 허용되지 않은 agent 거부, dry-run,
  실제 send와 TUI 회신을 확인했습니다. 이 결과는 paired Relay나 custom home·generation
  고정 지원을 뜻하지 않습니다.
- 격리된 Python 3.13 환경의 전체 기본 suite는 876개 실행, 37개 건너뛰기로 통과했습니다.
  MCP SDK 추가 후에는 MCP 통합 시험 28개를 포함해 880개 실행, 33개 건너뛰기로 통과했습니다.
  PR head `4087149`의 CI 28개는 모두 성공했습니다. 최종 문서 변경 head의 검증은 별도입니다.
- JSON의 소비 확인 값은 계속 false였습니다. TUI 회신 관찰은 해당 시험 메시지의 별도
  증거이며, 새로운 자동 ACK·대기 기능을 뜻하지 않습니다.

### 실패 기록과 남은 정식 전환 조건

macOS의 첫 shell-background 실행은 필수 조상 프로세스 확인에 실패해 등록을 거부했습니다.
터미널 도구에서 foreground 장기 실행으로 시작하자 등록됐습니다. 셸을 분리한 뒤에도
bridge의 TUI 조상 관계가 유지된다고 가정하지 마세요.
첫 Linux fixture 전송에는 MCP 모듈이 빠져 import 하나가 실패했습니다. 해당 추적 소스를
전송한 후 23개가 모두 통과했습니다. 시험 준비 오류이며 제품 수정의 증거는 아닙니다.

추가 테스트는 실행 시작 실패의 캐시·재시도 금지와 UTF-8 정확히 32 KiB 경계를 확인합니다.
재시작을 넘는 중복 방지나 unknown 결과의 무효과를 입증하지 않으며 자동 재전송은 금지합니다.
첫 지속 시험 A는 사용자의 Tailscale 업데이트로 중단됐으며 제품 결함이나 통과로 기록하지 않습니다.
새 지속 시험 B는 04:23 UTC부터 1,802.819초 동안 진행했습니다. 기기별 발견 31회와
dry-run 31회가 모두 성공했고, 새 전송 4건과 각 TUI의 서로 다른 답변 4건을 확인했습니다.
재전송은 없었습니다. 브리지 RSS는 Mac에서 61,680→61,968 KiB, Linux에서
47,204→47,228 KiB였습니다. 장기 가용성이나 메모리 누수가 없다는 보장은 아닙니다.
두 시험 브리지와 전용 TUI를 종료한 뒤 발견 목록은 비었고 등록·소켓 파일은 제거됐으며
잠금 파일은 유지됐습니다. Linux의 전용 소스 전송 폴더도 정리했습니다.
실제 수명 주기·연결 단절·양방향 경로의 위 증거는 날짜와 검증 환경이 한정된 결과입니다.
Claude·Codex·Antigravity 전체 상호 운용 및 paired Relay 전달은 다시 시험하지 않았으며,
관리형 sidecar·Windows와 함께 별도 기능 범위입니다. 한정된 Mac/Linux 수동 bridge
지원의 필수 선행조건으로 확대하지 않습니다. 실험 상태를 유지하며 정식 전환이나 런타임
동작 변경은 하지 않았습니다.
공식 sidecar 문서는 관리형 시작을 안내하지만, 조상 프로세스에 묶인 현재 bridge와의 호환성은
별도 조사해야 합니다. 전역 sidecar 설정, 인증 복사 및 운영 배포는 하지 않았습니다.
