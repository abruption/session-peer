# v0.9.0 통합 작업 (진행 중)

목표: 실제 에이전트 간 페어링된 직접/종단간 암호화(E2EE) 릴레이 전달을 통합하고, 설치 및 운영을 검증하며, v0.9.0 릴리스 PR을 준비한 후, 병합 후 태그/PyPI를 발행하고 v1.0.0-rc 전에 운영 검증을 수행합니다.

이후 모듈화 또는 릴레이 변경은 [v1 호환성 계약](compatibility-v1.md)을 보존해야 합니다.

신뢰할 수 있는 시작 상태: main 39fedf8은 #86만 포함합니다. #87/#88은 main이 아닌 refactor/47-agent-transports에 병합되었습니다. 통합 브랜치 feat/69-native-relay는 출처와 함께 승인된 해당 변경 사항들을 main으로 체리픽합니다. Main CI 실행 35185418394를 통과했습니다. 아래의 모든 게이트를 통과하기 전까지 이 브랜치는 릴리스가 아닙니다.

설계 결정:
- 핵심 독립형/SSH는 의존성 없이 유지합니다. 선택형 session_peer_relay 패키지 및 [relay] extra(Python 3.11+)는 명시적인 device/relay 명령에만 로드됩니다.
- 네이티브 엔드포인트는 운영자가 정의한 별칭이며, 피어가 제어하는 실행 파일, 홈 또는 임의의 CLI 인자가 될 수 없습니다. 수신자 정책은 페어링된 기기 지문을 기능 및 대상 별칭에 바인딩합니다. 페어링 자체로는 에이전트 접근 권한이 부여되지 않습니다.
- 기존 AgentRegistry 및 LocalTransport를 통해 list/send를 라우팅하며, 네이티브 I/O가 TLS 입장이나 철회를 차단하지 못하도록 제한된 워커 하위 프로세스를 사용합니다.
- 네이티브 효과가 발생하기 전에 제출 의도를 저널링합니다. 대상 바인딩과 메시지를 요청 요약에 포함합니다. 알 수 없는 결과는 절대 자동으로 재전송하지 않습니다.
- 기기별 키, WebSocket 내부의 고정된 TLS1.3, 별도의 릴레이 입장, 명시적 페어링/철회. 운영자는 기존 HTTPS 엣지 뒤에 릴레이를 설치합니다. 시크릿/개인 키 전파나 자동 공용 노출은 없습니다.
- 연구실을 역사적 근거로서 불변으로 유지합니다. 제품 패키지는 자체 회귀 테스트와 명시적인 실제 세션 테스트를 보유합니다. 픽스처 결과를 네이티브 결과로 간주하지 마십시오.

게이트 (아래에 근거가 기록되지 않는 한 보류 중):
1. 통합 기준선 테스트 및 wheel/sdist.
2. 제품 직접/릴레이 테스트: 네이티브 허용 목록, 페어링, 철회, 중복, 하위 프로세스 타임아웃/충돌, 차단된 트랜스포트 폴백, 메타데이터 삭제, 잘못된 형식/대용량 입력, 비공개 권한 및 서비스 재시작.
3. 빌드된 아티팩트로부터의 격리된 설치; Linux 서비스 강화/런북.
4. 독립적인 트랜스크립트/ACK 근거가 있는 직접 및 릴레이 경로를 통한 실제 사용 가능한 에이전트 세션 전달, 파일럿 리소스 중지/정리.
5. Main 통합 PR 통과; 릴리스 PR/버전/체인지로그/게시 감사.
6. 릴리스 병합 검증; 불변 태그, GitHub 게시, PyPI 설치 검사.
7. 실제 운영/소크 및 v1.0.0-rc 전 남은 결함 해결.
