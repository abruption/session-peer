# 컨트롤 워치독 및 릴레이 복구 (RC 후보)

`Upholds=`는 중지된 릴레이를 다시 시작할 수 있지만, systemd가 여전히 활성 상태로 간주하는 멈춘(frozen) 컨트롤 프로세스는 감지할 수 없습니다. 따라서 컨트롤 애플리케이션은 systemd 워치독에 참여합니다. 이는 systemd 외부에서는 선택 사항이며 Python 또는 Node 패키지 의존성을 추가하지 않습니다. 서비스 호스트에 `/usr/bin/systemd-notify`가 필요합니다.

`Type=notify`, `NotifyAccess=all`, `WatchdogSec=30` 및 `WatchdogSignal=SIGKILL`을 사용하십시오. `flock --no-fork --nonblock`으로 Node를 실행하여 Node가 메인 PID가 되고 `WATCHDOG_PID`와 일치하도록 하십시오. 기존의 배타적 작성자 락은 계속 유지됩니다. 다른 워치독 PID나 불완전한 워치독 구성은 조용히 비활성화되는 것이 아니라 시작 오류로 처리됩니다. 실행 파일은 `ProtectHome`에 의해 숨겨진 홈 디렉터리 외부의 루트 소유 Node 런타임이어야 합니다.

루프백 리스너가 시작된 후, 컨트롤은 헬스 체크를 통과할 때만 `READY=1` 및 `WATCHDOG=1`을 전송합니다. 최대 5초마다(또는 구성된 워치독 주기의 3분의 1마다) 동일한 이벤트 루프가 다음을 확인합니다:

- 게시자가 실패하지 않았으며 리스너가 실행 중인지;
- 가장 최근의 성공한 공개 상태가 180초 유효 기간 내에 있으며 미래로 5초를 넘지 않는지;
- 정규 상태 파일이 해당 공개 내용과 여전히 정확히 일치하는지;
- 컨트롤 데이터베이스 리비전이 공개된 리비전과 일치하는지.

HTTP `/healthz` 엔드포인트도 동일한 상태 검사를 사용합니다. 읽기 실패, 누락되거나 변경된 상태, 실패한 게시자 및 비정상(unhealthy) 검사는 하트비트를 전송하지 않습니다. 멈춘 이벤트 루프 역시 하트비트를 전송할 수 없습니다. 이러한 검사가 성공적인 OAuth 요청이나 네이티브 에이전트 전달을 의미하지는 않습니다.

알림은 셸을 사용하지 않는(shell-free) 2초 타임아웃 및 `SIGKILL` 종료 방식의 단일 실행(single-flight) 자식 프로세스를 사용합니다. 해당 환경에는 `NOTIFY_SOCKET`만 전달되며, OAuth 구성, 토큰 및 자격 증명 경로는 상속되지 않습니다. 알리미는 `MAINPID`를 설정하거나 `--no-block`을 사용하지 않습니다. systemd-notify의 확인 응답은 systemd가 알림을 귀속하기 전에 종료되는 것을 방지합니다. `NotifyAccess=all`은 유닛 cgroup 내부의 이 자식이 알림을 보내는 것을 허용하지만, 다른 유닛을 승인하지는 않습니다. 셧다운은 하트비트 스케줄링을 중지하며, 이미 실행 중인 알리미는 동일한 2초 타임아웃에 의해 제한됩니다.

운영자의 조율된 스택은 여전히 컨트롤의 실패를 릴레이 종료(`BindsTo`/순서 지정)로 연결해야 하며, 새로운 준비 상태 확인(`Upholds`/순서 지정) 후에만 릴레이를 다시 시작해야 합니다. 30초 워치독은 유계 장애 감지(bounded failure detection)이며, 즉각적인 상태 감지나 Python 상태 유효성 검사 및 실시간 철회 검사를 대체하지 않습니다. 시작, 재시작 및 속도 제한을 명시적으로 유지하십시오. 마이그레이션 및 재생(replay) 초기화가 자동 복구 의존성이 되어서는 안 됩니다.

공개 적용 전에 정확한 컴파일 후보 및 실제 샌드박스를 사용하여 메인 PID 귀속, 워치독 주기보다 긴 정상 동작, 컨트롤 cgroup SIGSTOP, 지속적인 비정상 상태, SIGKILL, 자동 재시작 후 새로운 준비 상태, 릴레이 충돌, 명시적 스택 중지 및 재시작 제한을 검증하십시오. 모든 키, 작업 영수증, 재생 증거 및 리비전 하이워터마크를 보존하십시오. 재시작하거나 카운터가 따라잡도록 두는 것만으로는 안전한 백업 복구가 수립되지 않습니다.

로컬 단위 테스트는 알림 게이팅, 실패, 유계 동시성(bounded concurrency), 환경 격리 및 상태 헬스 체크를 다룹니다. 이는 실제 systemd 알림 전달이나 SIGSTOP 복구 게이트를 확립하지 않으며, 이를 위해서는 KR 런타임 실험이 필요합니다.
