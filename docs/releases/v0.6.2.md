# session-peer 0.6.2

This release selects the active Codex home when duplicate saved threads have one
clear live writer and makes SSH account selection and connection failures visible
to callers.

## Changes

- Validate every known Codex home containing the target UUID with the exact
  thread-writer lock, a kernel advisory-lock probe, and two stable `lsof` owner
  observations. Exactly one same-user live writer can select the destination;
  competing, incomplete, or changing evidence fails before queueing.
- Revalidate all competing home candidates immediately before invoking
  `codex queue`, and expose the schema-versioned decision and bounded evidence in
  `codexHomeResolution` JSON.
- Generate a local reply command when an automatically detected return route
  points back to the sending machine, avoiding an unnecessary self-SSH login.
- Give an explicit `USER@HOST` precedence for remote delivery. Otherwise resolve
  the effective account through `ssh -G` with the same alias and options used for
  the connection, and report `sshUser` plus its source in JSON.
- Classify SSH authentication, host-key, timeout, and other transport failures.
  Authentication failures point to `USER@HOST` or the alias's SSH `User` setting;
  session-peer does not guess accounts or retry under a different username.
- Preserve SSH failure details when probing a remote standalone version instead
  of reporting every connection failure as an absent installation.

## Compatibility and limits

- Explicit `--codex-home` remains the strongest destination selector and bypasses
  automatic multi-home activity resolution. Discovery stays bounded to the
  selected/default home, configured homes, and supported Orca account homes.
- Automatic live-writer selection requires POSIX advisory locks and `lsof` on the
  destination. Missing tools, permission failures, or conflicting evidence fail
  closed when duplicate saved homes must be resolved.
- The resolved SSH user is configuration evidence, not proof that authentication
  will succeed. Session-peer does not discover credentials or alter SSH config.
- A queued message still does not prove consumption or acknowledgement. Reply
  waiting, remote-route verification, and broader diagnostics remain in the v0.7
  roadmap.

## Upgrade

Use the package manager that owns the installation:

```bash
pipx upgrade session-peer
uv tool upgrade session-peer
python -m pip install --upgrade session-peer
```

Standalone installations can run `session-peer update`. Re-run `install.sh` from
the v0.6.2 checkout when the bundled Claude skill should also be refreshed.

## Validation

- 198 unit/integration tests passed with both explicit `tests/` discovery and
  default unittest discovery.
- CI covers Ubuntu and macOS with Python 3.9/3.13, Windows with Python 3.13,
  package build and isolated installs, standalone install smoke tests, shellcheck,
  and secret scanning.
- Wheel and sdist builds were inspected and installed independently. The CLI,

  frozen legacy `cc_peer.py`.
- Release preparation did not submit a live Claude or Codex message.
