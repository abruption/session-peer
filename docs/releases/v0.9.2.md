# session-peer v0.9.2 — Windows Claude authentication hotfix

Prepared candidate; not yet published.

This patch is based on v0.9.1 and does not include the 1.0 beta/RC features.
It fixes the authentication envelope sent to native Windows Claude Code named
pipes. The registry's `peerToken` is now mapped to the wire protocol's `token`
field, rather than forwarding the registry JSON and process metadata verbatim.
Malformed key records and missing, empty or non-string tokens are not used.

The bug is present in v0.9.1 and in the initial Windows implementation; it is
not established to be a Claude Code update regression. On Claude Code 2.1.278,
the old envelope closes the pipe without delivering the message. An isolated
test changing only the auth envelope delivered a real message and produced a
receiver response. Exact ACK and final candidate validation are separate gates.

No permission settings or inbound policies are changed. A successful send
still reports a transport write, not proof that the agent consumed or accepted
the message. Existing unknown sends must not be replayed automatically.

The same correction must be carried forward to the 1.0 RC line. This release
does not add the RC's native Windows Codex writer checks or WSL/native Codex
bridge. It also improves SSH diagnostics for missing `python3` and Windows Store
aliases (#151): remote source streaming still requires working Python and a
POSIX-compatible SSH shell. It does not install Python, change SSH shells or
automatically resend messages.
