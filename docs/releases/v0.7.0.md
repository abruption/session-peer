# session-peer 0.7.0

This release adds read-only diagnostics and safe, structured reply routing, and
makes JSON responses and update notices consistent across local and remote
workflows.

## Changes

- Add `session-peer doctor` locally and over SSH. It distinguishes missing or
  incorrect homes, unavailable Claude inboxes, missing Codex executables,
  permission failures, unsupported Codex state schemas, and unknown inspection
  results without connecting to an inbox or writing a queue.
- Add opt-in `doctor --check-return-route`. The destination tests a fixed,
  non-interactive `ssh ... true` route back to the origin with password prompts,
  host-key enrollment, and key updates disabled. Forward SSH success is never
  treated as proof of reverse access.
- Add versioned `session-peer://v1/reply` addresses for Claude and Codex over
  local or SSH transport. The parser validates all fields, rejects conflicting
  CLI routing and unsafe input, and never evaluates the address as shell syntax.
  Same-user addresses for the current machine normalize to local delivery.
- Keep the existing human-readable `Reply:` command for compatibility. Send
  JSON now exposes the advertised `replyRoute` and structured-address
  `addressResolution`.
- Standardize every JSON result on schema version 1 with `schemaVersion`, `ok`,
  `host`, and `command`. A local or one-host command returns one object; repeated
  `--host` returns an ordered array with independent success or failure per host.
- Add a private 24-hour update cache and non-blocking background refresh. When a
  fresh GitHub release record proves the invoking client is behind, JSON adds
  `clientUpdate` and human output prints the matching upgrade command. Offline,
  stale, current, and opted-out states do not delay or change the requested
  command.

## Reply observation decision

There is no general `--wait` in this release. Claude's supported idle notice is
limited to a main Claude conversation observing another local Claude session,
while Codex queue submission has no matching cross-agent acknowledgement
observer. Transcript polling can confuse another request, stale output, or an
echo with a reply. `doctor` therefore reports reply observation as unsupported;
completion workflows should include a correlation token and request an explicit
message to the structured Reply-To address.

## Compatibility and limits

- The common envelope is a documented JSON contract change. Consumers should
  read `ok` on every result and handle an object or array according to the number
  of destinations.
- Messages with a detectable sender and return route gain a `Reply-To:` URI in
  addition to the existing `Reply:` command. `--no-reply-to` suppresses both.
- Doctor checks are evidence, not delivery. Claude inbox presence is
  filesystem-only until a real send, and Codex queued still does not mean
  consumed or acknowledged.
- Reverse-route tests are never automatic. They do not add keys, retry with
  another account, relax host-key policy, or alter SSH configuration.
- Codex home discovery remains bounded to the selected/default home, configured
  homes, and supported Orca account homes. It does not scan arbitrary roots.

## Upgrade

Use the package manager that owns the installation:

```bash
pipx upgrade session-peer
uv tool upgrade session-peer
python -m pip install --upgrade session-peer
```

Standalone installations can run `session-peer update`. Re-run `install.sh` from
the v0.7.0 checkout when the bundled Claude skill should also be refreshed.

## Validation

- 239 unit and integration tests passed with explicit `tests/` discovery and
  default unittest discovery.
- CI covers Ubuntu and macOS with Python 3.9/3.13, Windows with Python 3.13,
  package build and isolated installs, standalone install smoke tests,
  shellcheck, and secret scanning.
- Wheel and sdist contents were inspected and installed independently. The CLI,
  module, and package metadata report v0.7.0, and neither artifact contains the
  frozen legacy `cc_peer.py`.
- A real SSH doctor run found Claude inboxes and bounded default/Orca Codex homes.
  The opt-in reverse probe reported authentication failure independently of the
  successful forward connection. Release preparation did not submit a live
  Claude or Codex message.
