## Candidate scope

- [PR #401](https://github.com/abruption/session-peer/pull/401), merged as `f133153b32f68e39061d9c49d91e5042359e888f`, changes the embedded `install.sh` release verifier invocation to `python3 -I -S -` before release assets are authenticated. `-I` excludes the working directory and ignores `PYTHONPATH`; `-S` disables automatic site initialization, including `sitecustomize` and `usercustomize` startup hooks. Matching installer fixtures and generator markers preserve the canonical verifier contract and existing valid/rejected-release behavior.
- [PR #403](https://github.com/abruption/session-peer/pull/403) moves only the core Ubuntu/Python 3.9 CI cell from `ubuntu-latest` to `ubuntu-24.04`, retaining Python 3.9, all seven core cells and all 49 CI jobs. The matrix helper handles exclusions and checks the exact cells. Other Linux latest, macOS, Windows, package, MCP and Relay coverage remains unchanged. The preceding setup failure is not evidence of a product-code regression.

## Security and compatibility boundaries

The security change protects startup of the embedded installer verifier before asset authentication. It does not isolate every Python invocation, repair existing installations, replace already published immutable assets, or establish exploitation of a deployed installation. The interpreter and installer selected by the operator retain their own trust requirements. Published v1.6.0 assets remain unchanged; ordinary published-package commands do not deliver this unpublished candidate.

Core Python 3.9, optional MCP Python 3.10, Relay Python 3.11 and the existing SDK constraints remain unchanged. No dependency upgrade, new MCP tool, native-agent/SSH/ACK acceptance, caller identity, effective-storage attestation or atomic generation guarantee is added. #367 and separate dependency/research work remain excluded. Package publication does not install globally, restart receivers or MCP servers, deploy Node Control or roll out skills.
