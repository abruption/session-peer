# session-peer 0.8.0

This release lists Claude and Codex together, discovers Codex sessions across
bounded default/Orca/custom homes, and adds optional MCP tools, a Codex plugin,
and explicit bounded Codex wake. Message input and result formatting now have
separate named options.

## Changes

- #76: `list` defaults to both agents. Each session includes `agent`; use
  `--agent claude` or `--agent codex` to filter. Discovery reports independent
  outcomes and preserves successful rows when another source fails.
- #77: install `session-peer[mcp]` for the stdio `list_sessions` and
  `send_message` tools. The Codex plugin and marketplace files are in the
  repository. Default MCP policy permits local listing only; sending and SSH
  destinations require explicit capabilities and client authorization.
- #78: opt-in `send --wake` resumes an inactive Codex thread through native
  app-server without adding a second prompt. Separate wake results preserve
  queue submission details even when activation fails.
- #80: Codex listing aggregates the default home, `CODEX_HOME`, bounded macOS
  Orca account homes, and `SESSION_PEER_CODEX_HOMES`. Rows carry canonical
  `codexHome` and `stateDb`; identical UUIDs in distinct homes remain distinct.
  Explicit `--codex-home` restricts listing to that home.
- #82: `send --message TEXT` / `-m TEXT` explicitly selects message input;
  `--output-format text|json` selects result formatting. Positional messages,
  stdin, `--b64`, and `--json` remain compatible. Conflicting input sources or
  output selectors are rejected before transmission.

## Compatibility and limits

- Consumers of unfiltered `list` must use each row's `agent`. In multi-home
  results use the row's `codexHome`; the top-level scalar is omitted when more
  than one candidate home is involved. An automatically absent Codex install
  yields empty `not_installed`; missing explicitly configured homes are errors.
- The standalone CLI remains dependency-free on Python 3.9+. The optional MCP
  integration requires Python 3.10+ and the MCP extra.
- Wake supports macOS/Linux with Codex CLI **0.154.0** only. Other versions fail
  closed for wake; ordinary queue-only sends retain existing behavior. Wake can
  incur model usage and modify the target session's project under its existing
  policy. It is bounded to 1–60 seconds, not a persistent worker; timeout can
  interrupt partial work. See [wake details](../wake.md).
- Queue acceptance and wake completion do not confirm receipt of a particular
  message. `consumptionConfirmed` remains false; never automatically resend a
  submitted message after a wake or SSH failure.
- Home discovery is bounded and read-only. Listing neither wakes sessions nor
  unlocks writers, and this release does not introduce a relay transport.

## Upgrade

Use the installation's package manager (`pipx upgrade session-peer`,
`uv tool upgrade session-peer`, or `python -m pip install --upgrade session-peer`).
For MCP, install or upgrade the `session-peer[mcp]` extra. Standalone installations
can run `session-peer update`; re-run `install.sh` from the v0.8.0 checkout to
refresh the bundled skill. See [MCP setup](../mcp.md) for plugin configuration.

  Earlier live wake evidence is limited to Codex 0.154.0 on macOS; Linux lifecycle
