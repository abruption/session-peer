# session-peer v1.0.2

This stability-focused maintenance release follows v1.0.1. Local/SSH core commands remain dependency-free on Python 3.9+. Relay and MCP remain opt-in, and the Antigravity bridge remains experimental.

## Changes

- Control keeps health and published state consistent after rejected or failed mutations (#200). Its public-state budget now enforces the reader's 1 MiB UTF-8 limit before committing, without dropping revocation tombstones (#208).
- Control can authenticate client identity supplied by a loopback reverse proxy for rate limiting; arbitrary forwarded headers remain untrusted (#202).
- Recovery keeps unknown native outcomes unresolved instead of treating a completed journal entry as proof of delivery (#201). Approval schema v2 signs `peerGeneration` and preserves key-rotation generations (#203).
- The standalone installer stages downloads and validates the CLI before atomically replacing the runtime, preserving the existing installation on download or validation failure (#204).
- Explicit Codex wake and MCP CLI cleanup reap owned POSIX process groups, including TERM-resistant descendants (#205, #206).
- SSH rejects oversized shell-quoted UTF-8 commands before launching SSH, accounting for encoding and envelope overhead (#207).
- SQLite backup fixtures close their connections explicitly (#209). Relay setup failures provide allowlisted, actionable guidance without automatically installing dependencies, logging in, pairing, or resending (#210).
- The compatibility skill snapshot is synchronized to v0.3.1 (#199), and pinned GitHub Actions are updated. Independently installed skills retain their own update manager.

## Install and upgrade boundaries

Use the existing installation manager; do not silently replace another installation:

```bash
pipx upgrade session-peer
# New Unix / WSL installation with optional Relay and MCP:
pipx install 'session-peer[relay,mcp]==1.0.2'
```

Core requires Python 3.9+, MCP 3.10+, and Relay receiver/server use Unix or WSL with Python 3.11+. Service-managed macOS/Linux receivers still need the Codex executable on their service PATH or an operator-owned `codexBin` binding. Test the target with `--dry-run` before sending.

- Upgrade the device that commits recovery before generating v2 approvals: older releases accept v1 only. Legacy approvals remain usable when the archived key generation is known; recovery never guesses a rotated key's generation. Review existing recovery plans against archived receipts before activation; resuming does not rewrite old plans.
- Authenticated proxy identity requires separate operator configuration of `SESSION_PEER_TRUSTED_PROXY_TOKEN_FILE` and a proxy that overwrites both dedicated headers. The default remains socket-address rate limiting. Installing the package does not change proxy configuration or trust arbitrary CDN headers.
- An already oversized Control database remains unhealthy until capacity is resolved safely; the new guard does not delete historical records. Control deployment is separate from installing the Python CLI.
- Installer replacement is atomic for the runtime file, not a transaction across all files or rollback after a later skill-manager failure. POSIX cleanup excludes processes that escape the owned group and remote SSH processes; Windows MCP cleanup covers the direct child only.

## Validation and known limits

The release preparation gate includes regression tests, documentation/translation checks, generated-source checks, archive inspection, reproducible builds and clean wheel/sdist installations. These are not a new live four-hour campaign or a guarantee of hosted Relay/OAuth availability. Historical RC4 evidence belongs to v1.0.0, not to this maintenance release.

#161 remains open: the root cause and owner of intermittent public-path stalls are unconfirmed. This release does not claim to repair that network path. `posted`, `queued` and `submitted` are submission evidence, not consumption or ACK. Unknown outcomes must never trigger automatic resend. Package publication, fleet installation and production restarts remain separate operations.
