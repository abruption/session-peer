# v1.4.0 release preparation

Prepared on 2026-11-02 against published v1.3.3. At this dated checkpoint, v1.4.0 is an unpublished source candidate. The integrated base is `f290973962c63548f24153eeee12a8e3666fd043`, before version preparation; it is not the final release commit. This preparation authorizes no merge, tag, draft, workflow dispatch, publication or operational rollout.

Core Python 3.9, MCP Python 3.10+ and SDK requirement `mcp>=1.30,<2` are unchanged.

## Changes

- #356 / #361: add MCP `list_destinations` returning only policy-derived metadata, bounded to 64 aliases, 128 UTF-8 bytes per alias and 64 KiB per tool result, excluding the JSON-RPC envelope. This metadata query also works with policy version 1 and the default policy; it does not require policy version 2. It projects all configured policy entries without filtering by list/Send permission.
- #357 / #362: add single-target CLI `--dry-run --explain-json` delivery explanations. Raw SSH facts are captured before legacy output shaping; existing text and JSON output retain their contracts. MCP `preflight_send` requires the separate `preflight` capability in policy version 2; preflight never implicitly grants Send. Wake preflight also needs its separate wake capability, starts no model and reserves no wake budget.
- #358 / #363: add metadata-only diagnostics requiring the `diagnostics` capability in default mode. Active probing additionally requires `diagnostics_probe`, supports Mac/Linux only, and limits execution to 3 agents and 20 seconds excluding cleanup, with each pipe and the result bounded to 64 KiB. Nonblocking readers handle escaped pipe holders; cancellation wins during cleanup.
- Selected doctor agent/home scopes the actual collection; shared skill scanning is skipped. An OK result means collection succeeded, not agent availability, DB attestation or a reverse probe.
- #359 / #364: add policy version 2 route presets with approved names and exact action routes. Complete both checks before any Native invocation: first the route, then its revision; actual send requires an explicit target and revision. One snapshot and its `dp1` fingerprint are neither destination identity nor ACK. Existing list/send JSON remains unchanged; safe query paths do not fall back to repair. Presets remain limited to Mac/Linux local/SSH Claude Code and Codex routes; wake, URI, Antigravity, device, handoff and Windows support is not expanded.
- Release preparation also defensively rejects MCP preflight response-root fields from the ordinary native protocol (`submitted`, `consumptionConfirmed`, `status`, `dryRun`, `queueId`), which the fixed `send.preflight` schema does not contain. No normal production CLI counterexample, misrouting or security incident was observed; this guard adds no capability, protocol, ACK or permission. The internal MCP process helper now honors an explicitly supplied timeout while the default 130-second `CLI_TIMEOUT` behavior remains unchanged; this correction makes no claim of impact on current normal callers or of an outage.
