# session-peer v0.9.0

Optional Antigravity delivery and paired-device relay beta, with the existing
Claude/Codex local and SSH paths preserved.

- Agent adapters and local/SSH transports now share explicit identity, capability,
  execution and structured error contracts (#47).
- Antigravity can receive through an opt-in bridge started inside an existing
  authenticated TUI. Registration binds the home, process generation and thread;
  expiry and request limits constrain each bridge (#85).
- `session-peer[relay]` adds device pairing, pinned inner TLS 1.3 over direct TCP
  or WSS, peer revocation, policy-limited native targets, persistent request
  receipts, and `--device` integration for list/send (#69).
- Relay admission is separate from device pairing and native authorization.
  A Linux DynamicUser deployment example and setup/cleanup runbook are included.
- Paired `--dry-run` resolves the target without submitting a message. Route
  changes retain the pinned peer and receipt journal. Unknown outcomes must be
  reconciled, not automatically resent.
- A compact README is available in English, Korean, Japanese and Simplified
  Chinese, with matching quick starts and optional-feature requirements (#92).
  The full CLI guide is preserved in `docs/cli-reference.md`. Detailed technical
  documentation remains English; CLI output is not localized.
- Public bug/feature templates and private security-reporting guidance are now
  available, with `support@abruption.dev` as an alternative private contact
  (#91). Email is manually reviewed, never automatically published as an issue.

## Installation and compatibility

The core still supports Python 3.9+ without runtime dependencies. The optional
relay requires Unix and Python 3.11+: `pipx install 'session-peer[relay]'`.
Existing package-managed users should upgrade with their package manager.
Standalone `install.sh` does not install the optional relay package.

Antigravity is opt-in. Default listing includes Claude, Codex and any live registered Antigravity bridges. Paired native
access requires an explicit policy on the receiving device; pairing alone grants
no native access. Device-management commands output JSON.

## Validation and limits

A user-approved temporary public Cloudflare/Caddy WSS pilot delivered to an
existing KR Antigravity session, with an independently observed model ACK and
reused receipt on duplicate request. The route, service, bridge and test keys
were removed afterward; the user's TUI remained running. This is bounded live
Antigravity evidence, not live Claude/Codex or long-term stability evidence.

Send results distinguish submitted from consumed. The persisted intent journal
prevents automatic duplicate attempts but does not promise exactly-once effects;
a crash can leave an unknown outcome. The beta has no hosted relay, automatic
NAT traversal, automatic key rotation, journal garbage collection, or paired
wake/Reply-To routing. See `docs/paired-devices.md` for operational limits.

Actual device operation and defect resolution remain required before
v1.0.0-rc. No v1 stability claim is made by this release.
