# session-peer v1.0.4

Preparation status as of 2026-10-07: v1.0.4 is a maintenance candidate after v1.0.3, not yet published or operationally deployed. Publication status must be checked on GitHub/PyPI. The six reviewed fixes below must be present on integrated main before publication. Local/SSH core commands remain dependency-free on Python 3.9+; Relay and MCP remain opt-in, and the Antigravity bridge remains experimental.

## Changes

- MCP accepts valid file-based SSH policies again by validating the canonical host option (#262). SSH destination restrictions, the allowlist and the approved Codex home remain enforced.
- SSH classifies incomplete launched sends as `outcome_unknown` with `retryAllowed: false`, rather than implying success or safe retry; Codex queue timeouts preserve the same uncertainty (#263). Complete versioned outcomes and refusals survive transport failure. Legacy send dictionaries remain compatible on ordinary exits 0/1/2 only with exact boolean `ok` and an absent or matching command; malformed dictionaries and abnormal legacy exits are not completion evidence.
- Paired-device framing aligns the 32 KiB UTF-8 message budget, including the sender envelope, with a 64 KiB escaped application JSON budget and a 256 KiB native-worker JSON budget including operator-owned bindings (#264). Unicode and escaping-heavy inputs are checked before application writes, native effects or send intents. Known oversize requests are refused; later uncertain I/O stays unknown. Route setup refreshes only request expiry before application submission, preserving the original request ID and body without resend.
- An advisory remote-version probe failure no longer discards a successful SSH session list (#265). Sessions, host/discovery metadata and the primary exit status survive; a bounded version-unknown reason replaces raw diagnostics. Primary failures and strict remote-update verification are unchanged.
- Control's lockfile updates source-map-js from 1.2.1 to 1.2.2 for GHSA-68fv-2mgg-jv7q (#266), restoring the runtime dependency audit prerequisite. This is a lockfile-only patch, not a hosted Control deployment or a claim of fleet remediation.
- Claude discovery and doctor share a bounded 1 MiB registry reader with strict UTF-8, JSON-object and field-type validation (#267). It rejects symlinks, nonregular files, identity replacement and oversized growth, closes opened descriptors and preserves healthy rows and permission diagnostics. POSIX uses nonblocking/no-follow open checks; the Python 3.9-compatible Windows fallback does not promise equivalent POSIX flags or a universal filesystem read deadline.
- The compatibility skill snapshot remains 0.3.2, with minimum runtime 0.9.1 and full-coverage runtime 1.0.1. These independent compatibility versions do not replace the published 1.0.3 security recommendation, and a Python upgrade does not update a separately managed skill.

## Install and upgrade boundaries

After authorized publication, use the existing installation manager; these preparation notes do not authorize installation or silently replacing another installation:

```bash
pipx upgrade session-peer
# New Unix / WSL installation with optional Relay and MCP, after publication:
pipx install 'session-peer[relay,mcp]==1.0.4'
```

Core requires Python 3.9+, MCP 3.10+, and Relay receiver/server use Unix or WSL with Python 3.11+. Service-managed receivers need Codex on their service PATH or an operator-owned codexBin binding. A dry run resolves the target without proving a native effect or model ACK. This release does not broaden SSH, pairing or operator-binding permissions. The [v1.0.3 security notes](v1.0.3.md), existing allowlist and pairing-review requirements, and verified immutable standalone assets remain applicable; their published advisory/CVE history is not a new v1.0.4 disclosure or status verification.

## Validation and known limits

The release gate requires successful CI on the exact integrated public main commit, generated-source and four-language documentation checks, reproducible archive builds, clean wheel/sdist installations, optional-extra checks and current Python/Node dependency audits. Local preparation checks do not substitute for the final integrated gate, immutable asset/provenance verification or the required human PyPI environment review. No new live SSH/native messaging, OAuth/Relay health campaign or production restart is claimed.

Historical RC4 evidence belongs to v1.0.0, not v1.0.4: independent ACKs remain 20/21, with the owner's #164 exception preserved. #161 remains open; the external stall root cause is unconfirmed. `posted`, `queued` and `submitted` are submission evidence, not consumption or ACK. Unknown outcomes never authorize automatic resend. Package publication, hosted remediation, fleet installation and production restarts remain separate operations.
