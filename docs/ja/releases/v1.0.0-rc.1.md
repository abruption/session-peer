# session-peer v1.0.0-rc.1

最初の 1.0 リリース候補は、計画された v1 実装を完了し、安定版リリース前の
最終的な互換性およびパッケージングのフィードバックを求めます。

## beta.1 以降の変更

- durable reconciliation、control fencing、明示的な peer 承認、新しい identity を備えた
  fail-closed な鍵紛失・復元デバイス recovery workflow を追加します。
- 保守可能な Python core を所有範囲の明確な機能 segment に分割しながら、依存関係のない
  単一ファイル SSH artifact を決定論的に維持します。
- 1 つの完全な gate、immutable action pin、再現可能な archive、厳密な内容検査、
  provenance、attestation、runtime audit によってリリースを強化します。
- test を subsystem ごとに再編成し、private state と開発専用 tree を除外する厳密な
  wheel および source archive 契約を必須にします。
- 実際の Codex-to-Claude-to-Codex demo を追加し、PyPI summary を更新し、オプション relay の
  cryptography 下限を修正済みの 50.0.1 リリースへ引き上げます。

## リリース候補のインストール

Python package manager は通常 prerelease を選択しません。明示的に選択してください:

```bash
pipx install 'session-peer[relay]==1.0.0rc1'
# or
uv tool install 'session-peer[relay]==1.0.0rc1'
```

ペアリングした両 endpoint で同じ package version を使用してください。core は Python
3.9+ をサポートし、オプションの relay runtime には Unix または WSL と Python 3.11+ が必要です。

- [プロジェクト概要](https://abruption.dev/projects/session-peer/)
- [ペアリングデバイスガイド](https://github.com/abruption/session-peer/blob/v1.0.0-rc.1/docs/paired-devices.md)
- [v1 互換性契約](https://github.com/abruption/session-peer/blob/v1.0.0-rc.1/docs/compatibility-v1.md)
- [セキュリティポリシー](https://github.com/abruption/session-peer/blob/v1.0.0-rc.1/SECURITY.md)

## リリース候補の境界

- 明示的な tester 向けの prerelease です。通常の stable upgrade は最終版 1.0.0 が
  公開されるまで引き続き v0.9.1 を選択します。
- 候補では v1 互換性契約が凍結されます。非互換性の発見は黙って受け入れず、
  stable への昇格を停止します。
- ホスト型 relay の可用性と OAuth provider ポリシーは、package 公開とは別の運用
  service のままです。
- Antigravity は experimental のままであり、receiver とオプション relay runtime は
  Windows 上で native 実行されません。文書化された WSL 境界を使用してください。
- 記録済みの運用 campaign は、中断された 24 時間の結果と明示的な免除を保持します。
  この候補は uninterrupted service を主張しません。

バグは GitHub issue、セキュリティ問題はリポジトリの private advisory channel に報告してください。
報告には token、device key、certificate、session ID、conversation content を含めないでください。
