# v1.1.0 リリース候補

## 状態と前提条件

2026-10-09に準備した未公開の候補です。現在の公開安定版は1.0.4です。この準備草案は、機能ブランチのマージやリリースの存在を証明しません。PR #261と機能PR #283–#290を通常の保護手順でこの準備PRより先にマージし、公開前に正確な統合mainを検証して草案を更新してください。

## 予定される変更

- #242 / #283: Bash/zshとPowerShell 5.1の任意の `sp` シェルエイリアスは、正式な `session-peer` を通じて引数、標準入力、終了コードを保持します。wheel/sdistには手動で有効化するファイルが含まれます。PowerShellの既定エイリアスを含む既存のエイリアス・関数・実行ファイルとの衝突は拒否します。プロファイル/PATH変更、自動有効化、Python/TypeScript選択器はありません。単独ファイルの導入には別途レビューしたファイルが必要です。
- #268 / #284: 継承された `CODEX_SQLITE_HOME` または検査した設定のルート `sqlite_home` がある場合、探索・キュー送信・wakeの前に安全側で停止します。限定された保存先保護であり、移動したDBの対応やCodexの全実効設定の証明ではありません。
- #232 / #285: 外部メッセージ本文を引用し、送信元と返信先の主張を未検証として示します。ペアリング受信側の認証済み識別はデバイス鍵であり、人やモデルではありません。本文の区分は万能なプロンプト注入対策ではありません。追加文も容量制限に含まれ、`chars` は処理後の本文を示します。
- #180 / #286: 任意のClaude `targetGeneration` 探索と `--target-generation` は元のプロセス・接続先を固定し、書き込み前に接続済みの相手を再確認します。古い対象は実行前に拒否します。Codex、Antigravity、ペアリングデバイスの世代保証は未対応で、writer再起動によって未対応状態が対応済みになることはありません。
- #183 / #287: 任意の `--ssh-identity` は接続のホスト鍵証拠を示し、`--require-ssh-host-key` は認証・リモート実行前に実際の接続の鍵を固定します。POSIXの通常のEd25519/RSA/ECDSA鍵に対応し、ホスト証明書とセキュリティ鍵の種類には対応しません。ホスト鍵はエージェント識別・セッション世代・ACKではありません。
- #238 / #288: 協調的なwake深度・送信元識別子の伝播と対象別呼び出し制限が既存の保護を補います。環境変数が削除されると新しい送信元で開始でき、共有MCPの起動環境は呼び出しごとの文脈ではありません。ネイティブwakeは以前に検証したCodex 0.154.0の経路に限定されます。
- #211 / #289: `session-peer setup` はローカル/SSH/Relayの読み取り専用点検と明示的に承認した操作を提供します。既定の点検では鍵やDBを作成せず、管理ツールの案内は自動インストールしません。既存ポリシーを拡張せず、元の登録要求を永続的に保持し、準備確認ではメッセージを送りません。前景受信側の設定はサービス導入ではありません。
- #181 / #290: 実験的な任意機能handoffは、送信側の永続的な再送防止、時間と容量を制限した標準入力/プロセス処理、受領確認専用の状態・待機・ACK操作を追加します。ローカルPOSIX Claudeは検証済みの元の世代の受領経路に対応します。ローカルCodexと単一宛先POSIXソースストリーミングSSHは相関IDによる送信のみ対応し、観察・ACKは未対応です。必須のdelivered/acknowledged待機は未対応経路で実行前に拒否します。リモート受領、Windows、ペアリングhandoff、複数ホストの任意機能、本文を読まないCodex観察、完全な復元検証は別条件として残ります。

## 互換性と安全上の境界

コアはPython 3.9以上、MCPは3.10以上、Unix/WSL Relayは3.11以上が必要です。任意機能を無効にした通常の結果はネイティブの省略可能フィールドを保持します。`posted`、`queued`、`submitted` は消費の証明ではなく、不明な結果は自動再送を許可しません。実験的な待機は宛先ごとに既定30秒、整数1–60秒の総時間と整理用5秒を使用します。状態・受領操作はネイティブメッセージを送信しません。受領権限はトークン保持を示すものでモデル識別ではなく、受信側のネイティブ履歴に委譲された権限が残る場合があります。

本文区分後の全体にはCodex/ペアリング32 KiB、ペアリングアプリケーションJSON 64 KiB（JSONエスケープを含む）、worker 256 KiB、キューレコード1 MiBの制限が適用されます。通常のSSHは90,000文字とコマンド131,071バイトの制限を維持します。完全で有効なネイティブ応答は通信障害後も保持できますが、不完全またはプロトコル上限を超えた出力は不確実です。

同梱スキルは0.3.2で、最低/全機能ランタイム互換性は0.9.1/1.0.1です。別のスキルPR #30は未公開で、新しい案内にはマージ・公開・正確なスナップショット同期が必要です。この候補には含まれません。#180、#181、#268の明示的な未対応検証条件は維持し、この草案で終了しません。

## 検証と公開のゲート

ローカル統合候補の検証は所有するfixtureと隔離した導入を対象とし、新たな実エージェント/SSH/Relay検証ではありません。バージョン変更後、正確な統合mainの新しいCI、単独ファイルの再生成、4言語の文書検査、隔離wheel/sdist導入、手動有効化ファイルの検査、最新の依存関係監査が必要です。過去の20/21 ACK証拠と未解決の#161は変更せず、1.1.0の検証にはなりません。残るプラットフォーム・機能条件を明示してください。

パッケージ公開には本番配備を含みません。タグ、不変アセット、GitHub/PyPI公開、人手のPyPI環境レビュー、フリート導入、Control/Relay配備は既存の承認を必要とする別段階です。この文書は公開、サービス再起動、新しい可用性を証明しません。
