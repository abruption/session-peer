## 検証と残る条件

対象6件のPRはマージ済みですが、PR #315には最終コミットのレビュー・CI、単独ファイル再生成の検査、翻訳ハッシュ、全プラットフォームテスト、隔離wheel/sdistインストールと最新の依存関係監査が必要です。各ブランチの成功は最終準備ツリーの証拠ではありません。別途の承認による準備PRのマージ後、正確なmain CI成功、不変ドラフト資産7個と証明の確認、必須の人手によるpypi環境承認が必要です。この準備はPR #315のマージ、タグ・ドラフト作成、ワークフロー実行、公開、配備の承認ではありません。

リリース準備PRは対象6件のPRをすべてマージした後、最後にマージします。統合mainを反映した準備PRの最終コミットを更新・レビューし、過去の承認をv1.2.0の承認とみなしません。準備ブランチのCIとローカル統合成果物は予行検証の証拠であり、公開用リリース資産ではありません。保護された最終mainのCI成功後、承認済み準備ワークフローでその正確なmainコミットから資産を再ビルド・検証し、公開前に不変資産7個と証明をすべて確認します。公開時は実際の公開証拠を確認してから4言語READMEの安定版・候補案内とリリースノートを更新し、公開完了を先に宣言しません。

Issue #180、#181、#268、#304、#306、#307は未完了のままです。native Codex世代・ACK、完全な保存先検証、一般的な空TUI入力、Antigravity安定版対応、残るnative・プラットフォーム受け入れ条件は提供しません。固定handoff契約とfixtureは変更しません。submitted/queuedは消費やACKではなく、unknownは自動再送を許可しません。

プラグインと別管理スキルのバージョンは独立し変更しません。新しい実SSH、Relay、MCP、OAuth、フリート、nativeエージェントの受け入れ証拠は主張しません。過去のRC4 ACK証拠は20/21のままで、#161は原因未確定の監視項目です。パッケージ公開に本番配備は含まず、Control/Relay配備と各端末の更新には別途の承認・検証が必要です。
