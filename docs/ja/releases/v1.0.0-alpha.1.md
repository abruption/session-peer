# session-peer v1.0.0-alpha.1

最初のオプトイン 1.0 アルファ版では、v0.9.0 の依存関係のないローカルおよび SSH ワークフローを維持しながら、認証されたパブリックリレーパスが追加されます。

## Highlights

- ピン留めされた内部 TLS 1.3 経由でデバイスをペアリングし、直接 TCP またはブラインドパブリック WSS 経由で送信します。リレーはルーティングメタデータを参照できますが、アプリケーションメッセージを復号することはできません。
- 検証済みの GitHub または Google OAuth でサインインし、ブラウザのデバイスコードでネイティブ CLI を認証して、すべてのリレー許可を登録済みデバイスキーにバインドします。
- 新旧キーの証明、永続的な操作レシート、および不明な応答後のリカバリにより、デバイスキーをローテーションします。失効によりアクティブなマネージド接続が切断されます。
- 再起動後も使用済みチケットとパブリックステートリビジョンのハイウォーターマークを永続化します。KR デプロイには、協調ブート、ウォッチドッグリカバリ、暗号化リカバリスナップショットが含まれます。
- Claude、Codex、および Antigravity ネイティブ配信をサポートします。送信、重複抑制、および独立して監視されたエージェント確認応答は、個別の結果状態として維持されます。
- 招待やユーザー数の上限がない、検証済みのパブリックサインアップを提供します。オペレーターはコミットされたIDを排除することなく新規サインアップを停止でき、オペレーター専用の集計メトリクスダッシュボードはユーザーやデバイスの識別子を公開しません。

## Install the alpha

Python パッケージマネージャーは通常、プレリリースを選択しません。明示的にオプトインしてください:

```bash
pipx install 'session-peer[relay]==1.0.0a1'
# or
uv tool install 'session-peer[relay]==1.0.0a1'
```

ペアリングされた両方のエンドポイントで同じパッケージバージョンを使用してください。コアは引き続き Python 3.9+ をサポートします。オプションのリレーランタイムには Unix および Python 3.11+ が必要です。

- [Project overview](https://abruption.dev/projects/session-peer/)
- [Paired-device guide](https://github.com/abruption/session-peer/blob/v1.0.0-alpha.1/docs/paired-devices.md)
- [CLI reference](https://github.com/abruption/session-peer/blob/v1.0.0-alpha.1/docs/cli-reference.md)
- [Security policy](https://github.com/abruption/session-peer/blob/v1.0.0-alpha.1/SECURITY.md)

バージョンがピン留めされたリポジトリリンクは、タグが作成されたときに利用可能になります。

## Compatibility changes

このalphaはversioned reply URI、JSON schema 1 result、device backup manifest、
relay/control protocol stateを追加します。提案されたstabilityとmigration ruleは
[v1互換性契約](../compatibility-v1.md)で管理します。このalphaにdeprecationはなく、
persistent control upgradeはstable v1前に明示migration pathを使用する必要があります。

## Alpha boundaries

- これは明示的なテスター向けのプレリリースです。通常の安定版アップグレードでは引き続き v0.9.0 が選択されます。
- パブリックリレーの可用性と OAuth プロバイダーポリシーは、パッケージのインストールとは別の運用サービスです。
- Google OAuth はプロバイダーのテスト/公開ポリシーによって引き続き制限される場合があります。
- ペアリングと OAuth だけでは、ネイティブエージェントアクセスは決して付与されません。受信側エンドポイントは引き続きローカルポリシーを適用し、ユーザーは実際のエージェント応答を検証します。
- 完了した検証証拠は、独立した Linux/macOS テスト、実際のパブリック WSS ペアリング、リプレイ拒否、ライブ失効、実際のエージェント ACK、ウォッチドッグリカバリ、KR リブート、および隔離されたバックアップ復元をカバーしています。中断されたエージングテストは、24時間合格とは主張されません。
- Windows はローカルおよび SSH サポートを保持します。オプションのレシーバー/リレーランタイムは Unix 専用です。

バグは GitHub issue から報告し、セキュリティ上の問題はリポジトリのプライベートアドバイザリチャネルから報告してください。レポートにトークン、デバイスキー、証明書、セッション ID、または会話内容を含めないでください。
