# session-peer 0.7.0

このリリースでは、読み取り専用の診断と安全で構造化された返信ルーティングが追加され、ローカルおよびリモートのワークフロー全体でJSONレスポンスと更新通知の一貫性が向上しました。

## 変更点

- ローカルおよびSSH経由で `session-peer doctor` を追加。受信箱に接続したりキューに書き込んだりすることなく、存在しないまたは不正なホーム、利用不可能なClaude受信箱、存在しないCodex実行可能ファイル、権限の失敗、サポートされていないCodex状態スキーマ、および不明な検査結果を区別します。
- オプトインの `doctor --check-return-route` を追加。接続先は、パスワードプロンプト、ホストキーの登録、およびキーの更新を無効にした状態で、送信元に戻る固定の非対話型 `ssh ... true` ルートをテストします。順方向のSSH成功が逆方向アクセスの証拠として扱われることは決してありません。
- ローカルまたはSSHトランスポート経由のClaudeおよびCodex向けに、バージョン管理された `session-peer://v1/reply` アドレスを追加。パーサーはすべてのフィールドを検証し、競合するCLIルーティングや安全でない入力を拒否し、アドレスをシェル構文として評価することは決してありません。現在のマシンの同一ユーザー向けのアドレスは、ローカル配信に正規化されます。
- 互換性のため、既存の人間が読める `Reply:` コマンドを維持。送信JSONは、提示された `replyRoute` および構造化アドレスの `addressResolution` を公開するようになりました。
- すべてのJSON結果を、`schemaVersion`、`ok`、`host`、`command` を持つスキーマバージョン1に標準化。ローカルまたは単一ホストのコマンドは1つのオブジェクトを返し、`--host` の繰り返し指定はホストごとの独立した成功または失敗を含む順序付き配列を返します。
- プライベートな24時間更新キャッシュと非ブロッキングのバックグラウンド更新を追加。最新のGitHubリリースレコードによって呼び出し元クライアントが古いことが証明された場合、JSONに `clientUpdate` が追加され、人間向け出力に対応するアップグレードコマンドが表示されます。オフライン、キャッシュ切れ、最新、およびオプトアウトの状態によって、要求されたコマンドが遅延したり変更されたりすることはありません。

## 返信観測の決定

このリリースには一般的な `--wait` はありません。Claudeでサポートされているアイドル通知は、メインのClaude会話が別のローカルClaudeセッションを監視することに限定されており、Codexキューの送信には対応するエージェント間の確認応答オブザーバーがありません。トランスクリプトのポーリングは、別のリクエスト、古い出力、またはエコーを返信と混同する可能性があります。したがって `doctor` は返信の観測をunsupportedとして報告します。完了ワークフローには関連付けトークンを含め、構造化Reply-Toアドレスへの明示的なメッセージを要求する必要があります。

## 互換性と制限

- 共通エンベロープは文書化されたJSON契約の変更です。利用側はすべての結果で `ok` を読み取り、接続先の数に応じてオブジェクトまたは配列を処理する必要があります。
- 検出可能な送信者と返信ルートを持つメッセージには、既存の `Reply:` コマンドに加えて `Reply-To:` URIが付与されます。`--no-reply-to` は両方を抑制します。
- Doctorのチェックは証拠であり、配信ではありません。Claudeの受信箱の存在確認は実際の送信まではファイルシステム上のみであり、Codexのキューへの追加は依然として消費や確認応答を意味しません。
- 逆方向ルートテストが自動で行われることは決してありません。キーの追加、別のアカウントでの再試行、ホストキーポリシーの緩和、またはSSH設定の変更は行いません。
- Codexホームの探索は、選択された/デフォルトのホーム、設定されたホーム、およびサポートされているOrcaアカウントのホームに制限されたままです。任意のルートをスキャンすることはありません。

## アップグレード

インストールを管理しているパッケージマネージャーを使用してください:

```bash
pipx upgrade session-peer
uv tool upgrade session-peer
python -m pip install --upgrade session-peer
```

スタンドアロンインストールでは `session-peer update` を実行できます。バンドルされたClaudeスキルも更新する場合は、v0.7.0のチェックアウトから `install.sh` を再実行してください。

## 検証

- 明示的な `tests/` 探索とデフォルトのunittest探索の両方で、240個の単体テストおよび結合テストに合格しました。
- CIは、Python 3.9/3.13でのUbuntuおよびmacOS、Python 3.13でのWindows、パッケージビルドと分離インストール、スタンドアロンインストールのスモークテスト、shellcheck、およびシークレットスキャンをカバーしています。
- wheelとsdistの内容が検査され、個別にインストールされました。CLI、モジュール、およびパッケージメタデータはv0.7.0を報告し、どちらの成果物にも凍結されたレガシーの `cc_peer.py` は含まれていません。
- 実際のSSH doctorの実行により、Claudeの受信箱と制限されたデフォルト/OrcaのCodexホームが検出されました。オプトインの逆方向プローブは、成功した順方向接続とは無関係に認証の失敗を報告しました。リリース準備において、ライブのClaudeまたはCodexメッセージは送信されませんでした。
