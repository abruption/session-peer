# session-peer 0.6.2

このリリースでは、重複して保存されたスレッドに明確に稼働中のライターが1つ存在する場合にアクティブなCodexホームを選択し、SSHアカウントの選択および接続の失敗を呼び出し元に可視化します。

## 変更点

- 対象のUUIDを含む既知のすべてのCodexホームを、正確なスレッドライターロック、カーネルの勧告ロックプローブ、および2つの安定した `lsof` 所有者観測によって検証します。同一ユーザーの稼働中ライターが正確に1つだけ接続先を選択できます。競合する証拠、不完全な証拠、または変化する証拠がある場合は、キューに追加する前に失敗します。
- `codex queue` を呼び出す直前にすべての競合する候補ホームを再検証し、スキーマバージョン管理された決定と制限された証拠を `codexHomeResolution` JSONで公開します。
- 自動検出された返信ルートが送信元マシンを指している場合にローカルの返信コマンドを生成し、不要な自分自身へのSSHログインを回避します。
- リモート配信において明示的な `USER@HOST` を優先します。それ以外の場合は、接続に使用されるのと同じエイリアスとオプションを使用して `ssh -G` で有効なアカウントを解決し、`sshUser` とそのソースをJSONで報告します。
- SSHの認証、ホストキー、タイムアウト、およびその他のトランスポート障害を分類します。認証の失敗は `USER@HOST` またはエイリアスのSSH `User` 設定を示します。session-peerがアカウントを推測したり、別のユーザー名で再試行したりすることはありません。
- リモートのスタンドアロンバージョンをプローブする際、すべての接続失敗をインストールの不在として報告するのではなく、SSHの失敗の詳細を保持します。

## 互換性と制限

- 明示的な `--codex-home` は依然として最も強力な宛先選択フラグであり、自動マルチホームアクティビティ解決をバイパスします。探索は、選択された/デフォルトのホーム、設定されたホーム、およびサポートされているOrcaアカウントホームに制限されたままです。
- 自動稼働中ライター選択には、接続先でのPOSIX勧告ロックと `lsof` が必要です。重複して保存されたホームを解決する必要がある場合、ツールの欠落、権限の失敗、または競合する証拠があると安全側に倒して失敗します。
- 解決されたSSHユーザーは設定上の証拠であり、認証が成功する証明ではありません。session-peerが認証情報を探索したりSSH設定を変更したりすることはありません。
- キューに入れられたメッセージは依然として消費や確認応答を証明するものではありません。返信待ち、リモート探索検証、およびより広範な診断は引き続きv0.7ロードマップに含まれています。

## アップグレード

インストールを管理しているパッケージマネージャーを使用してください:

```bash
pipx upgrade session-peer
uv tool upgrade session-peer
python -m pip install --upgrade session-peer
```

スタンドアロンインストールでは `session-peer update` を実行できます。同梱のClaudeスキルも更新する場合は、v0.6.2のチェックアウトから `install.sh` を再実行してください。

- 明示的な `tests/` 探索とデフォルトのunittest探索の両方で、198件の単体/統合テストに合格しました。
