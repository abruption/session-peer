# v1.4.0のリリース準備

公開済みv1.3.3を基準に2026-11-02に準備しました。この日付の確認時点では、v1.4.0は未公開のソース候補です。統合基準はバージョン準備前の`f290973962c63548f24153eeee12a8e3666fd043`であり、最終リリースコミットではありません。この準備はマージ、タグ・ドラフト作成、ワークフロー実行、公開や運用環境への配備を承認しません。

コアPython 3.9、MCP Python 3.10+、SDK要件`mcp>=1.30,<2`は変更しません。

## 変更内容

- #356 / #361: ポリシーから導出したメタデータのみを返すMCP `list_destinations`を追加します。別名は最大64件、各別名はUTF-8で128バイト、ツール結果はJSON-RPCの外枠を除き64 KiBに制限します。このメタデータ照会はポリシーバージョン1と既定ポリシーでも動作し、ポリシーバージョン2を要求しません。list/Send権限で絞り込まず、設定されたすべてのポリシー項目を投影します。
- #357 / #362: 単一対象のCLI `--dry-run --explain-json`配信説明を追加します。従来の出力形式に整形する前に生のSSH情報を収集し、既存のテキスト・JSON出力の契約を維持します。MCP `preflight_send`にはポリシーバージョン2の別の`preflight`権限が必要で、preflightが暗黙にSendを許可することはありません。Wake preflightには別のwake権限も必要で、モデルを起動せずwake予算を予約しません。
- #358 / #363: 既定モードで`diagnostics`権限が必要なメタデータ専用の診断を追加します。能動プローブには追加で`diagnostics_probe`が必要で、Mac/Linuxのみ対応します。クリーンアップを除く実行上限はエージェント3件と20秒で、各パイプと結果は64 KiBに制限します。非ブロッキングリーダーがプロセス範囲を抜けたパイプ保持者を扱い、クリーンアップ中もキャンセルを優先します。
- doctorで選択したエージェント・homeが実際の収集範囲を定め、共有スキルの走査は省略します。OK結果は収集の成功を意味し、エージェントの利用可能性、DBの証明や逆方向プローブは意味しません。
- #359 / #364: 承認済みの名前と動作ごとの正確な経路を使うポリシーバージョン2の経路プリセットを追加します。どのNative呼び出しよりも前に両方の検査を完了します。まず経路を確認し、次にリビジョンを確認します。実際の送信には明示的な送信対象とリビジョンが必要です。単一のスナップショットとその`dp1`フィンガープリントは宛先の識別子やACKではありません。既存のlist/send JSONは維持し、安全な照会経路から修復動作には切り替えません。プリセットはMac/Linuxのローカル・SSHのClaude CodeとCodex経路に限定し、wake、URI、Antigravity、device、handoff、Windowsの対応は拡大しません。
- リリース準備では、固定の`send.preflight`スキーマに含まれない通常のネイティブプロトコルの応答ルートフィールド（`submitted`、`consumptionConfirmed`、`status`、`dryRun`、`queueId`）もMCP preflightで防御的に拒否します。通常の本番CLIの反例、誤ったルーティングやセキュリティ事故が観測されたわけではありません。この防御検査は機能・プロトコル・ACK・権限を追加しません。内部MCPプロセスヘルパーは明示的に渡されたタイムアウトを守るようになり、既定の130秒の`CLI_TIMEOUT`動作は維持します。この修正は現在の通常の呼び出し元への影響や障害の発生を主張しません。

## 境界とリリース条件

この拡張は、新たな実環境のNative/SSH、Windows 3.14やfree-threadedの受け入れ、ACK・重複排除・handoffの保証、所有元app-serverの対応やサポート水準の昇格を追加しません。不明なロールや結果の制限は維持します。キューへの投入はACKではなく、不確実性が自動再試行を許可することはありません。

正確な現行コミットをレビューし、現行コミットの検査と最終的な保護されたmain CIの成功を要求し、公開済みv1.3.3のタグ・資産・過去の記録をすべて保全します。公開を先取りしないこの日付付き案内を固定します。別途承認された公開では、`SHA256SUMS`と`release-provenance.json`を含む固定資産7個を正確なタグ・ソースと認証済みattestationに照合し、依存関係監査と新規インストール検査を行い、必須のPyPI環境の人による承認を維持します。非公開のPyPIログイン・接続再確認の省略は、その承認を免除しません。

提供状況の案内を更新する前に実際のGitHub・PyPI公開の根拠を別途記録し、将来の公開を宣言しません。Python公開、グローバルMCP環境の更新、サービス変更、Node Control配備、独立してインストールしたスキルは、それぞれ別途承認が必要な作業です。
