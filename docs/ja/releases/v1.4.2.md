## 範囲

- PR #372はhandoff watchのテストコードにある#370を修正します。パイプの観測に期限を設け、中断時の終了処理区間に入る前に補助プロセスの出力を確認し、フレームの欠落・準備段階の失敗を再現する回帰ケースで、期限内の失敗と補助プロセスの後処理を検証します。CIではPOSIXテストのマトリクスジョブをそれぞれ15分、その中のコアテスト段階を5分に制限し、致命的シグナル発生時のスタック追跡用にfaulthandlerを有効にします。これはテスト・CIの修正であり、製品ランタイムの不具合修正や元のCI停止原因の立証ではありません。
- PR #374は韓国語、日本語、中国語簡体字のREADMEと運用ガイドにある#373を修正します。handoffの受領確認・ACK情報、保存済みのペアリング要求処理結果、過去のControl管理操作結果、SSHホスト鍵の確認記録を区別します。関連する運用用語を修正し、既存の英語の探索・設定説明を明確にするとともに、見出し階層と改行を含むインラインコードの検査を強化します。既存のqueued/submitted、消費、ACKの区別は維持します。
- バージョン値以外のランタイム動作は変えません。固定された[英語版handoff契約](../../contracts/handoff-v1.md)と、その契約の[固定テストデータ](https://github.com/abruption/session-peer/blob/c265861d5251f8bab65229521444168e23bc13a9/tests/fixtures/handoff-v1.json)は変更しません。PR #372で変更したのは別のwatchテスト用補助コードです。新機能、新たなネイティブ・SSH配信、Windows 3.14・free-threaded Python、消費・ACK保証、プラットフォームサポートの検証は主張しません。
