# session-peer v1.0.4

2026-10-07付のメンテナンス版：v1.0.4は以下のレビュー済み修正6件が統合mainに反映されたv1.0.3の後継です。パッケージ公開には本番配備を含みません。公開状態はGitHub/PyPIで確認してください。ローカル/SSHコア命令はPython 3.9+で外部依存なしを維持します。RelayとMCPは任意機能、Antigravityブリッジは実験的です。

## 変更

- MCPは正規のホストオプションを検証し、有効なファイルベースSSHポリシーを再び許可します (#262)。SSH宛先制約、許可リスト、承認済みCodexホームは引き続き適用されます。
- SSHは起動済みだが未完了の送信を`outcome_unknown`、`retryAllowed: false`と分類し、成功や安全な再試行を示唆しません。Codexキューのタイムアウトも同じ不確実性を維持します (#263)。完全な版付き結果や拒否は転送失敗後も保持されます。旧送信辞書は通常終了0/1/2で正確な真偽値`ok`と、不在または一致するcommandがある場合のみ互換です。不正な辞書や異常な旧形式終了は完了証拠ではありません。
- ペア機器のフレーミングは送信者エンベロープを含むUTF-8メッセージ32 KiB、エスケープ済みアプリJSON 64 KiB、運用者所有バインディングを含むネイティブワーカーJSON 256 KiBの予算を整合します (#264)。Unicodeやエスケープの多い入力はアプリ書き込み、ネイティブ効果、送信意図の記録前に検査します。判明した超過要求は拒否し、後の不確かなI/Oはunknownのままです。経路設定後、アプリ送信前に期限のみ更新し、元の要求IDと本文を維持して再送しません。
- 補助的なリモート版プローブの失敗で、成功したSSHセッション一覧を破棄しません (#265)。セッション、ホスト/探索メタデータ、主要終了状態を維持し、生の診断ではなく制限された版不明の理由を表示します。主要失敗と厳格なリモート更新検証は変わりません。
- Controlのロックファイルでsource-map-jsを1.2.1から1.2.2へ更新し、GHSA-68fv-2mgg-jv7qに対応してランタイム依存監査の前提を復旧します (#266)。ロックファイルだけの修正で、ホストControlの配備や機器群への対策適用を主張しません。
- Claude探索とdoctorは厳格なUTF-8、JSONオブジェクト、フィールド型検証を備えた1 MiB上限のレジストリリーダーを共有します (#267)。シンボリックリンク、非通常ファイル、識別子の置換、上限を超す増加を拒否し、開いた記述子を閉じ、正常な行や権限診断を維持します。POSIXはnonblocking/no-followのopen検査を使用します。Python 3.9互換のWindows代替経路は同等のPOSIXフラグや全ファイルシステム読み取りの期限を保証しません。
- 互換スキルのスナップショットは0.3.2、最小ランタイム0.9.1、全機能ランタイム1.0.1を維持します。独立した互換版は公開済み1.0.3のセキュリティ推奨を代替せず、Python更新は別管理のスキルを更新しません。

## 導入・更新の境界

既存の導入管理ツールを使います。パッケージ公開は機器群への導入や別の導入を黙って置き換える権限を与えません。

```bash
pipx upgrade session-peer
# New Unix / WSL installation with optional Relay and MCP:
pipx install 'session-peer[relay,mcp]==1.0.4'
```

コアはPython 3.9+、MCPは3.10+、Relay受信側/サーバーはUnixまたはWSLとPython 3.11+が必要です。サービス管理の受信側はサービスPATHのCodexか運用者所有のcodexBin設定が必要です。dry runは宛先を解決しますが、ネイティブ効果やモデルACKの証明ではありません。SSH、ペアリング、運用者バインディングの権限を拡張しません。[v1.0.3セキュリティノート](v1.0.3.md)、既存の許可リストとペアリングレビュー要件、検証済み不変な単独ファイル資産は引き続き適用されます。公開済み勧告/CVE履歴は新たなv1.0.4開示や状態再検証ではありません。

## 検証と既知の制限

リリースゲートは統合済み公開mainの正確なコミットでのCI成功、生成ソースと4言語文書検査、再現可能なアーカイブビルド、クリーンなwheel/sdist導入、任意extras検査、現在のPython/Node依存監査を要求します。ローカル準備検査は最終統合ゲート、不変資産/来歴検証、必須の人によるPyPI環境レビューを代替しません。新たな実時間SSH/ネイティブ送信、OAuth/Relayヘルス試験、本番再起動は主張しません。

過去のRC4証拠はv1.0.4ではなくv1.0.0のものです。独立ACKは20/21を維持し、所有者の#164例外を保存します。#161は未解決で外部停滞の根本原因は未確認です。`posted`、`queued`、`submitted`は送信証拠で、消費やACKではありません。不明な結果は自動再送を許可しません。パッケージ公開、ホスト対策、機器群導入、本番再起動は別々の作業です。
