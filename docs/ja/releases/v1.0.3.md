# session-peer v1.0.3

v1.0.2に続くセキュリティと安定性のメンテナンスリリースです。ローカル/SSHコアはPython 3.9+で追加依存なしで動作します。RelayとMCPは任意で、Antigravityブリッジは実験段階です。

## セキュリティ修正

リリース準備時点で5件すべての勧告にCVE識別子は割り当てられていません。GHSA識別子を使用して公開を進めます。

- [GHSA-9x52-82cv-4c22](https://github.com/abruption/session-peer/security/advisories/GHSA-9x52-82cv-4c22): OpenSSH実行前にSSH宛先と指定された全オプションを検証し、リモート引数をシェル引用します。
- [GHSA-4rvw-q2vm-v4x3](https://github.com/abruption/session-peer/security/advisories/GHSA-4rvw-q2vm-v4x3): ペアリングは証明書に基づく初期principal、またはローテーション鍵の既存の信頼済みバインディングを要求します。
- [GHSA-6xwm-5p7g-8v8q](https://github.com/abruption/session-peer/security/advisories/GHSA-6xwm-5p7g-8v8q): Relayは無効なパス/接続をセッション発行予算から分離し、送信元別の有限ハンドシェイク制限を追加します。
- [GHSA-2hjv-35jg-gghm](https://github.com/abruption/session-peer/security/advisories/GHSA-2hjv-35jg-gghm): ホストされたControlのデバイスコード発行は所定のクライアントフィールドのみ許可し、保留コード数を制限して期限切れ記録を整理します。
- [GHSA-646x-xjw9-mf6x](https://github.com/abruption/session-peer/security/advisories/GHSA-646x-xjw9-mf6x): ホストされたControlはbearer資格情報のCookie昇格を防ぎ、承認とログインセッション管理にCookie/Origin検査を適用します。

クライアントと自己ホストのRelay/Controlを更新してください。ソース修正はホストされた対策の配備を証明しません。既存のペアリングバインディングは自動監査・削除されないため、運用者が確認して信頼できないものを取り消し、再ペアリングする必要があります。リバースプロキシでは認証された送信元境界とエッジ制限を設定してください。多数の送信元は全体予算を使い切る可能性が残ります。

## 安定性とリリースの変更

- SSHは有効なインバンド結果とタイムアウト前に取得した応答を保持します。不確実な送信はunknownのままで、自動再試行は禁止です (#249)。
- MCPは所有するwakeプロセスに強制終了前の後処理時間を与えます (#250)。
- 受信側は未認証作業の受付を分離し、後処理と終了を制限します (#251)。
- PyPI公開は明示的な環境レビューを要求し、依存監査は製品CIと独立して定期実行します (#252, #253)。
- ネイティブメッセージは先頭のダッシュをそのまま保持し、過大なWindowsコマンドラインを起動前に拒否します (#254)。
- 人向け出力は端末制御文字をエスケープし、構造化JSONのデータは保持します (#255)。
- SSH単独ファイル更新は候補を検証し、置換を直列化して古い版への降格を防ぎ、確定または不確実なコミット受領情報を保持します (#256)。
- 単独ファイルのインストール/更新は不変リリース資産と来歴を認証し、リリースのインストール検査は隔離された導入済みパッケージを確認します (#257)。
- Controlログインは生成から24時間で絶対失効し、ブラウザーのセッション一覧/取り消しは独立したレート予算を使用します (#258)。

## インストールと更新の境界

既存のインストール管理ツールを使用してください。pipxの例:

```bash
pipx upgrade session-peer
# New Unix / WSL installation with optional Relay and MCP:
pipx install 'session-peer[relay,mcp]==1.0.3'
```

コアはPython 3.9+、MCPは3.10+、Relay受信側/サーバーはUnixまたはWSLとPython 3.11+が必要です。サービス管理の受信側はサービスPATHのCodexか運用者所有のcodexBin設定が必要です。送信前に--dry-runで確認してください。

SSHオプションの互換性は意図的に狭くなります。文書化された許可リストの接続オプションのみ受け付けます。ProxyCommand、LocalCommand、-Fなどローカルコマンド実行や別設定ファイルを選択するものは拒否します。信頼されたユーザー所有のOpenSSH設定は運用者の境界として残ります。検証済み単独ファイルの導入には認証済みGitHub CLIのattestation検証が必要で、古い未署名版や開発mainへの自動フォールバックはありません。

更新時、既存のスライド式Controlセッションは元の生成時刻から24時間に制限され、すぐ再ログインが必要な場合があります。デバイス取り消しとアカウントのログインセッション取り消しは別です。紛失したデバイスや資格情報は両方を取り消し、対象ログインを特定できなければ他の全セッションを取り消してください。

## 検証と既知の制限

リリースゲートは回帰、文書/翻訳、生成ソース、アーカイブ、再現性、クリーンなパッケージ導入と依存監査を確認します。これらはゲート要件で、新しい実時間4時間試験の証拠ではありません。過去のRC4検証と独立ACK 20/21はv1.0.0に属します。非公開勧告フォークではCIが動作しないため、統合された公開mainの正確なコミットが公開前にゲートを通過する必要があります。

#161は公開経路の停滞の根本原因が未確認のままです。posted、queued、submittedは送信証拠で、消費やACKではありません。不明な結果は自動再送を許可しません。パッケージ公開、ホスト対策の配備、機器群への導入、本番サービス再起動は別の作業です。
