# session-peer 0.8.0

このリリースでは、Claude と Codex をまとめて一覧表示し、制限されたデフォルト/Orca/カスタムホームにわたって Codex セッションを検出し、オプションの MCP ツール、Codex プラグイン、および明示的で制限付きの Codex wake を追加します。メッセージ入力と結果のフォーマットに、個別の名前付きオプションが用意されました。

## 変更点

- #76: `list` のデフォルトで両方のエージェントを対象とします。各セッションには `agent` が含まれます。フィルタリングするには `--agent claude` または `--agent codex` を使用してください。検出は独立した結果を報告し、別のソースが失敗した場合でも成功した行を保持します。
- #77: stdio の `list_sessions` および `send_message` ツールを使用するには `session-peer[mcp]` をインストールします。Codex プラグインとマーケットプレイスファイルはリポジトリ内にあります。デフォルトの MCP ポリシーはローカルの一覧取得のみを許可します。送信および SSH 宛先には、明示的なケーパビリティとクライアントの承認が必要です。
- #78: オプトインの `send --wake` は、2 回目のプロンプトを追加することなく、ネイティブの app-server を介して非アクティブな Codex スレッドを再開します。個別に出力される wake 結果により、アクティベーションが失敗した場合でもキュー送信の詳細が保持されます。
- #80: Codex の一覧取得は、デフォルトのホーム、`CODEX_HOME`、制限された macOS Orca アカウントホーム、および `SESSION_PEER_CODEX_HOMES` を集約します。各行には正規の `codexHome` と `stateDb` が付与されます。異なるホームにある同一の UUID は区別されたままです。明示的な `--codex-home` は一覧取得をそのホームに限定します。
- #82: `send --message TEXT` / `-m TEXT` でメッセージ入力を明示的に選択し、`--output-format text|json` で結果のフォーマットを選択します。位置指定のメッセージ、stdin、`--b64`、および `--json` は引き続き互換性があります。競合する入力ソースや出力セレクターは、送信前に拒否されます。

## 互換性と制限事項

- フィルタなしの `list` の利用者は、各行の `agent` を使用する必要があります。マルチホームの結果では、各行の `codexHome` を使用してください。複数の候補ホームが関係している場合、トップレベルのスカラーは省略されます。自動検出で Codex のインストールが存在しない場合は空の `not_installed` が返され、明示的に設定されたホームが見つからない場合はエラーになります。
- スタンドアロン CLI は Python 3.9+ で依存関係のない状態を維持します。オプションの MCP 統合には Python 3.10+ と MCP エクストラが必要です。
- Wake は Codex CLI **0.154.0** の macOS/Linux のみをサポートします。他のバージョンでは wake に対してフェイルクローズします。通常のキュー送信のみの場合は既存の動作が維持されます。Wake はモデルの使用量を発生させ、既存のポリシーの下でターゲットセッションのプロジェクトを変更する可能性があります。これは永続的なワーカーではなく 1〜60 秒に制限されており、タイムアウトによって部分的な作業が中断される可能性があります。[wake の詳細](../wake.md) を参照してください。
- キューへの受け入れおよび wake の完了は、特定のメッセージの受信を確認するものではありません。`consumptionConfirmed` は false のままです。wake や SSH の障害の後に、送信済みメッセージを自動的に再送信しないでください。
- ホームの検出は制限されており、読み取り専用です。一覧取得によってセッションが wake されたりライターのロックが解除されたりすることはなく、このリリースではリレートランスポートは導入されません。

## アップグレード

インストールのパッケージマネージャーを使用してください（`pipx upgrade session-peer`、`uv tool upgrade session-peer`、または `python -m pip install --upgrade session-peer`）。MCP の場合は、`session-peer[mcp]` エクストラをインストールまたはアップグレードしてください。スタンドアロンインストールの場合は `session-peer update` を実行できます。同梱のスキルを更新するには、v0.8.0 のチェックアウトから `install.sh` を再実行してください。プラグインの設定については [MCP のセットアップ](../mcp.md) を参照してください。

## 検証

- MCP SDK がインストールされた状態で 301 件のテストに合格しました。スタンドアロンの明示的なテストおよびデフォルトの unittest 検出で、それぞれ 301 件のテストが正常に実行され、2 件のオプションの SDK テストがスキップされました。
- wheel および sdist が独立してビルドされ、新規環境にインストールされました。モジュールおよびディストリビューションのメタデータは 0.8.0 を報告し、隔離されたホームの Codex 一覧取得は成功して空の `not_installed` を返します。wheel の MCP エクストラとエントリポイントもインストールされ、確認されました。
- 両方のディストリビューションに MCP アダプターが含まれ、凍結されたレガシーの `cc_peer.py` は除外されています。sdist にはプラグインおよび統合のドキュメントが含まれています。
- すべての機能 PR は順次マージされる前に CI に合格しました。リリース CI は、Ubuntu/macOS 上のコア Python 3.9/3.13 および Windows 上の 3.13 をカバーしています。オプションの MCP は Ubuntu/macOS 上の Python 3.10/3.13、およびパッケージ/インストール/シェルのチェックを使用します。
- リリース準備中に実際稼働メッセージや wake アクティベーションが送信されることはありませんでした。以前の実稼働 wake の証拠は macOS 上の Codex 0.154.0 に限定されており、Linux のライフサイクル動作はフィクスチャでテストされています。[検証の証拠](../wake.md#validation-evidence) を参照してください。
