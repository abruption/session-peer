統合ソースの基準は、バージョン準備コミットより前の `a0e7af032fd372334782cc3ac3d97b21c71dd797` です。機能PR6件は#329、#330、#331、#332、#325、#328の順にマージしました。この基準の[統合CI](https://github.com/abruption/session-peer/actions/runs/39905198747)と[CodeQL](https://github.com/abruption/session-peer/actions/runs/39905198891)は成功していますが、最終リリースコミットの検証に代わるものではありません。

## 含まれる変更

- #323 / #325: `send --dry-run --explain`、`doctor --explain`、`handoff status --explain`のテキスト説明。対応するペアリング先の準備状況を含め、既存の結果と記録済みの証拠を説明します。権限の付与や消費の証明ではありません。古い受信側では追加情報が不明のままになる場合があります。保存済みの受信確認の証拠と新しい観測は区別します。
- #324 / #328: Mac/Linuxのlocal/SSH Claude Code・Codex向けに、任意の経路プリセットと独立した受信者アドレス帳を追加。実際のアドレス送信には現在の `--address-revision` と正確な `--confirm-target` が必要で、選択先とwriterを再確認します。revisionは人物の認証やnative世代・ストレージの原子的な一致の証明ではありません。Windows、ペアリング機器、Antigravityのアドレス帳操作は未対応です。
- #296 / #329: 既存intentを観察する、時間制限付きPOSIX `handoff watch`。送信、再送、collector、新たな受信確認権限は作成しません。実験的handoffの範囲と既存の未対応チャネルは維持します。
- #312 / #330: 明示的に信頼したSSH設定に対応。信頼した設定はローカルSSHコマンドを実行できるため、運用者による信頼判断が必要であり、sandboxではありません。既存の宛先確認と不確定な結果の扱いは維持します。
- #212 / #331: 入力を表示しない端末入力と独立したフィンガープリント確認を使う、有効期限付き一回限りのペアリングリンクと設定案内。双方が対応ペアリングプロトコルと既存のUnix Relay要件を満たす必要があります。ペアリングは宛先ポリシーやnative承認に代わりません。保留中の申し出の取り消しは、完了したペアリングを失効させません。
- #294 / #332: Mac/Linuxで、特定バージョンの自動ランタイム通知をローカルで非表示にし、明示的に解除する操作。管理はオフラインで行い、明示的な更新確認とスキル通知の既存動作は維持します。

正確な組み合わせ、プラットフォーム制限、エラー動作は[CLIリファレンス](../cli-reference.md)、[handoffガイド](../handoff-runtime.md)、[ペアリング機器ガイド](../paired-devices.md)を参照してください。統合変更には回帰テストの安定化と、期限切れRelay roomの利用可否判定の修正も含まれます。再実行の成功だけでは、過去の別の失敗の原因は特定できません。

## 互換性と残る作業

コアランタイムはPython 3.9+を維持します。任意のMCPはPython 3.10+、Unix/WSL Relay receiverはPython 3.11+が必要です。コアlocal/SSH利用に外部Python依存関係は追加しません。通常の送信結果は、消費、受信ACK、タスク完了と区別します。不確定な結果は自動再送を許可しません。

互換スキルコピーはcompanion 0.3.3、最小ランタイム0.9.1、案内範囲全体の基準1.0.1を維持します。companionの1.3案内は別途レビューする文書更新です。このランタイムの公開によってスキルがインストールまたは公開されるわけではありません。プラグインとTypeScriptのバージョンも独立しています。

Side Session・steering研究（#245/#247、Draft #246/#248）はLong-termに割り当てられ、リリース機能には含まれません。残るnative世代、handoff、ストレージ、起動時の受け入れ作業（#180/#181/#268/#304/#306/#307）は本リリースで完了しません。一般的なCodex ACK、最初の入力前の配信、Antigravity正式対応を新たに主張しません。

## リリース検証

準備PRの最新レビューとCI、その後の保護されたmainの正確なコミットでのCIと依存関係監査が必要です。生成された単独ファイルの一致、4言語の文書、パッケージ内容、新規インストールを確認します。ローカル統合・ビルド結果は事前検証であり、公開成果物や新たな実エージェント・プラットフォーム受け入れ検証ではありません。

承認済みのタグとドラフトを準備した後、preparation workflowとattach-draftジョブの成功を待ちます。公開前に、不変の成果物7件、`SHA256SUMS`、`release-provenance.json`、認証済みattestationを正確なタグとコミットに照合します。必須の人手によるPyPI環境承認は維持します。公開証拠は別途記録し、この固定文書を改訂するために不変の成果物を置き換えないでください。

パッケージ公開はControl/Relayサービスの配備やインストール済み機器の更新を含みません。運用への反映と実際の受け入れ検証は別です。
