# session-peer 0.6.1

このリリースでは、エージェント間メッセージの帰属確認が容易になり、暗黙的なCodex送信によって重複するセッションホーム間がサイレントに選択されるのを防止します。

## 変更点

- 選択された/デフォルトのホーム、macOS Orcaアカウントホーム、および明示的に設定された `SESSION_PEER_CODEX_HOMES` 全体で重複するCodexスレッドUUIDを検出します。曖昧な暗黙的送信はキューに追加される前に失敗します。`--codex-home` は依然として明示的な宛先選択フラグです。
- 選択、キュー送信、および消費が混同されないように、`codexHome`、`submitted`、および `consumptionConfirmed` フィールドを追加しました。
- デフォルトのメッセージエンベロープで検出された送信者を `claude:<session>` または `codex:<thread-uuid>` として識別し、一致する返信先を生成します。
- `tailscale status --json` を介して既知のTailscale SSH接続先を解決します。オンラインのピアは現在のMagicDNS FQDN経由でルーティングされ、オフラインのピアはSSHの前に失敗し、一致しない接続先は通常のSSHホストのままとなります。
- 指定された接続先をSSHエイリアスとして維持し、検証済みのMagicDNSで `HostName` を上書きし、`HostKeyAlias` を介して指定されたホストを保持することにより、既存のSSH設定とホストキーを保持します。結果では、異なる場合に正規の `host` と元の `sshHost` を報告します。
- 標準ライブラリテストスイートを `tests/` 配下に整理し、CI探索を更新しました。

## 互換性と制限

- 既存のClaude/Codexターゲット、抑制フラグ、一般的なSSH接続先、およびパッケージ/スタンドアロンインストールパスは引き続きサポートされます。
- 送信者エンベロープはベストエフォートのメタデータであり、認証されたアイデンティティではありません。
- キューに入れられたメッセージは消費や確認応答の証明ではありません。このリリースでは、セッションの起動、返信待ち、または逆方向SSH到達性の検証は行いません。これらはv0.7ロードマップに含まれています。
- 複数のCodexホームを持つユーザーは、list、dry-run、およびsendに同じ明示的な `--codex-home` を渡す必要があります。

## アップグレード

インストールを管理しているパッケージマネージャーを使用してください:

```bash
pipx upgrade session-peer
uv tool upgrade session-peer
python -m pip install --upgrade session-peer
```

スタンドアロンインストールでは `session-peer update` を実行できます。同梱のClaudeスキルも更新する場合は、v0.6.1のチェックアウトから `install.sh` を再実行してください。

## 検証

- 明示的な `tests/` 探索とデフォルトのunittest探索の両方で、174件の単体/統合テストに合格しました。
- CIは、Python 3.9/3.13でのUbuntuおよびmacOS、Python 3.13でのWindows、パッケージビルド、スタンドアロンインストールのスモークテスト、shellcheck、およびシークレットスキャンで合格しました。
- wheelおよびsdistのビルドと、分離された成果物のインストールが検証されました。
- ローカルのCodex listおよび明示的ホームでのdry-runが送信なしで完了しました。
- Tailscale IPによって指定された読み取り専用SSH listは、元のホストキーエイリアスを保持しながら、検証済みのMagicDNS名経由で接続しました。
