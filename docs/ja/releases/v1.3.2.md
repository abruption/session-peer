## 変更内容

- #341 / #342：レシーバー起動時の`ready:true`を維持し、`directReadyConfirmed:false`を追加して、ローカルリスナーの設定とリモートからの到達可能性を区別します。TLS完了だけではペアリング、ネイティブ対象へのアクセス、ACKを証明しません。
- 明示的に選択する`--diagnostic-events`にDirectのコールバック・TLS観測と、上限のあるレシーバーごとの`accepted`、`tlsCompleted`、`tlsFailed`カウンターを追加します。`accepted`と`peer_tls`の段階では合計で60秒に最大2件を記録し、TLS成功・失敗は後者の段階の制限を共有します。正常終了時には0件も含む`summary`の記録を追加で1回試み、終了処理を繰り返しても再試行しません。固定フィールドにアドレス、ピア/セッションID、メッセージデータ、例外原文は含めません。ロギング失敗は元のハンドシェイク例外を置き換えません。既存の同期stderr出力には、出力先が詰まった場合の強制的な制限時間はありません。
- 実験用TCPプローブはPython 3.9/3.10の`asyncio.TimeoutError`を処理し、Python 3.9/3.13で応答が止まるループバック回帰試験を実施しました。手動の2台のMac・tailnet実験はCIとは別で、`experiments/`はwheel/sdistから除外されます。[実験記録](https://github.com/abruption/session-peer/blob/dac1c30b1553136b9379be0c6d94eef34ccbad51/experiments/macos-direct-listener/README.md)を参照してください。
- #343 / #345：Node Controlの`better-auth`と`@better-auth/core`の固定版を1.7.5から1.7.7へ更新し、アダプター・telemetryの版もそろえます。上流は[GHSA-965c-763c-88jm](https://github.com/advisories/GHSA-965c-763c-88jm)（重大）、[GHSA-r4xp-prcw-77qf](https://github.com/advisories/GHSA-r4xp-prcw-77qf)（高）、[GHSA-44jh-23m7-hpcf](https://github.com/advisories/GHSA-44jh-23m7-hpcf)（低）の最初の修正版を1.7.7としています。
- #344 / #345：保護された読み取り区間に入ってからだけREADYを通知するよう、SIGINT試験を同期します。macOS Python 3.13で観測されたシグナル終了(-2)と想定する処理済み終了130の競合に対応し、製品のシグナル動作ではなく試験の同期を変更します。固定sleepや弱いアサーションでこの境界を代用せず、過去のCI失敗の正確な原因も確定していません。

- #346 / #347：オプションのMCP SDK要件を`mcp>=1.30,<2`へ引き上げます。コアのPython 3.9下限とMCPのPython 3.10+マーカーは維持します。POSIX CIはMac/Linux、Python 3.10/3.13、正確な下限`1.30.0`または最新の互換`1.x`という2つのSDKプロファイルを組み合わせた8セルです。間接依存関係は通常どおり解決し、下限プロファイルは全パッケージの最低版を検証するものではありません。インストール済みSDKの標準入出力（`stdio`）契約チェックは、HTTP/OAuthの露出や悪用可能性を立証しません。

PR #345の2つのゲート修正は個別レビュー済みのコミットとしてマージされ、PR #347のMCP下限・CIプロファイルもマージされました。レビュー対象のPR #347コミットはMCPの全8セルを含む32チェックに成功し、自動Codexコード・セキュリティレビューも別途指摘なしで完了しました。このPR結果は保護された最終mainの検証や公開証拠に代わるものではありません。リリース準備PRのマージ前に現在のmainの検証成功を必須とします。

## 原因と互換性の範囲

所有者がPython.appへの着信接続を許可した後、両方のMacで、元の公開済みv1.3.1のHomebrew Python 3.14.9ランタイム、同じtailnetのbindアドレスと各機器の同じポートを使い、Directペアリングと認証済みprobeが成功しました。新しい試験用の識別情報を使い、ネイティブ呼び出しは0件でした。転送プロセスや別のインタープリターは不要でした。この結果は、今回の接続を妨げていたのがmacOSアプリケーションファイアウォールの承認待ちだったことを裏付けます。診断コードが接続を復旧したわけではありません。以前の陰性・署名・転送の対照試験は過去の観測記録であり、必須の解決策やmacOS・Tailscale・Pythonに共通する原因の判定ではありません。

Directのbind、TLS・認証チェック、期限、ペアリング状態、自動再試行禁止の動作は維持します。ファイアウォール・アクセス方針・ランタイム選択を自動化せず、新しいプラットフォームや一般的なACK対応も追加しません。既存ユーザーのpending状態は再試行・初期化していません。ネイティブ世代識別、handoff、保存先、起動時の受け入れ条件(#180/#181/#268/#304/#306/#307)とSide Session・steering研究は別途扱います。

オプションのRelayレシーバーモジュールの変更はwheel/sdistに含まれ、単体版`session_peer.py`には組み込まれません。診断機能を適用するには、レシーバー自身のパッケージ・環境を更新し、そのプロセスを明示的に再起動する必要があります。単体ファイルの更新だけでは、これらのモジュールは更新されません。この公開で運用環境の更新や再起動は行いません。

調査したControlソースはSQLiteと`bearer`、`deviceAuthorization`プラグインを使い、勧告のMagic Link/OAuth Proxy/PostgreSQL経路は使っていません。配備済み環境での悪用可能性は立証していません。Node Controlの依存関係修正はPython wheel/sdistに含まれず、別途承認されたサービス配備が必要です。上流のOAuth検証識別子の接頭辞変更を確認し、検証ストレージを共有するサーバー間で更新を調整してください。更新後、進行中だったOAuthサインインは最初からやり直す必要が生じる場合があります。この準備では運用環境への配備、セッション失効、データ移行を行いません。

互換スキルはv0.4.0、最小ランタイム0.9.1 / 文書のCLI機能の基準1.3.0を維持し、受信側`codexBin`の最小バージョンも1.0.1のままです。変更のないSHA-256は`debedd472e3b0c0c6844fb63f7fb2f17cb6c6cc8c3e981e9afd2531a35327af7`です。ランタイムの公開は、別途管理するスキルの更新や稼働サービスの配備を行いません。
