# session-peer v1.0.0

最初の v1 安定版は RC4 で検証されたランタイムを提供します。`v1.0.0-rc.4` からランタイム動作は変わらず、版と文書のみを昇格しました。ローカル/SSH の基本メッセージングは依存関係なしです。任意の MCP、エンドツーエンド暗号化によるペアリング済み direct/Relay メッセージングと管理された入場、実験的 Antigravity ブリッジは明示的に有効にします。

## 検証と変更

- #162 は試行ごとのサニタイズされた経路診断と、送信前の control/admission 段階での限定された 1 回の再試行を追加しました。送信後の結果が不明なメッセージは自動再送しません。
- #168 は通常のアイドル期限切れ後の受信側再接続の空白を短縮し、Relay レグの 10/10 秒 keepalive と `receiverRoleBusy`/`clientRoleBusy` 指標を追加しました。
- 5 ホストの `rc4-rerun-02` は 14,436.65 秒で完了し、公開 health 241/241、probe 147/147、送信 21/21、計画された Relay 再起動から 3.182 秒で復旧しました。正確な ACK は 20/21 です。元の T120 Windows native Claude ACK は TUI 終了で未確認ですが、同じ経路の別の新しい単発検査は正確な ACK を得ました。ユーザーは #164 の運用例外を承認しましたが、元の集計は遡及して変更しません。

## インストール

既存のパッケージマネージャーを使い、インストール環境やデバイス ID を混在させないでください。

```bash
# Unix / WSL paired transport and MCP
pipx install 'session-peer[relay,mcp]==1.0.0'
# Native Windows core and MCP (Relay receiver runs in WSL)
pipx install 'session-peer[mcp]==1.0.0'
```

コアは Python 3.9+、MCP は 3.10+、Relay 受信側/サーバーは Unix または WSL の 3.11+ が必要です。launchd/systemd 起動の macOS・Linux 受信側のサービス `PATH` には対象 TUI の `codex` 実行ファイルディレクトリが必要です (#171、#176)。`codexBin` は WSL 専用で、同じ環境の `send --dry-run` で確認してください。Relay デバイスログインは期限切れになり再承認が必要な場合があります。429/slow_down の扱いは #174 で追跡します。

## 境界

#161 の断続的な Cloudflare↔KR 転送停滞の位置と責任は未確定です。RC4 は増幅を緩和しましたが経路を修復しておらず、#161 は v1.0.1 の監視として開いたままです。ホスト型 Relay/OAuth の可用性はパッケージ公開とは別です。Windows の検出結果には終了済み Claude 記録が残る場合があります (#173)。Antigravity は実験的です。submitted/queued は消費や ACK の証拠ではなく、結果不明のメッセージを自動再送しません。
