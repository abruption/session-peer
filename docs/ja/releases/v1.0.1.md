# session-peer v1.0.1

v1.0.0 に続くメンテナンスリリースです。ローカルと SSH のメッセージ機能は、外部 Python 依存なしで利用できます。Relay、MCP、Antigravity のオプトイン境界は変わりません。

## 変更点

- POSIX インストーラーは個別管理の Claude Code と Codex のスキルパスを尊重し、別途導入したスキルを上書きしません（#187）。
- KR スナップショットヘルパーは明示的な実行フラグを要求し、ヘルプや無効な引数では実行しません（#175）。
- デバイス認可のポーリングは 429 と slow_down の応答で即終了せず、待機時間を延ばします（#174）。
- macOS・Linux の Relay 受信側は Codex 実行ファイルを指定できます。ネイティブ配送前の失敗は配送後の結果不明ではなく拒否として分類します（#171、#176）。
- Windows Claude の検索は終了済み・再利用済み PID を除外し（#173）、Codex の検索は保存前の稼働中 writer と存在しないスレッドを区別します（#166）。
- 更新確認は別途インストールした session-peer スキルの古い版や非互換を通知できますが、暗黙には変更しません（#167）。
- オプションの Relay 診断は受信側ライフサイクルに時刻を付け、試行を対応付け、本文なしでレグごとのフレーム進行を記録します（#172、#197）。
- Relay control は追加のメトリクスカウンターを受け入れます。Dependabot のバージョン更新 PR 作成は無効です（#189）。

## インストール

既存のパッケージマネージャーによる導入は、`pipx upgrade session-peer` など通常の更新コマンドを使います。MCP を含む Unix・WSL の新規ペアデバイス導入には `pipx install 'session-peer[relay,mcp]==1.0.1'` を使います。コアのみなら Python 3.9 以上で外部依存はなく、Relay には Unix または WSL と Python 3.11 以上が必要です。

サービス管理下の macOS・Linux 受信側には対象 Codex 実行ファイルを見せるか、新しい明示的な実行ファイルオプションを設定してください。送信前に `--dry-run` で宛先を確認します。

## 既知の制限

- Cloudflare から KR Relay への断続的な停滞（#161）は原因と責任箇所が未確定です。追加診断は今後の調査を助けますが、ネットワーク修復を証明しません。
- 投稿またはキュー登録は ACK ではありません。送信後の結果が不明なときは自動再送しないでください。
- パッケージ公開はホスト型 Relay や OAuth の可用性を保証しません。Antigravity ブリッジは実験段階です。
