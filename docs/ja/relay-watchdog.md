# 制御ウォッチドッグとリレー復旧 (RC 候補)

`Upholds=` は停止したリレーを再起動できますが、systemd が依然としてアクティブとみなしているフリーズした制御プロセスを検出することはできません。そのため、制御アプリケーションは systemd ウォッチドッグに参加します。これは systemd 外部では任意であり、Python や Node のパッケージ依存関係を追加しません。サービスホスト上に `/usr/bin/systemd-notify` が必要です。

`Type=notify`、`NotifyAccess=all`、`WatchdogSec=30`、および `WatchdogSignal=SIGKILL` を使用します。`flock --no-fork --nonblock` で Node を起動し、Node がメイン PID となり `WATCHDOG_PID` と一致するようにします。既存の排他ライターロックは保持されたままになります。異なるウォッチドッグ PID や不完全なウォッチドッグ設定は、警告なしに無効化されるのではなく、起動エラーとなります。実行可能ファイルは、`ProtectHome` によって隠蔽されたホームの外部にある root 所有の Node ランタイムである必要があります。

ループバックリスナーの起動後、制御はヘルスチェックに合格した場合にのみ `READY=1` および `WATCHDOG=1` を送信します。最大でも 5 秒ごと（または設定されたウォッチドッグ周期の 3 分の 1 ごと）に、同じイベントループが以下を確認します:

- パブリッシャーが失敗しておらず、リスナーが実行中であること。
- 最新の成功した公開状態が 180 秒の有効期間内にあり、未来に向かって 5 秒を超えていないこと。
- 通常の状態ファイルがその公開内容と依然として完全に一致していること。
- 制御データベースのリビジョンが公開されたリビジョンと等しいこと。

HTTP の `/healthz` エンドポイントでも同じ状態チェックが使用されます。読み取りの失敗、状態の欠落や変更、失敗したパブリッシャー、および不健全なチェックではハートビートは送信されません。フリーズしたイベントループもハートビートを送信できません。これらのチェックによって、OAuth リクエストの成功やネイティブエージェントの配信が暗示されることはありません。

通知には、シェルを介さない、2 秒のタイムアウトと `SIGKILL` 終了を備えた単一実行の子プロセスが使用されます。その環境には `NOTIFY_SOCKET` のみが渡され、OAuth 設定、トークン、および認証情報パスは継承されません。通知機能は `MAINPID` を設定せず、`--no-block` も使用しません。systemd-notify の確認応答により、systemd が通知を属性付けする前に終了することを防ぎます。`NotifyAccess=all` は、ユニットの cgroup 内のこの子プロセスが通知を行うことを許可しますが、他のユニットを認可するものではありません。シャットダウンはハートビートのスケジューリングを停止し、すでに実行中の通知機能は同じ 2 秒のタイムアウトによって制限されます。

オペレーターの協調スタックは、依然として制御の障害をリレーの終了に結び付け（`BindsTo`/順序付け）、新たなレディネスチェックの後にのみリレーを再起動する必要があります（`Upholds`/順序付け）。30 秒のウォッチドッグは有界な障害検出であり、即座のヘルス検出や、Python の状態検証およびライブ失効チェックの代替となるものではありません。起動、再起動、およびレート制限は明示的に保ってください。マイグレーションおよびリプレイの初期化が自動復旧の依存関係になってはなりません。

本番適用前に、コンパイルされた正確な候補と実際のサンドボックスを使用して、メイン PID の属性付け、ウォッチドッグ周期を超える正常動作、制御 cgroup SIGSTOP、持続的な不健全状態、SIGKILL、自動再起動後の新たなレディネス、リレーのクラッシュ、明示的なスタック停止、および再起動制限を検証してください。すべての鍵、操作レシート、リプレイ証拠、およびリビジョンの高水位標を保持してください。再起動することやカウンターを追いつかせることのいずれも、安全なバックアップ復旧を確立するものではありません。

ローカル単体テストは、通知ゲーティング、障害、有界な並行性、環境の分離、および状態ヘルスチェックをカバーしています。これらは実際の systemd 通知配信や SIGSTOP 復旧ゲートを確立するものではなく、それには KR ランタイム実験が必要です。

参考資料: [systemd v255 通知セマンティクス](https://github.com/systemd/systemd/blob/v255/man/systemd-notify.xml) および [サービスウォッチドッグオプション](https://github.com/systemd/systemd/blob/v255/man/systemd.service.xml)。
