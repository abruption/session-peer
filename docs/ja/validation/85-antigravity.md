# #85 Antigravityアダプター開発検証

2026-09-17; ローカルブランチ `feat/85-antigravity-adapter`、分離されたワークツリー `/tmp/session-peer-85`、#47 `993d04d` ベース。中継への依存、リリース、リモートプッシュ、PRなし。バージョンは開発メタデータとして0.8.0のまま維持。この機能は公開された0.8.0ディストリビューションには含まれていません。Issue: https://github.com/abruption/session-peer/issues/85

## 実装内容

スタンドアロンソースにおけるオプトインの登録済みセッションアダプター、ローカル/SSHのlistおよびsend、doctor機能、正確なUUID/ホーム/プロセス識別および世代チェック、同一UID限定のプライベートフレーム化ソケット、制限されたリクエスト/ライフタイム/ネイティブサブプロセス、同世代内のリクエスト重複排除/競合処理、シグナルクリーンアップおよび古いプロセスの再起動。送信者検出には一意の登録済み先祖が必要です。MCP一覧表示は、3番目の組み込みアダプターが追加された際にも明示的なエージェント許可リストを保持します。

## 証拠

- macOS Python 3.14: オプションのMCP SDKをインストールした状態で332件のテストに合格（実際のMCP stdioテストを含む）。SDKなしの場合: 332件のテスト、2件のオプションスキップ。
- KR Ubuntu Python 3.12: 17件のアダプターテストに合格。実際のUnixソケット、ダミーのネイティブ実行可能ファイル、SIGTERMクリーンアップおよび古いプロセスの再起動フィクスチャ、モデル呼び出しなし。
- wheel/sdistをビルドし、分離された仮想環境に個別にインストール。CLIブリッジのヘルプおよび登録済み限定の一覧表示をスモークテスト。グローバルインストールなし。
- 実際のKR agy 1.2.4 TUI: ユーザーがツールランナーを通じて制限付きブリッジを起動。ワークスペースが別のユーザーのディレクトリ下にあったにもかかわらず、ソースストリーミングされたSSH `list` が正しいubuntuホームを検出。2つの異なる統合マーカーがそれぞれ1つのSYSTEM受信レコードと1つの正確なMODEL ACKを生成。重複リクエストは抑制され、同一IDで本文が変更されたものや古い世代のリクエストは拒否された。ドライランはネイティブ配信を呼び出さなかった。構造化 `consumptionConfirmed` はfalseのままであったが、独立したトランスクリプト観測によりこれらのテストACKが確認された。
- 明示的なブリッジ停止によりソケットと登録を削除。その後のSSH listは登録済みセッションなしを返した。ユーザーTUIは元のcwdで存続。リモートのテストソース/テストは削除された。スプリットロック競合を回避するため、UIDごとのプライベートランタイムディレクトリに1つの空のロックファイルが意図的に残されているが、アクティブなブリッジ/ソケット/登録は残っていない。

詳細なサニタイズ済み証拠はローカルの `/tmp/session-peer-85-evidence/` にあります:
`list.json`、`send.json`、`observation.json`、`cleanup.json`、`linux-tests.log`、`full-tests.log`。最初のライブテストのトランスクリプトマーカーは、`cleanup.json` 内で2回目のテストマーカーとともに保持されています。`send.json` には2回目の実行が含まれています。生の環境、トークン、認証情報、または無関係なトランスクリプトは収集されませんでした。

## 制限事項 / 今後のステップ

これは実験的な明示的登録ワークフローです。CLIサイドカーの自動起動、ヘッドレスライターの代替、無人登録、永続的な送信トレイ、自動ACK/wait/wake、UID間アクセス、または厳密に1回の主張はありません。ネイティブの送信者はTUIのagentapiアイデンティティです。説明的なFromヘッダーは暗号論的な送信者証明ではありません。新しい実装のライブネイティブテストはLinuxです。macOSにはプロトコル/ライフサイクルフィクスチャと以前のネイティブPoCがありますが、このブランチのライブネイティブテストではありません。Windowsブリッジはサポートされていません。Windows CIおよびPython 3.9の実行はローカルでは実行されませんでした。SIGKILLは同期的にクリーンアップできません。再起動では排他ロックを取得した後にのみ古いエントリが削除されます。PIDポーリングは、検証とagentapi呼び出しの間のすべてのプロセス終了競合を排除することはできません。

以前のKR PoCでは、7つのメッセージを使用してビジー配信、SSH切断、ブリッジおよびTUIの再起動を実証しました。これらの結果はこの実装に役立てられましたが、このブランチのライブ実行としてはカウントされません。製品レベルの再接続耐久性、長時間実行オペレーション、およびペアリング/中継の統合は、引き続き個別のv0.9/RC作業となります。
