# Handoff ランタイム候補

ドライランは新たに見つかった別の対象ではなく、準備時の対象を検証します。Claude は元の PID・世代の検査を維持し、Codex は元のホーム・書き込みプロセス情報を再確認して照合します。情報が変われば実際には送信せず拒否し、準備済みの対象を変更しません。

これは [#181](https://github.com/abruption/session-peer/issues/181) の未公開実装候補です。公開済み Python v1.0.4 の機能ではありません。[確定した Handoff v1 設計](contracts/handoff-v1.md) と合成検証データは変更せず、設計の受け入れ条件をすべて満たしたという主張もしません。

## 候補が対応する経路

同一 POSIX マシンの Claude 受信箱への送信では、利用者が明示的に初期化した専用記録と、独立した非公開の受領確認コレクターを使用できます。接続先の PID、元のプロセス生成情報、登録された接続先が選択した世代と一致する必要があります。同一 POSIX マシンの Codex は相関 ID 付きのキュー提出を受け付けますが、確認権限は発行せず対象世代は null のままです。配信・確認を必須とする待機はキュー呼び出し前に拒否し、ベストエフォートの確認・観測は unsupported と実際の提出情報を返します。モデルやセッションは起動しません。単一 POSIX 宛先のソース転送型 SSH は、以下の相関 ID 専用 Claude/Codex 提出に対応します。本文を読まない Codex 観測、時間制限付き Windows パイプ、ペアリング機器、SSH 受領確認の準備経路は未対応です。従来のローカル・SSH 送信と Codex wake のバージョン制限は変えません。

```sh
session-peer handoff init --json
session-peer handoff prepare --to worker --message-file ./private-message.txt --json
session-peer send --to worker --message-file ./private-message.txt --correlation-id PREPARED_UUID --request-ack --wait-for acknowledged --wait-timeout 30 --json
session-peer handoff status --correlation-id PREPARED_UUID --json
session-peer handoff wait --correlation-id PREPARED_UUID --wait-for acknowledged --wait-timeout 30 --json
session-peer ack --receipt - --json
session-peer handoff confirm --receipt - --json
```

メッセージは所有者だけがアクセスできる通常の UTF-8 ファイルに置き、例の文字列ではなく prepare が返した ID を使用します。確認 JSON は非公開の標準入力だけで渡します。受信者は通常の権限確認に従って受領確認を送るか判断します。委任された確認権限は、他のツール実行、メッセージ送信、モデル起動、会話履歴の閲覧を許可しません。自動応答を推定しません。

この候補の送信は、名前付きオプション・位置引数の本文、非公開メッセージファイル、時間制限付き POSIX の生の標準入力を受け付けます。標準入力には元の送信期限一つを適用し、厳密 UTF-8、400 万バイト・100 万コードポイントに制限します。終端のないパイプや SIGINT は intent の作成前に拒否し、架空の epoch・提出結果を作りません。確認の標準入力は別のサイズ・時間制限付き API です。複数ホストへの opt-in 送信は未実装です。従来の標準入力と複数ホスト送信は変えません。実際の送信では共通の外部メッセージ境界ですべての本文行を引用し、最終文字数には境界と確認権限も含めます。

Codex の準備は正規化したスレッド・保存先と、サイズ制限付きの元の保存先・書き込みプロセス判定を非公開で記録します。準備済み ID の再利用時に判定が変わると、対象を結び直さず拒否します。これは原子的な世代や消費の証明ではありません。従来の生存する書き込みプロセス・明示的な非アクティブ保存先の規則を維持し、一度だけのキュー呼び出し直前に元の判定を再検査します。バージョン照会とキューは #268 の共通保存先検査・環境正規化を使いますが、ネイティブ設定層・デーモンの保証は同 issue の未解決調査です。専用 POSIX 子プロセスの生の出力・診断を制限し、元の期限と終了処理予算を使います。完全で対象が一致するキュー応答はタイムアウト・異常終了後も queueId・提出情報を保持できます。応答なし・別対象・不完全・不正 UTF-8・上限超過の出力は終了コード 0 でも unknown のままで再送しません。stderr の診断は証拠にせず、app-server・本文・会話履歴 API を呼びません。

権限発行前に、保護された正確なスクリプトと Python、同スクリプトの ACK コマンドを検査します。非公開の送信入力には PATH の未検証 session-peer ではなく、その隔離 Python 確認処理器と記録先を指定し、生の権限トークンは標準入力だけで渡します。確認入力は EOF まで合計 5 秒、4096 バイトに制限します。提出後の保存失敗では確認済みの対象・文字数・dry-run 情報を保持し、証明できない handoff/ACK は省略し再送を禁止します。明示的な待機がなければ確認済み提出は成功・終了コード 0 と固定の記録診断を維持し、検証できない明示的待機は架空の結果を作らず終了コード 1/130 で失敗します。

Codex の相関 ID 専用モードには進行中の明示的待機がありません。完全で有効なキュー応答後の SIGINT は成功・終了コード 0 と wait not_requested を維持し、不完全な証拠は unknown・終了コード 130 です。バージョン事前照会の中断はキューを呼ばず拒否・終了コード 130 になります。stderr 診断の超過は stdout の超過と区別し、既に取得した有効な stdout 応答を消しません。プロトコル stdout の超過は必ず unknown です。失敗した提出の記録は固定理由の閉じた形式だけを認め、破損した成功・秘密フィールドは照会結果に写さず ledger_corrupt で拒否します。不正な公開相関 ID は本文入力前の使用法エラー・終了コード 2、非公開確認の検証は別の操作失敗です。

## ソース転送型 SSH の相関 ID 専用経路

送信者はメタデータ、送信を伴わない対象確認、永続的な提出意図、一回の実際の提出と後始末に、宛先ごとの元の予算を使います。保護されたメタデータ子プロセスは探知時間を更新せず From/Reply と構造化 SSH 自己宛先の正規化を維持します。使用済みの意図は新しい確認前に拒否します。必須のリモート配信・受領確認待機は SSH 提出前に拒否し、ベストエフォート要求は unsupported を返して権限やリモート記録・コレクターを作りません。提出前に元の Claude 世代、または正規化された Codex ホーム・書き込みプロセス情報を再確認します。Codex 世代指定は未対応として拒否し、黙って削除しません。読み取り専用の状態・待機は SSH 提出を行いません。

確認処理は返信前にリモート起動に結びつく単調時計の古い基準点を記録します。送信者は厳密に返信を検証した後、元の時計を一度だけ読み、二つの残り時間を求めます。リモート提出は古い基準点と残り時間を使い、総予算内の後始末に正確に 5 秒を確保します。起動変更、未来・期限切れの基準点、不正な文脈は提出前に拒否します。UTC や機器間の時計の原点を比較しません。SSH 終了はリモート提出や消費の取り消しを証明しません。ホームの対応は信頼したリモート処理器による実際の expanduser/resolve の結果で、専用シンボリックリンクを含みます。送信者による独立した inode 検証、原子的なプロセス世代、一般的な保存先保証ではありません。

実際の引数は設定・ソース・SSH 子プロセス開始前に限定された非公開処理器に結びつく必要があります。隠しオプションは認証ではなく、受信側は外部本文を各行一度引用します。厳密なネイティブ形式と要求・対象・ホーム・文脈検証は、切断、時間切れ、診断超過、中断後も完全な提出証拠を保ちます。プロトコル stdout 超過時には残った正常な接頭部分を成功として採用しません。同一接続で確認した SSH 識別情報と安全な返信メタデータはネイティブ事実と分けて保持します。非公開証拠、本文、時計基準点、内部文脈は公開出力に反映しません。専用の偽 SSH・ソース転送・SQLite・キュー試験はこの候補範囲の検証であり、実際のリモートホスト、モデル消費、導入済み逆方向 SSH 確認経路の証拠ではありません。

## 証拠・プライバシー・時間制限

受信箱への完全な書き込みは提出であり、消費やターン完了ではありません。認証された対応する受領確認、または時間関係を証明できる明示的な運用者の確認だけが acknowledged を生成します。書き込み・応答処理中に届いた早い確認は、サイズ制限付きの未分類証拠として保存します。提出と元の時計の順序を証明してから分類し、確認を作り出したり時刻を遡らせたりしません。確定した確認はコレクター再起動後も保持し、未使用の権限は保守的に失効させます。期限後の重複でも元のトークンハッシュの証明が必要です。手動確認は過去の待機を書き換えません。

Python Claude の既存の省略フィールドを false/null で補いません。待機が失敗しても確認済みの提出事実を保持します。進行中の待機を中断すると stopped を記録し、完全な構造化出力と終了コード 130 を返します。その後の状態照会は終了コード 0 で成功できます。状態照会、待機、受領確認、手動確認はネイティブメッセージを提出しません。記録がない・壊れている・ID が不明な場合は架空の epoch を作らず、別の handoffQuery エラーを返します。自動再送や別経路への切り替えは禁止します。

マシンごとの総予算は準備前から始まり、既定は 30 秒、ASCII 整数 1..60 のみです。総予算内で正確に 5 秒を終了処理に確保し、観測・提出は総予算から 5 秒を引いた時点で終了します。診断用期限もこの境界を示します。5 秒以下は送信前に拒否します。Python ではファイルシステム・識別確認・fsync を強制キャンセルできないため、普遍的な厳密リアルタイム保証ではありません。

生トークンは承認されたネイティブ入力と非公開 IPC・標準入力にだけ渡します。送信者・コレクターの通常出力、引数、URI、環境変数、自身の記録には含めず、ハッシュだけを保存します。受信者のキュー・履歴には委任トークンが残り、同じ利用者権限の読者が取得する場合があります。token_possession は独立したモデル認証ではありません。受信者の会話履歴は読みません。

## 保存方式と残る条件

2026-10-09 の時計調査: [CPython 3.9.25 の Darwin 実装](https://github.com/python/cpython/blob/0bbaf5de9744ae1acea3e2c9ad2257d1cc68e847/Python/pytime.c#L823) はプロセス固有の開始 tick を差し引きます。この候補では Darwin の送信者・記録・コレクターが型検証済み mach_absolute_time/mach_timebase_info ナノ秒を共用し、他の環境ではネイティブ単調時計を使います。受信箱処理器へは保存時刻ではなく、その時計系へ変換した残り時間だけを渡します。時計の証明がない・不正な場合は拒否し、旧候補の別時計記録を暗黙に読み替えません。実際の親子プロセスの値を比較し、macOS Python 3.9 は CI で別途検証します。

POSIX の専用ディレクトリは ~/.local/share/session-peer/handoff です。原子的保存・fsync と固定の排他ロックにより、実際の提出前に初回の試行権限を消費します。その後のクラッシュは実際の書き込み前でも unknown となります。将来の受領確認・待機・提出情報を予約し、10,000 件・32 MiB の制限に削除記録と予約領域も含めます。試行防止記録は自動削除しません。待機は 1 件につき最大 64 回です。

ネイティブの起動情報と単調時計の連続性を証明できる場合だけ、30 日後に詳細を対象に結び付けた tombstone に圧縮します。証明できなければ保守的に保持し、容量が早く尽きる可能性があります。再起動をまたぐ保持は追加審査事項です。既知の復元記録は再利用前に運用者が HandoffLedger.quarantine_restored() を明示的に実行して隔離します。CLI 復元・照合ツールは未完成です。保管・再初期化は明示的な操作であり、自動修復しません。未申告の巻き戻しや複製は確実には検出できません。古いコレクターソケットを自動削除・再接続しません。コレクターは最大 24 時間、権限の TTL は元の意図の永続保存から 24 時間です。再起動時は未使用権限を失効させます。公開前にライフサイクル・失効を設計全体と照合する必要があります。

検証は専用 Unix 受信箱、実際の接続 PID・プロセス生成情報、非公開コレクター・標準入力送信プロセス、専用 SQLite と模擬 Codex キュー子プロセス、時間制限付き生入力、厳密 JSON、同時起動、クラッシュ後の試行防止、遅延・重複・期限切れ、SIGINT を使用します。模擬キュー・バージョン情報は実際の Codex セッションや全バージョンの互換性を証明しません。実際の Claude モデル消費、Codex 観測器、遠隔初期化、Windows 終了処理は証明しません。残る条件を解決するまで #181 は開いたままで、確定した設計データをランタイム認証とみなしません。
