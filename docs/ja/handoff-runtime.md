# Handoff ランタイム候補

これは [#181](https://github.com/abruption/session-peer/issues/181) の未公開実装候補です。公開済み Python v1.0.4 の機能ではありません。[確定した Handoff v1 設計](contracts/handoff-v1.md) と合成検証データは変更せず、設計の受け入れ条件をすべて満たしたという主張もしません。

## 候補が対応する経路

同一 POSIX マシンの Claude 受信箱への送信では、利用者が明示的に初期化した専用記録と、独立した非公開の受領確認コレクターを使用できます。接続先の PID、元のプロセス生成情報、登録された接続先が選択した世代と一致する必要があります。モデルやセッションは起動しません。本文を読まない Codex 注入観測、時間制限付き Windows パイプ、ペアリング機器、逆方向 SSH の確認経路は未対応です。これらの経路の opt-in 送信は実際の送信前に拒否します。従来のローカル・SSH 送信と Codex wake のバージョン制限は変えません。

```sh
session-peer handoff init --json
session-peer handoff prepare --to worker --message-file ./private-message.txt --json
session-peer send --to worker --message-file ./private-message.txt --correlation-id PREPARED_UUID --request-ack --wait-for acknowledged --wait-timeout 30 --json
session-peer handoff status --correlation-id PREPARED_UUID --json
session-peer handoff wait --correlation-id PREPARED_UUID --wait-for acknowledged --wait-timeout 30 --json
session-peer ack --receipt - --json
session-peer handoff confirm --receipt - --json
```

メッセージは所有者だけがアクセスできる通常の UTF-8 ファイルに置き、例の文字列ではなく prepare が返した ID を使用します。確認 JSON は非公開の標準入力だけで渡します。受信者は通常の権限確認に従って受領確認を送るか判断します。委任された確認権限は、他のツール実行、メッセージ送信、モデル起動、会話履歴の閲覧を許可しません。自動応答を推定しません。

この候補の送信は、名前付きオプション・位置引数の本文または非公開メッセージファイルを受け付けます。終端のないパイプは合計時間を超えるため、本文の標準入力は読み取る前に拒否します。確認の標準入力は別のサイズ・時間制限付き API です。複数ホストへの opt-in 送信とリモートの handoff 応答検証は未実装です。従来の標準入力と複数ホスト送信は変えません。実際の送信では共通の外部メッセージ境界ですべての本文行を引用し、最終文字数には境界と確認権限も含めます。

権限発行前に、保護された正確なスクリプトと Python、同スクリプトの ACK コマンドを検査します。非公開の送信入力には PATH の未検証 session-peer ではなく、その隔離 Python 確認処理器と記録先を指定し、生の権限トークンは標準入力だけで渡します。確認入力は EOF まで合計 5 秒、4096 バイトに制限します。提出後の保存失敗では確認済みの対象・文字数・dry-run 情報を保持し、証明できない handoff/ACK は省略して失敗と再送禁止を返します。

## 証拠・プライバシー・時間制限

受信箱への完全な書き込みは提出であり、消費やターン完了ではありません。認証された対応する受領確認、または時間関係を証明できる明示的な運用者の確認だけが acknowledged を生成します。書き込み・応答処理中に届いた早い確認は、サイズ制限付きの未分類証拠として保存します。提出と元の時計の順序を証明してから分類し、確認を作り出したり時刻を遡らせたりしません。確定した確認はコレクター再起動後も保持し、未使用の権限は保守的に失効させます。期限後の重複でも元のトークンハッシュの証明が必要です。手動確認は過去の待機を書き換えません。

Python Claude の既存の省略フィールドを false/null で補いません。待機が失敗しても確認済みの提出事実を保持します。進行中の待機を中断すると stopped を記録し、完全な構造化出力と終了コード 130 を返します。その後の状態照会は終了コード 0 で成功できます。状態照会、待機、受領確認、手動確認はネイティブメッセージを提出しません。記録がない・壊れている・ID が不明な場合は架空の epoch を作らず、別の handoffQuery エラーを返します。自動再送や別経路への切り替えは禁止します。

マシンごとの総予算は準備前から始まり、既定は 30 秒、ASCII 整数 1..60 のみです。総予算内で正確に 5 秒を終了処理に確保し、観測・提出は総予算から 5 秒を引いた時点で終了します。診断用期限もこの境界を示します。5 秒以下は送信前に拒否します。Python ではファイルシステム・識別確認・fsync を強制キャンセルできないため、普遍的な厳密リアルタイム保証ではありません。

生トークンは承認されたネイティブ入力と非公開 IPC・標準入力にだけ渡します。送信者・コレクターの通常出力、引数、URI、環境変数、自身の記録には含めず、ハッシュだけを保存します。受信者のキュー・履歴には委任トークンが残り、同じ利用者権限の読者が取得する場合があります。token_possession は独立したモデル認証ではありません。受信者の会話履歴は読みません。

## 保存方式と残る条件

2026-10-09 の時計調査: [CPython 3.9.25 の Darwin 実装](https://github.com/python/cpython/blob/0bbaf5de9744ae1acea3e2c9ad2257d1cc68e847/Python/pytime.c#L823) はプロセス固有の開始 tick を差し引きます。この候補では Darwin の送信者・記録・コレクターが型検証済み mach_absolute_time/mach_timebase_info ナノ秒を共用し、他の環境ではネイティブ単調時計を使います。受信箱処理器へは保存時刻ではなく、その時計系へ変換した残り時間だけを渡します。時計の証明がない・不正な場合は拒否し、旧候補の別時計記録を暗黙に読み替えません。実際の親子プロセスの値を比較し、macOS Python 3.9 は CI で別途検証します。

POSIX の専用ディレクトリは ~/.local/share/session-peer/handoff です。原子的保存・fsync と固定の排他ロックにより、実際の提出前に初回の試行権限を消費します。その後のクラッシュは実際の書き込み前でも unknown となります。将来の受領確認・待機・提出情報を予約し、10,000 件・32 MiB の制限に削除記録と予約領域も含めます。試行防止記録は自動削除しません。待機は 1 件につき最大 64 回です。

ネイティブの起動情報と単調時計の連続性を証明できる場合だけ、30 日後に詳細を対象に結び付けた tombstone に圧縮します。証明できなければ保守的に保持し、容量が早く尽きる可能性があります。再起動をまたぐ保持は追加審査事項です。既知の復元記録は再利用前に運用者が HandoffLedger.quarantine_restored() を明示的に実行して隔離します。CLI 復元・照合ツールは未完成です。保管・再初期化は明示的な操作であり、自動修復しません。未申告の巻き戻しや複製は確実には検出できません。古いコレクターソケットを自動削除・再接続しません。コレクターは最大 24 時間、権限の TTL は元の意図の永続保存から 24 時間です。再起動時は未使用権限を失効させます。公開前にライフサイクル・失効を設計全体と照合する必要があります。

検証は専用 Unix 受信箱、実際の接続 PID・プロセス生成情報、非公開コレクター・標準入力送信プロセス、厳密 JSON、同時起動、クラッシュ後の試行防止、遅延・重複・期限切れ、SIGINT を使用します。実際の Claude モデル消費、Codex 観測器、遠隔初期化、Windows 終了処理は証明しません。残る条件を解決するまで #181 は開いたままで、確定した設計データをランタイム認証とみなしません。
