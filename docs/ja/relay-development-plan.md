設計上の決定事項:
- コアのスタンドアロン/SSH は依存関係のない状態を維持する。オプションの session_peer_relay パッケージおよび [relay] エクストラ（Python 3.11+）は、明示的な device/relay コマンドに対してのみロードされる。
- ネイティブエンドポイントはオペレーターが定義したエイリアスであり、ピアが制御する実行可能ファイル、ホーム、または任意の CLI 引数であってはならない。受信ポリシーは、ペアリングされたデバイスのフィンガープリントをケーパビリティおよびターゲットエイリアスにバインドする。ペアリング単体ではエージェントへのアクセス権は付与されない。
- 既存の AgentRegistry および LocalTransport 経由で list/send をルーティングし、制限付きのワーカーサブプロセスを使用して、ネイティブ I/O が TLS アドミッションや失効をブロックできないようにする。
- ネイティブな影響が発生する前に送信の意図をジャーナルに記録する。リクエストダイジェストに宛先バインディングとメッセージを含める。unknown の結果は決して自動的に再送信しない。
- デバイス固有の鍵、WebSocket 内のピン留めされた TLS 1.3、個別のリレーアドミッション、明示的なペアリング/失効。オペレーターは既存の HTTPS エッジの背後にリレーをインストールし、シークレット/秘密鍵の伝播や自動的なパブリック公開は行わない。
- 過去の証拠としてラボをイミュータブルに保つ。製品パッケージには独自の回帰テストと明示的な実セッションテストがあり、フィクスチャの結果をネイティブのものとしてカウントすることは決してしない。
