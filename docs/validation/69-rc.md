## Local findings and corrections

The independent ontology review reproduced three failures: restore could expose
state before quarantine, restored senders could still send/rotate, and a missing
relay replay file could be recreated automatically. The Python correction
`52d32c6` stages restoration before publication, checks both sender and receiver
recovery boundaries, and requires explicit durable replay initialization.

Regression coverage also checks an interrupted restore, retained status lookup,
missing/corrupt replay state, bootstrap ticket fencing, failure to persist a spent
ticket, and rollback of public state across restart. A complete machine rollback
of all authorities cannot be detected by a high-water mark on that same machine;
host-loss recovery still requires external reconciliation/fencing.

Local macOS/Python 3.13 run after this correction: 399 discovered tests, 396
passed and 3 Node integration tests explicitly skipped pending the common API
contract. Wheel and sdist builds passed. The initial Node candidate independently
passed typecheck/build and 31 tests on macOS; KR reported the same 31 tests on
Linux ARM64 Node 22/24. These counts are not live OAuth or model validation.

The exact Python commit `52d32c6` was also archived and installed into an isolated
KR Ubuntu ARM64/Python 3.12 virtual environment with relay and MCP extras. All
396 tests passed there in 36.611 seconds. The temporary source/environment was
removed after preserving the test log. No model call, production receiver,
relay service or Caddy change was part of this run.

Node/Python tests under `tests/test_control_integration.py` use the real control
application, Better Auth, SQLite and cryptography with disposable seeded sessions.
Their loopback HTTP bridge replaces only the external TLS transport. No test
authentication endpoint is added to the production application. The integrated
candidate initially passed three tests: generation-zero enrollment/admission/revocation,
managed key rotation with lost commit response and native-effect deduplication,
and cross-owner receiver rejection. The shared contract omits expectedGeneration
on first registration and uses expectedGeneration=0/new generation=1 on first
rotation. Historical completed operations reconcile via the owner-only receipt.

The subsequent macOS candidate run passed all 401 Python tests with integration
enabled, 52 Node tests, typecheck/build and a production npm audit (zero reported
vulnerabilities). Producer regressions include restrictive umask, separate-DB
restart, a directory-fsync failure after visible publication, revision exhaustion
and restored/missing revision refusal. Google bootstrap tests include partial
write/file-fsync/link failures, ambiguous directory persistence and explicit
operator confirmation. These are fixture results, not live provider login.

A fourth cross-language test then passed the complete managed admission → cookie
→ WebSocket → pinned endpoint TLS → native fixture path. The captured relay frames
did not contain the marker, and control revocation closed an already-open sender
connection and released its relay slot. Only outer network TLS was redirected to
loopback; this does not prove public WSS. Fresh wheel and sdist core installs also
passed version/help smoke, and the no-extras suite passed 338 tests (8 optional
module skips).

KR producer work df66f9a/1336ee0 supplied the public-directory permissions and
revision fault tests, integrated with the Python generation contract and existing
public-file rollback guard. The final integrated candidate still needs independent
