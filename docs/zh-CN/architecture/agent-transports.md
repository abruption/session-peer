# ADR: 内部代理与执行传输契约

状态：已接受，用于 v0.8 之后的重构（#47）。这是内部源码契约，并非公开的外部插件 ABI。在单独准备发布之前，软件包版本保持为 0.8.0。

## 决策

保留无依赖的 `session_peer.py` 独立产物，并在该文件中定义契约。SSH 将其源码流式传输到目标端的 `python3 -`；常规的远程操作仍然不需要安装 session-peer 服务或软件包。现在将运行时拆分为可导入的文件需要打包构建工具、远程模块安装或第二种分发机制。验证代理/传输边界不需要这些。

代理拥有原生身份、发现、验证、提交、诊断、代理特定的命令选项以及展现形式。传输拥有这些操作执行的位置。`LocalTransport` 调用已注册的适配器；`SshTransport` 解析目的地并调用现有的经过安全引用的单源码 SSH 协议。接收端解析相同的 CLI 并调用其本地适配器。SSH 不是代理。

初始注册表显式包含 Claude，后跟 Codex。CLI 选项、列表、发送、doctor、Reply-To 验证和 MCP 代理策略均使用该注册表。MCP 仍然是 CLI 的强制执行策略的子进程客户端；注册绝不授予发送/wake 权限。更新部署仍然与代理提交区分开来。

## 证据与兼容性

- Claude 发现生成 PID/名称/收件箱证据并投递到原生套接字。完成写入并非消费证明。
- Codex 使用原生队列和应用服务器接口。同一个 UUID 可能出现在多个主目录中，因此身份保留主机和主目录，而不是仅按 UUID 折叠。多主目录清单、歧义检查和活跃写入者验证仍保留在 Codex 实现中。调用方默认值并非关于远程接收端活跃主目录的证据。
- 原生队列接受可能发生在失败的 wake 之前。保留原生有效负载，包括队列 ID、提交和 wake 状态；切勿自动重试。
- wake 是可选的，并且仍然受限于先前验证过的运行时和生命周期。两个适配器均不支持 wait 和确认（acknowledgement）。
- 主机身份、发送者信封和返回路由规范化独立于代理。在发送端构建一次消息信封，并通过 SSH 传输其现有的 base64 表示形式。

现有选项、网络字段、响应信封 schemaVersion、顺序和退出码保持不变。新增的例外是 `doctor.capabilities.agents`，将注册名称映射到布尔值 `list`、`send`、`wake`、`wait` 和 `ack` 支持。这些描述了已实现的机制，而不是当前的凭据、收件箱可用性、模型就绪状态或目的地权限。`doctor.capabilities.replyObservation` 保留其先前的含义。

远程列出部分失败也接受 `not_installed` 发现状态；否则缺失的可选 Codex 安装可能会丢弃另一个代理的失败诊断信息。带有 `submitted: true` 的失败远程提交同样会保留其原生结果，而不是丢弃其 ID。Reply-To 不能在针对另一个代理的注册前缀时声称一个代理。

## 契约与信任边界

`ADAPTER_CONTRACT_VERSION = 1` 独立于 JSON 响应 schemaVersion。注册表在注册前验证名称、确切契约版本、功能和方法；重复项将被拒绝。`SessionIdentity` 记录代理、主机、标识符和可选的 Codex 主目录。`ExecutionContext` 提供目的地身份和已解析的选项。这些是进程局部值，而不是新的网络协议。发现和提交保留类型化字典契约，以便原生结果字段不会被扁平化消除。

`AdapterError` 派生自现有的 CLI 错误，并添加了代理/原因字段。契约错误使用 `invalid_adapter_contract`、`duplicate_agent`、`unknown_agent`、`unsupported_capability` 或 `invalid_target`。格式错误的发现和诊断使用 `invalid_adapter_result`。意外的操作异常被收容为 `adapter_failed`，而不回显异常文本。意外的提交错误或格式错误的提交结果将变为 `outcome_unknown` 且不重试，因为原生提交可能已经发生。现有的有意 CLI/原生错误及其结构化详细信息保持原样。

发现在聚合之前验证每个适配器的结果。一个适配器的失败不得丢弃来自另一个适配器的成功行或诊断信息。不允许任何适配器仅仅因为其传输返回就声称已消费。

不存在入口点（entry-point）发现、按名称导入、插件目录扫描或由消息驱动的加载。消息中的名称、CLI 参数、URI 或 MCP 策略不能导致代码安装或执行。未知的显式代理将失败；普通目标字符串中未注册的前缀仍保留为字面 Claude 名称以保持兼容性。`claude:` 前缀同样仍是字面 Claude 名称的一部分；Codex 和新注册的适配器使用其已注册的前缀。

未来的外部插件需要单独的设计：显式的操作员安装和允许列表、软件包所有权和依赖隔离、版本协商、错误收容以及记录进程内 Python 插件执行受信任代码这一事实。此项更改不提供沙盒或外部加载标志。

## 验证

`tests/test_adapters.py` 测试通用的 Claude/Codex/夹具契约、第三方代理 CLI 和 Reply-To 路由、功能、不兼容的注册、格式错误的结果、异常收容、MCP 策略以及原生提交计数。源端注册的夹具仅插入到流式传输程序的测试副本中，并通过现有的 SSH 序列化器在新的 Python 子进程中执行。该测试不需要生产环境调度编辑、外部插件加载器、实时模型账户、SSH 连接或消息投递。

现有的传输、原生套接字、队列、多主目录、回复、MCP 和 wake 测试套件仍然是兼容性基线。软件包和独立安装测试确保单文件和可选扩展组件的分发边界保持不变。
