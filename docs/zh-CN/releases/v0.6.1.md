# session-peer 0.6.1

此版本使跨 agent 消息更容易归因，并防止隐式 Codex 发送在重复会话主目录之间进行无提示的选择。

## 变更

- 跨所选/默认主目录、macOS Orca 账户主目录以及显式配置的 `SESSION_PEER_CODEX_HOMES` 检测重复的 Codex 线程 UUID。模棱两可的隐式发送会在排队前失败；`--codex-home` 仍为显式目标选择器。
- 添加 `codexHome`、`submitted` 和 `consumptionConfirmed` 字段，使选择、队列提交和消费不相混淆。
- 在默认消息信封中将检测到的发送方标识为 `claude:<session>` 或 `codex:<thread-uuid>`，并生成匹配的回复目标。
- 通过 `tailscale status --json` 解析已知的 Tailscale SSH 目标。在线对端通过当前的 MagicDNS FQDN 路由，离线对端在 SSH 前失败，不匹配的目标仍为普通 SSH 主机。
- 通过将提供的目标保留为 SSH 别名、使用经过验证的 MagicDNS 覆盖 `HostName` 以及通过 `HostKeyAlias` 保留提供的主机，来保留现有的 SSH 配置和主机密钥。结果在两者不同时报告规范 `host` 和原始 `sshHost`。
- 将标准库测试套件整理在 `tests/` 下，并更新 CI 发现机制。

## 兼容性与限制

- 现有的 Claude/Codex 目标、抑制标志、通用 SSH 目标以及软件包/独立安装路径仍受支持。
- 发送方信封是尽力而为的元数据，而非经过身份验证的身份。
- 已排队的消息不是消费或确认的证据。此版本不会唤醒会话、等待回复或验证反向 SSH 可达性；这些仍保留在 v0.7 路线图中。
- 拥有多个 Codex 主目录的用户应在 list、dry-run 和 send 时传递相同的显式 `--codex-home`。

## 升级

使用管理该安装的包管理器：

```bash
pipx upgrade session-peer
uv tool upgrade session-peer
python -m pip install --upgrade session-peer
```

独立安装可以运行 `session-peer update`。当捆绑的 Claude skill 也需要刷新时，从 v0.6.1 检出中重新运行 `install.sh`。

## 验证

- 通过显式 `tests/` 发现和默认 unittest 发现，174 个单元/集成测试均获通过。
- CI 在配备 Python 3.9/3.13 的 Ubuntu 和 macOS、配备 Python 3.13 的 Windows 上均获通过，涵盖软件包构建、独立安装冒烟测试、shellcheck 以及机密扫描。
- 验证了 wheel 和 sdist 构建以及隔离的产物安装。
- 本地 Codex 列出和显式主目录 dry-run 顺利完成，未进行提交。
- 通过 Tailscale IP 提供的只读 SSH 列出通过经过验证的 MagicDNS 名称进行连接，同时保留了原始主机密钥别名。
