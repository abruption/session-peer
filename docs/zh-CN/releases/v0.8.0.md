# session-peer 0.8.0

此版本将 Claude 和 Codex 一同列出，跨有界的默认/Orca/自定义主目录发现 Codex 会话，并添加了可选的 MCP 工具、Codex 插件以及显式有界的 Codex wake。消息输入和结果格式化现在具有单独的具名选项。

## 变更

- #76：`list` 默认包含两个代理。每个会话都包含 `agent`；使用 `--agent claude` 或 `--agent codex` 进行过滤。发现报告独立的结果，并在另一个源失败时保留成功的行。
- #77：安装 `session-peer[mcp]` 以获取 stdio `list_sessions` 和 `send_message` 工具。Codex 插件和市场文件位于仓库中。默认 MCP 策略仅允许本地列出；发送和 SSH 目的地需要显式功能和客户端授权。
- #78：可选的 `send --wake` 通过原生 app-server 恢复不活跃的 Codex 线程，而无需添加第二个提示词。即使激活失败，单独的 wake 结果也会保留队列提交详细信息。
- #80：Codex 列出聚合了默认主目录、`CODEX_HOME`、有界的 macOS Orca 账户主目录以及 `SESSION_PEER_CODEX_HOMES`。行携带规范的 `codexHome` 和 `stateDb`；不同主目录中相同的 UUID 仍保持不同。显式的 `--codex-home` 将列出限制在该主目录。
- #82：`send --message TEXT` / `-m TEXT` 显式选择消息输入；`--output-format text|json` 选择结果格式化。位置消息、stdin、`--b64` 和 `--json` 保持兼容。冲突的输入源或输出选择器会在传输前被拒绝。

## 兼容性与限制

- 未过滤 `list` 的使用者必须使用每行的 `agent`。在多主目录结果中使用该行的 `codexHome`；当涉及多个候选主目录时，顶层标量会被省略。自动检测缺失的 Codex 安装会产生空的 `not_installed`；缺失显式配置的主目录属于错误。
- 独立 CLI 在 Python 3.9+ 上保持无外部依赖。可选的 MCP 集成需要 Python 3.10+ 和 MCP extra。
- wake 仅支持搭配 Codex CLI **0.154.0** 的 macOS/Linux。其他版本针对 wake 安全失败（fail closed）；普通的仅入队发送保留现有行为。wake 可能会产生模型用量，并在现有策略下修改目标会话的项目。它被限制在 1–60 秒，不是持久的工作进程；超时可能会中断部分工作。参见 [wake 详情](../wake.md)。
- 队列接受和 wake 完成并不确认接收到了特定消息。`consumptionConfirmed` 仍为 false；在 wake 或 SSH 失败后切勿自动重新发送已提交的消息。
- 主目录发现是有界的且只读的。列出既不唤醒会话也不解锁写入者，且此版本未引入中继传输。

## 升级

使用安装对应的包管理器（`pipx upgrade session-peer`、`uv tool upgrade session-peer` 或 `python -m pip install --upgrade session-peer`）。对于 MCP，安装或升级 `session-peer[mcp]` extra。独立安装可运行 `session-peer update`；从 v0.8.0 检出重新运行 `install.sh` 可刷新附带的技能。有关插件配置，请参阅 [MCP 设置](../mcp.md)。

## 验证

- 在安装 MCP SDK 的情况下通过了 301 项测试。独立显式和默认 unittest 发现各自成功运行了 301 项测试，跳过了两项可选 SDK 测试。
- Wheel 和 sdist 独立构建并安装到全新环境中。模块和分发元数据报告 0.8.0；隔离主目录 Codex 列出返回成功的空 `not_installed`。Wheel 的 MCP extra 和入口点也经过了安装和检查。
- 两种分发均包含 MCP 适配器并排除了冻结的遗留 `cc_peer.py`；sdist 包含插件和集成文档。
- 所有功能 PR 在按序合并前均通过了 CI。发布 CI 涵盖 Ubuntu/macOS 上的核心 Python 3.9/3.13 和 Windows 上的 3.13；可选 MCP 在 Ubuntu/macOS 上使用 Python 3.10/3.13，加上软件包/安装/shell 检查。
- 发布准备期间未提交实时消息或 wake 激活。先前的实时 wake 证据仅限于 macOS 上的 Codex 0.154.0；Linux 生命周期行为经过了夹具测试。参见[验证证据](../wake.md#validation-evidence)。
