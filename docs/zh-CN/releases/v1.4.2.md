# v1.4.2维护版本发布准备

于2026-11-05基于已发布的v1.4.1（[GitHub](https://github.com/abruption/session-peer/releases/tag/v1.4.1)、[PyPI](https://pypi.org/project/session-peer/1.4.1/)）准备。在该日期的检查时点，v1.4.2仍是未发布的维护候选版本。整合维护基准为版本准备之前的`c265861d5251f8bab65229521444168e23bc13a9`，并非最终发布提交。所有者要求的是发布准备，不代表批准合并、创建标签或草稿、触发工作流、发布或运维部署。

## 范围

- PR #372修复handoff watch测试代码中的#370：为管道观测设置截止时间，在进入中断结束处理窗口之前确认辅助进程的输出，并通过帧缺失、准备阶段失败的回归案例，验证有限时间内失败及辅助进程清理。CI将POSIX测试矩阵中的各项任务限制为15分钟，其中的核心测试步骤限制为5分钟，并启用faulthandler以在致命信号发生时输出堆栈。这些是测试／CI修复，不代表修复产品运行时缺陷，也不能证明原始CI停滞的原因。
- PR #374修复韩语、日语和简体中文README及运维指南中的#373。它区分handoff接收确认／ACK信息、持久化的配对请求处理结果、历史Control管理操作结果与SSH主机密钥核验记录；修正相关运维术语，澄清现有英文发现／配置说明，并加强标题层级和跨行内联代码检查。原有queued/submitted、消费和ACK之间的边界保持不变。
- 除版本值外，运行时行为不变。冻结的[英文handoff契约](../../contracts/handoff-v1.md)及其[固定契约测试数据](https://github.com/abruption/session-peer/blob/c265861d5251f8bab65229521444168e23bc13a9/tests/fixtures/handoff-v1.json)保持不变；PR #372修改的是另一处watch测试辅助代码。不宣称新增功能，或完成新的原生／SSH投递、Windows 3.14／free-threaded Python、消费／ACK保证及平台支持验证。
- #316的Relay测试／关闭诊断监控、#367的配对设备汇总发现及Long-term研究仍独立处理。重跑成功本身不能证明历史故障的原因或已被解决。

保留现有标签、不可变资产和注明日期的准备／发布记录。软件包发布不会更新独立管理的技能或其他全局MCP环境，也不会重启接收器或部署Node Control服务。
