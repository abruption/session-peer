# session-peer 0.7.0

此版本增加了只读诊断和安全、结构化的回复路由，并使本地和远程工作流中的 JSON 响应和更新通知保持一致。

## 变更

- 在本地和通过 SSH 增加 `session-peer doctor`。它在不连接收件箱或写入队列的情况下，区分缺失或不正确的主目录、不可用的 Claude 收件箱、缺失的 Codex 可执行文件、权限失败、不受支持的 Codex 状态 schema 以及未知的检查结果。
- 增加可选的 `doctor --check-return-route`。目标端测试一条返回来源的固定、非交互式 `ssh ... true` 路由，并禁用了密码提示、主机密钥登记和密钥更新。正向 SSH 成功绝不会被视为反向访问的证据。
- 增加针对通过本地或 SSH 传输的 Claude 和 Codex 的带版本的 `session-peer://v1/reply` 地址。解析器验证所有字段，拒绝冲突的 CLI 路由和不安全输入，并且绝不会将地址评估为 shell 语法。当前机器上相同用户的地址将规范化为本地投递。
- 保留现有的人类可读 `Reply:` 命令以保持兼容性。发送 JSON 现在公开宣告的 `replyRoute` 和结构化地址 `addressResolution`。
- 将每个 JSON 结果标准化在带有 `schemaVersion`、`ok`、`host` 和 `command` 的 schema 版本 1 上。本地或单主机命令返回一个对象；重复的 `--host` 返回有序数组，每个主机具有独立的成功或失败状态。
- 增加私有的 24 小时更新缓存和非阻塞后台刷新。当最新的 GitHub release 记录证明调用的客户端落后时，JSON 会增加 `clientUpdate`，人类可读输出会打印匹配的升级命令。离线、陈旧、最新和选择退出状态均不会延迟或更改所请求的命令。

## 回复观察决策

此版本中没有通用的 `--wait`。Claude 支持的空闲通知仅限于主 Claude 对话观察另一个本地 Claude 会话，而 Codex 队列提交没有匹配的跨 agent 确认观察器。轮询转录可能会混淆其他请求、陈旧输出或回显与回复。因此，`doctor` 将回复观察报告为不受支持；完成工作流应包含关联令牌，并请求向结构化 Reply-To 地址发送显式消息。

## 兼容性与限制

- 通用信封是一项已写入文档的 JSON 契约变更。使用者应读取每个结果中的 `ok`，并根据目标数量处理对象或数组。
- 具有可检测发送方和返回路由的消息除现有的 `Reply:` 命令外，还会获得一个 `Reply-To:` URI。`--no-reply-to` 会同时抑制两者。
- Doctor 检查是证据，而非投递。在实际发送之前，Claude 收件箱的存在仅为文件系统层面的检查，而 Codex 已排队仍不意味着已被消费或确认。
- 反向路由测试绝不是自动的。它们不会添加密钥、使用其他账户重试、放宽主机密钥策略或更改 SSH 配置。
- Codex 主目录发现仍受限于所选/默认主目录、已配置的主目录以及受支持的 Orca 账户主目录。它不会扫描任意根目录。

## 升级

使用管理该安装的包管理器：

```bash
pipx upgrade session-peer
uv tool upgrade session-peer
python -m pip install --upgrade session-peer
```

独立安装可以运行 `session-peer update`。当捆绑的 Claude skill 也需要刷新时，从 v0.7.0 检出中重新运行 `install.sh`。

## 验证

- 通过显式 `tests/` 发现和默认 unittest 发现，240 个单元和集成测试均获通过。
- CI 覆盖了配备 Python 3.9/3.13 的 Ubuntu 和 macOS、配备 Python 3.13 的 Windows、软件包构建和隔离安装、独立安装冒烟测试、shellcheck 以及机密扫描。
- 检查了 wheel 和 sdist 的内容并进行了独立安装。CLI、模块和软件包元数据均报告 v0.7.0，且两个产物均不包含冻结的旧版 `cc_peer.py`。
- 一次真实的 SSH doctor 运行找到了 Claude 收件箱以及有边界的默认/Orca Codex 主目录。可选的反向探测独立于成功的正向连接报告了身份验证失败。发布准备未提交实时的 Claude 或 Codex 消息。
