# session-peer v1.0.0-rc.1

首个 1.0 候选发布版完成了计划中的 v1 实现，并在稳定版发布前征求最后的兼容性与打包反馈。

## beta.1 之后的变化

- 添加 fail-closed 的密钥丢失与设备恢复 workflow，包括 durable reconciliation、
  control fencing、显式 peer 批准和全新 identity。
- 将可维护的 Python core 拆分为职责明确的功能 segment，同时以确定性方式保留
  无依赖的单文件 SSH artifact。
- 通过一个完整 gate、immutable action pin、可复现 archive、精确内容检查、
  provenance、attestation 和 runtime audit 强化发布流程。
- 按 subsystem 重组 test，并要求精确的 wheel 与 source archive 契约，排除
  private state 和仅用于开发的 tree。
- 添加真实的 Codex-to-Claude-to-Codex demo，更新 PyPI summary，并将可选 relay 的
  cryptography 下限提高到已修复的 50.0.1 版本。

## 安装候选发布版

Python package manager 通常不会选择 prerelease。请明确选择：

```bash
pipx install 'session-peer[relay]==1.0.0rc1'
# or
uv tool install 'session-peer[relay]==1.0.0rc1'
```

请在两个已配对 endpoint 上使用相同的 package version。core 支持 Python 3.9+；
可选 relay runtime 需要 Unix 或 WSL 以及 Python 3.11+。

## 候选发布版边界

- 这是供明确 tester 使用的 prerelease。常规 stable upgrade 在最终 1.0.0 发布前
  仍选择 v0.9.1。
- 候选版本冻结 v1 兼容性契约；任何不兼容发现都会阻止 stable 晋级，而不会被静默接受。
- 托管 relay 可用性和 OAuth provider 策略仍是与 package 发布分离的运维 service。
- Antigravity 仍为 experimental；receiver 和可选 relay runtime 不会在 Windows 上
  native 运行，请使用文档化的 WSL 边界。
- 已记录的运维 campaign 保留其中断的 24 小时结果和明确豁免；本候选版本不声称
  提供 uninterrupted service。

请通过 GitHub issue 报告错误，通过仓库的 private advisory channel 报告安全问题。
报告中请勿包含 token、device key、certificate、session ID 或 conversation content。
