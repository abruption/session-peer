# session-peer v1.0.0-beta.1

首个 1.0 beta 在保留无依赖的本地与 SSH 工作流的同时，推动认证中继迈向稳定契约。

## 亮点

- 冻结关于回复 URI、JSON 结果、中继与 control 协议、备份 manifest、migration
  及弃用策略的 v1 兼容性契约。
- 使用有序、transactional 的第一方 migration 替代隐式 control 数据库初始化，
  并通过备份 metadata 记录已应用的 schema revision。
- 在不含用户、设备、token、session 或 message 标识符的情况下公开有界 relay capacity、
  admission 拒绝和 rate-limit metric。
- 支持显式指向原生 Windows Codex 的 WSL relay receiver，同时保留接收端策略与所有权检查。
- 重组可复用部署示例和仅限运维人员的 artifact，使 source distribution 排除 private 运维配置。

## 安装 beta

Python package manager 通常不会选择 prerelease。请明确选择：

```bash
pipx install 'session-peer[relay]==1.0.0b1'
# or
uv tool install 'session-peer[relay]==1.0.0b1'
```

请在两个已配对 endpoint 上使用相同的 package version。core 支持 Python 3.9+；
可选 relay runtime 需要 Unix 或 WSL 以及 Python 3.11+。

## Beta 边界

- 这是供明确 tester 使用的 prerelease。常规 stable upgrade 仍选择 v0.9.1。
- 托管 relay 可用性和 OAuth provider 策略仍是与 package 发布分离的运维 service。
- WSL 支持涵盖以原生 Windows Codex 为目标的 Unix relay receiver；receiver 和可选
  relay runtime 不会在 Windows 上原生运行。
- Control migration 为 forward-only。upgrade 或 rollback 前，请 backup persistent
  state 并遵循文档化的兼容性契约。
- Pairing 和 OAuth 本身不会授予 native agent 访问权限。接收 endpoint 仍执行
  local policy，用户需验证实际 agent 结果。

请通过 GitHub issue 报告错误，通过仓库的 private advisory channel 报告安全问题。
报告中请勿包含 token、device key、certificate、session ID 或 conversation content。
