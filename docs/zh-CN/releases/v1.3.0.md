# v1.3.0 发布准备

## 源码与发布状态

于2026-10-23以已发布的1.2.1为基准准备。本文记录发布范围与验证条件，并非软件包已发布的公告。发布记录请查看[GitHub Releases](https://github.com/abruption/session-peer/releases)和[PyPI](https://pypi.org/project/session-peer/)。

集成源码基准为版本准备提交之前的 `a0e7af032fd372334782cc3ac3d97b21c71dd797`。六个功能PR按#329、#330、#331、#332、#325、#328的顺序合并。该基准的[集成CI](https://github.com/abruption/session-peer/actions/runs/39905198747)与[CodeQL](https://github.com/abruption/session-peer/actions/runs/39905198891)已通过，但不能代替最终发布提交的检查。

## 包含的变更

- #323 / #325：为 `send --dry-run --explain`、`doctor --explain` 和 `handoff status --explain` 提供文本说明。说明已有结果和记录的证据，包括受支持的配对端就绪信息，不授予权限，也不证明消息已被消费。旧接收端的附加信息可能仍为未知。已保存的收件确认依据与新观测有所区别。
- #324 / #328：为Mac/Linux上的local/SSH Claude Code与Codex增加可选路由预设和独立收件人地址簿。实际地址发送要求当前 `--address-revision` 与准确的 `--confirm-target`，并重复检查所选目标和writer。revision不认证人员身份，也不证明native代次或存储的原子一致性。Windows、配对设备及Antigravity地址簿操作仍不受支持。
- #296 / #329：增加有时间上限的POSIX `handoff watch`，观察已有intent。不创建提交、重发、collector或新的收件确认权限。实验性handoff范围及现有不支持的通道保持不变。
- #312 / #330：支持显式信任的SSH配置。受信任配置可能执行本地SSH命令，因此需由操作者作出信任判断，这不是sandbox。保留现有目标检查和不确定结果处理。
- #212 / #331：增加有时限、一次性的配对链接和引导设置，采用隐藏终端输入与独立指纹确认。两端均须满足受支持的配对协议及现有Unix Relay要求。配对不取代目标策略或native审批；取消待处理邀请不会撤销已完成的配对。
- #294 / #332：在Mac/Linux本地隐藏指定版本的自动运行时通知，并提供显式清除操作。管理操作离线完成；显式更新检查和技能通知保持原有行为。

具体组合、平台限制及错误行为请参阅[CLI参考](../cli-reference.md)、[handoff指南](../handoff-runtime.md)和[配对设备指南](../paired-devices.md)。集成变更还包含回归测试稳定性改进，以及Python Relay（`session_peer_relay/relay.py`）中过期room的可用性判断修复。运行中的Relay需由操作者更新并重启后才能应用此修复；尚未执行服务部署。重跑通过本身不能确定此前其他失败的原因。

## 兼容性与剩余工作

核心运行时仍要求Python 3.9+；可选MCP要求Python 3.10+，Unix/WSL Relay receiver要求Python 3.11+。核心local/SSH使用不增加第三方Python依赖。普通提交结果仍区别于消费、收件ACK和任务完成。不确定结果绝不授权自动重发。

GitHub发布包含来自已发布companion 0.3.3的兼容 `SKILL.md` 产物，最低运行时0.9.1、完整指南覆盖基准1.0.1保持不变。新的companion 1.3指南是单独审核的文档更新，不包含在本运行时发布中，也不会由此安装或发布。插件与TypeScript版本也保持独立。

Side Session和steering研究（#245/#247、Draft #246/#248）已归入Long-term，不属于发布功能。剩余的native代次、handoff、存储及启动验收工作（#180/#181/#268/#304/#306/#307）不会因本次发布而完成。不新增通用Codex ACK、首次输入前投递或Antigravity正式支持的声明。
