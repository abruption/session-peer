# session-peer v1.0.1

这是 v1.0.0 之后的维护版本。本地和 SSH 消息传递仍无需第三方 Python 依赖。Relay、MCP 和 Antigravity 集成仍保持自选边界。

## 变更

- POSIX 安装器尊重分别管理的 Claude Code 和 Codex 技能路径，不覆盖独立安装的技能（#187）。
- KR 快照辅助程序要求显式执行标志，帮助信息或无效参数不会触发快照（#175）。
- 设备授权轮询遇到 429 和 slow_down 时会退避，而不是立即退出（#174）。
- macOS 和 Linux Relay 接收端可指定 Codex 可执行文件；原生投递前的失败归类为拒绝，而非投递后结果未知（#171、#176）。
- Windows Claude 发现会排除已退出或复用的 PID（#173）；Codex 发现会区分尚未保存的活动 writer 与不存在的线程（#166）。
- 更新检查可提示单独安装的 session-peer 技能版本过旧或不兼容，但不会暗中更改它（#167）。
- 可选 Relay 诊断为接收端生命周期添加时间戳、关联尝试，并在不记录消息正文的前提下记录各链路帧进度（#172、#197）。
- Relay control 接受新增指标计数器。Dependabot 版本更新 PR 创建已关闭（#189）。

## 安装

已有包管理器安装请使用常规升级命令，例如 `pipx upgrade session-peer`。新的 Unix 或 WSL 配对设备安装若包含 MCP，可使用 `pipx install 'session-peer[relay,mcp]==1.0.1'`。仅核心功能在 Python 3.9 及以上版本无需外部依赖；Relay 要求 Unix 或 WSL 和 Python 3.11 及以上版本。

由服务管理器启动的 macOS 和 Linux 接收端必须能找到目标 Codex 可执行文件，或配置新的显式可执行文件选项。发送前用 `--dry-run` 确认目标。

## 已知限制

- Cloudflare 到 KR Relay 的间歇性停滞（#161）根因及责任区段仍未确定。新增诊断有助于后续调查，但不证明网络问题已修复。
- 已提交或已排队不代表 ACK。提交后结果未知时不要自动重发。
- 软件包发布不保证托管 Relay 或 OAuth 的可用性。Antigravity 桥接仍为实验性功能。
