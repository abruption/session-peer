# session-peer v1.0.0

首个 v1 稳定版提供已在 RC4 验证的运行时。与 `v1.0.0-rc.4` 相比运行时行为未变，仅升级版本和文档。基本本地/SSH 消息功能仍无依赖。可选 MCP、端到端加密的配对 direct/Relay 消息与受管准入，以及实验性 Antigravity 桥接均需显式启用。

## 验证与变更

- #162 添加逐次尝试的脱敏路径诊断，并仅在提交前的 control/admission 阶段进行一次有界重试。提交后结果不明的消息不会自动重发。
- #168 缩短正常空闲到期后的接收端重连空档，增加 Relay 连接的 10/10 秒 keepalive 和 `receiverRoleBusy`/`clientRoleBusy` 指标。
- 五主机 `rc4-rerun-02` 完成 14,436.65 秒：公开 health 241/241、probe 147/147、提交 21/21、计划内 Relay 重启后 3.182 秒恢复。准确 ACK 为 20/21。原始 T120 Windows native Claude ACK 因 TUI 关闭无法确认；同一路径另一次新的单发检查取得准确 ACK。用户在 #164 接受了这一运维例外，但不能追溯修改原始计数。

## 安装

使用现有的软件包管理器，不要混用安装环境或设备身份。

```bash
# Unix / WSL paired transport and MCP
pipx install 'session-peer[relay,mcp]==1.0.0'
# Native Windows core and MCP (Relay receiver runs in WSL)
pipx install 'session-peer[mcp]==1.0.0'
```

核心需要 Python 3.9+，MCP 需要 3.10+，Relay 接收端/服务器需要 Unix 或 WSL 的 3.11+。由 launchd/systemd 启动的 macOS、Linux 接收端服务 `PATH` 必须包含目标 TUI 的 `codex` 可执行文件目录（#171、#176）。`codexBin` 仅适用于 WSL；请在相同环境用 `send --dry-run` 检查。Relay 设备登录会到期，可能需要重新授权；429/slow_down 在 #174 跟踪。

## 边界

#161 的间歇性 Cloudflare↔KR 传输停滞位置及责任尚未确定。RC4 减轻了放大效应，并未修复底层路径；#161 保持开放并移至 v1.0.1 监控。托管 Relay/OAuth 可用性与软件包发布分开。Windows 发现结果可能保留已退出的 Claude 会话记录（#173）。Antigravity 仍为实验性。submitted/queued 不是消费或 ACK 证据，不得自动重发结果不明的消息。
