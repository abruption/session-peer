# session-peer v0.9.0

可选的 Antigravity 投递和配对设备中继 Beta 版，同时保留现有的 Claude/Codex 本地和 SSH 路径。

- 代理适配器和本地/SSH 传输现在共享显式的身份、功能、执行和结构化错误契约（#47）。
- Antigravity 可以通过在现有已认证 TUI 内部启动的可选桥接进行接收。注册会绑定主目录、进程代际和线程；过期时间和请求限制约束每个桥接（#85）。
- `session-peer[relay]` 添加了设备配对、通过直接 TCP 或 WSS 的固定内部 TLS 1.3、对端吊销、策略受限的原生目标、持久请求回执以及用于 list/send 的 `--device` 集成（#69）。
- 中继准入与设备配对及原生授权相互独立。包含 Linux DynamicUser 部署示例和设置/清理操作手册。
- 配对 `--dry-run` 在不提交消息的情况下解析目标。路由变更保留固定的对端和回执日志。未知结果必须进行调和，不得自动重新发送。
- 提供英文、韩文、日文和简体中文的精简版 README，具有匹配的快速开始和可选功能要求（#92）。完整的 CLI 指南保留在 `docs/cli-reference.md` 中。详细技术文档仍为英文；CLI 输出未本地化。
- 现已提供公开错误/功能模板和私密安全报告指南，并将 `support@abruption.dev` 作为备选私密联系方式（#91）。电子邮件由人工审核，绝不会自动作为议题发布。

## 安装与兼容性

核心功能仍支持 Python 3.9+ 且无运行时依赖。可选的中继功能需要 Unix 和 Python 3.11+：`pipx install 'session-peer[relay]'`。现有通过包管理器安装的用户应使用其包管理器进行升级。独立的 `install.sh` 不安装可选的中继软件包。

Antigravity 为可选功能。默认列表包含 Claude、Codex 以及任何活跃注册的 Antigravity 桥接。配对原生访问需要在接收设备上配置显式策略；仅凭配对不授予原生访问权限。设备管理命令输出 JSON。

## 验证与限制

经用户批准的临时公开 Cloudflare/Caddy WSS 试点投递到了现有的 KR Antigravity 会话，具有独立观察到的模型 ACK，并在重复请求时重用了回执。路由、服务、桥接和测试密钥在事后均被移除；用户的 TUI 保持运行。这是有界的实时 Antigravity 证据，并非实时 Claude/Codex 或长期稳定性证据。

发送结果区分了已提交（submitted）与已消费（consumed）。持久化的意图日志可防止自动重复尝试，但不承诺精确一次（exactly-once）效果；崩溃可能会留下未知结果。测试版没有托管中继、自动 NAT 穿透、自动密钥轮换、日志垃圾回收或配对 wake/Reply-To 路由。运维限制请参阅 `docs/paired-devices.md`。

在 v1.0.0-rc 之前，仍需进行实际设备操作和缺陷解决。此版本不作 v1 稳定性声明。
