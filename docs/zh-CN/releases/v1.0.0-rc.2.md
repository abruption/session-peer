# session-peer v1.0.0-rc.2

这是准备中的候选版本，并非发布公告。RC2 保留 RC1 契约并集成 #158。除明确测试预发布版外，稳定版用户应继续使用 v0.9.2。

## RC1 之后的变更

- #157：将 Windows Claude 注册信息中的 peerToken 映射为协议 token 字段，拒绝无效密钥并保持先认证后消息的顺序。此修复也已在 v0.9.2 发布。
- #153：检查原生 Windows Codex writer 锁、唯一所有者、同用户 SID、可执行文件身份及进程创建时间。未知或歧义证据均被拒绝。
- #156：从 WSL 通过操作员指定的原生 Python 执行 Windows Codex 发现与发送，不再使用 Linux 读取 Windows SQLite/WAL。
- #151：解释不可用的 SSH python3、Windows Store 别名及兼容 POSIX 的远程 shell 要求。此诊断也已在 v0.9.2 发布，但不添加原生 Windows SSH shell 支持。

## 必须迁移的 WSL 策略

- 现有 Windows Codex 绑定必须添加 `codexPython`，即指向已安装的原生 Windows Python 3.9+ `python.exe` 的挂载绝对路径，不可使用 Store 别名或符号链接。参见[配对设备指南](../paired-devices.md)。
- 保留固定的 `codexHome` 与 `codexBin`。接收端不再绕过活动 writer 检查；Linux/macOS 绑定省略两个可执行文件字段。
- 保留设备身份、固定信任、回执、tombstone 和 replay 状态。升级时不要删除状态或重放结果未知的消息。
- 原生 Windows 核心与 MCP 仍受支持。接收端/中继运行时需要 Unix 或 WSL 及 Python 3.11+，不代表支持原生 Windows 中继。

## 发布后安装

配对端点使用相同的包管理方式和精确版本。现有托管安装应在原环境内升级，不要更换其他安装管理方式。

```bash
# Unix / WSL with relay and MCP
pipx install 'session-peer[relay,mcp]==1.0.0rc2'
# Native Windows core and MCP, without relay
pipx install 'session-peer[mcp]==1.0.0rc2'
```

Python/PyPI 版本为 `1.0.0rc2`，GitHub 标签为 `v1.0.0-rc.2`。无依赖核心需要 Python 3.9+，MCP 需要 Python 3.10+。

## 证据与剩余条件

在此次版本更新前，用户独立确认了原生 Windows Codex、公开 Relay → WSL → 原生 Codex，以及已打包稳定版 Claude 修复的精确 ACK。原生 Windows MCP 列表/dry-run 和 SSH 诊断也已通过。这些是修复候选的证据，并非 RC2 全设备安装或连续运行观察通过的证据。

在记录 RC2 验收证据前，保持 #150 与 #151/#153/#156/#157 开启。不要将 `posted` 或 `queued` 等同于消费；没有独立观察到的 ACK 时，`consumptionConfirmed: false` 才是准确状态。

## 发布后验证计划

1. 验证发布的精确标签/提交、wheel/sdist 哈希及全新安装。GitHub 必须标为 prerelease 而非 Latest，稳定版升级仍应选择 v0.9.2。
2. 备份安装文件并创建经批准的一致状态快照后，在 Mac mini、MacBook、quintet-desktop、KR、US 安装精确 RC2。保留生产身份及 replay 状态，不要悄悄更换安装管理方式。
3. 重复发现、JSON schema、诊断、dry-run 与 MCP 策略验证。以新相关 token 和独立实际 ACK 验证 Windows Claude/Codex、WSL→原生 Codex 及 Mac/服务器基线路由。不更改 SSH 设置，验证不支持的原生 SSH 边界提示。
4. 因接收端传输代码已变更，重复 #150 的全主机四小时观察：每分钟健康检查、每五分钟直接/中继探测、T0/T2h/T4h 独立 ACK，并在 T2h 协调一次中继重启。验证重连、吊销/恢复、重复/冲突 ID 及 unknown 结果保留。RC1 证据不能替代 RC2。
5. 按 issue 记录环境、精确构件及脱敏证据。无法解释的失败、缺失 ACK 或前提不足会阻止升级为正式版；不要仅因 PR 合并或 PyPI 发布成功就关闭 RC2 里程碑。

## 发布边界

- 准备不授权创建标签、发布、替换全设备安装或重启生产服务；这些操作需要另行批准。
- Antigravity 仍为实验性功能。托管 Relay/OAuth 健康状态独立于软件包发布。
- 不要为强制 ACK 更改入站权限、重试结果不明的发送、公开凭据或把对端请求当作用户直接批准。
