# v1.4.0发布准备

于2026-11-02基于已发布的v1.3.3准备。在这个注明日期的检查点，v1.4.0仍是未发布的源码候选版本。集成基准为版本准备前的`f290973962c63548f24153eeee12a8e3666fd043`，并非最终发布提交。本准备不授权合并、创建标签或草稿、触发工作流、发布或生产部署。

核心Python 3.9、MCP Python 3.10+及SDK要求`mcp>=1.30,<2`保持不变。

## 变更

- #356 / #361：增加仅返回策略派生元数据的MCP `list_destinations`，最多64个别名，每个别名最多128个UTF-8字节，每次工具结果最多64 KiB，不含JSON-RPC外层封装。此元数据查询也适用于策略版本1和默认策略，不要求策略版本2。它投影所有已配置的策略条目，不按list/Send权限筛选。
- #357 / #362：增加针对单一目标的CLI `--dry-run --explain-json`传递说明。在转换为旧有输出格式前收集原始SSH事实；现有文本和JSON输出契约保持不变。MCP `preflight_send`要求策略版本2中的独立`preflight`权限，preflight不隐含Send权限。Wake preflight还需要单独的wake权限，不启动模型，也不预留wake预算。
- #358 / #363：增加默认模式下需具备`diagnostics`权限的仅元数据诊断。主动探测还需要`diagnostics_probe`，仅支持Mac/Linux，执行上限为3个代理、20秒，不含清理时间；每条管道与结果均限制为64 KiB。非阻塞读取器处理逃离进程范围的管道持有者，清理期间仍优先响应取消。
- doctor中选择的代理与home决定实际收集范围，并跳过共享技能扫描。OK结果表示收集成功，不证明代理可用性、DB认证或反向探测。
- #359 / #364：增加策略版本2的路由预设，采用获准名称和各动作的精确路由。任何Native调用之前都须完成两项检查：先检查路由，再检查其修订；实际发送须显式指定接收目标和修订。单次快照及其`dp1`指纹都不是目标身份或ACK。现有list/send JSON保持不变；安全查询路径不会退回修复操作。预设仍仅支持Mac/Linux上的本地或SSH Claude Code与Codex路由；不扩展wake、URI、Antigravity、device、handoff或Windows支持。
- 发布准备还在MCP preflight中防御性地拒绝普通原生协议的响应根字段（`submitted`、`consumptionConfirmed`、`status`、`dryRun`、`queueId`），因为固定的`send.preflight`模式不包含这些字段。未观察到正常生产CLI的反例、错误路由或安全事件；此防护不增加能力、协议、ACK或权限。内部MCP进程辅助函数现会遵守显式传入的超时值，默认130秒的`CLI_TIMEOUT`行为保持不变；此修正不声称当前正常调用方受到影响或曾发生故障。

## 边界与发布条件

这些扩展不增加新的实际Native/SSH、Windows 3.14或free-threaded验收，不增加ACK、去重或handoff保证，也不增加所属app-server支持或提升支持级别。未知角色与未知结果的限制保持不变；进入队列不代表ACK，不确定性绝不授权自动重试。

审查准确的当前提交，要求当前提交检查与最终受保护main CI成功，并保留所有已发布v1.3.3标签、资产及历史记录。冻结这份不预告发布的日期记录。另行授权的发布必须将包含`SHA256SUMS`和`release-provenance.json`的7个固定资产与准确标签、源码及经过认证的attestation核对，执行依赖审计与全新安装检查，并保留PyPI环境必需的人工批准。省略私有PyPI登录或绑定复查不免除该批准。

更新可用性说明前，须另行记录实际GitHub和PyPI发布依据，不得宣告将来已发布。Python发布、全局MCP环境升级、服务变更、Node Control部署和独立安装的技能均是需要另行授权的操作。
