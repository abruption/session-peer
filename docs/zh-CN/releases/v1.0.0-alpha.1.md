# session-peer v1.0.0-alpha.1

首个可选的 1.0 alpha 版本添加了经过身份验证的公共中继路径，同时保留了来自 v0.9.0 的无依赖本地和 SSH 工作流。

## Highlights

- 通过固定的内部 TLS 1.3 配对设备，并通过直接 TCP 或盲目公共 WSS 发送。中继可以看到路由元数据，但无法解密应用程序消息。
- 使用经过验证的 GitHub 或 Google OAuth 登录，通过浏览器设备代码授权原生 CLI，并将每次中继准入绑定到注册的设备密钥。
- 使用新旧密钥证明、持久操作收据以及未知响应后的恢复来轮换设备密钥。撤销将关闭活动的受管连接。
- 跨重启持久保存已用票据和公共状态修订高水位线。KR 部署包括协调引导、看门狗恢复和加密恢复快照。
- 支持 Claude、Codex 和 Antigravity 原生交付。提交、重复抑制和独立观察到的代理确认仍为不同的结果状态。
- 提供无需邀请或用户数量上限的已验证公开注册。操作员可以在不驱逐已提交身份的情况下关闭新注册，并且仅供操作员使用的聚合指标页面不会公开任何用户或设备标识符。

## Install the alpha

Python 软件包管理器通常不会选择预发布版本。请显式选择加入：

```bash
pipx install 'session-peer[relay]==1.0.0a1'
# or
uv tool install 'session-peer[relay]==1.0.0a1'
```

在两个配对的端点上使用相同的软件包版本。核心仍然支持 Python 3.9+；可选的中继运行时需要 Unix 和 Python 3.11+。

## Alpha boundaries

- 这是一个面向明确测试人员的预发布版本。正常的稳定升级仍将继续选择 v0.9.0。
- 公共中继可用性和 OAuth 提供商策略属于运营服务，与安装软件包是分开的。
- Google OAuth 可能会继续受到提供商测试/发布政策的限制。
- 配对和 OAuth 本身绝不会授予原生代理访问权限。接收端点仍会强制执行其本地策略，且用户会验证实际的代理响应。
- 已完成的证据涵盖独立的 Linux/macOS 测试、实际公共 WSS 配对、重放拒绝、实时撤销、真实代理 ACK、看门狗恢复、KR 重启以及隔离备份恢复。中断的浸泡测试不作为 24 小时通过的声明。
- Windows 保留本地和 SSH 支持；可选的接收器/中继运行时仅限 Unix。

请通过 GitHub issue 报告错误，并通过存储库的私有公告渠道报告安全问题。不要在报告中包含令牌、设备密钥、证书、会话 ID 或对话内容。
