# session-peer v1.0.4

2026-10-07维护版本：v1.0.4是v1.0.3的后续版本，以下六项经过审核的修复已整合到main。包发布不包含运营部署；请在GitHub/PyPI确认发布状态。核心本地/SSH命令仍在Python 3.9+上无需外部依赖；Relay和MCP仍为可选功能，Antigravity桥接仍属实验性。

## 变更

- MCP通过验证规范主机选项，再次接受有效的文件型SSH策略 (#262)。SSH目的地限制、允许列表及获准Codex home仍被执行。
- SSH将已启动但未完成的发送分类为`outcome_unknown`，并设为`retryAllowed: false`，不暗示成功或可安全重试；Codex队列超时保留同样的不确定性 (#263)。完整的版本化结果和拒绝在传输失败后仍保留。旧发送字典仅在普通退出0/1/2、精确布尔值`ok`及缺省或匹配的command时保持兼容；错误字典及异常旧格式退出不是完成证据。
- 配对设备帧统一包含发送者信封的32 KiB UTF-8消息预算、64 KiB转义后应用JSON预算及包含运营人员绑定的256 KiB原生worker JSON预算 (#264)。Unicode与大量转义输入在应用写入、原生副作用或发送意图记录之前检查。已确定超限请求被拒绝；后续不确定I/O仍为unknown。路由准备后仅在应用提交前刷新期限，保留原始请求ID和正文，不重发。
- 辅助远程版本探测失败不再丢弃成功的SSH会话列表 (#265)。会话、主机/发现元数据和主退出状态保持不变，以有限的版本未知原因替代原始诊断。主要失败及严格远程更新验证不变。
- Control锁文件将source-map-js从1.2.1更新至1.2.2，针对GHSA-68fv-2mgg-jv7q恢复运行时依赖审计前提 (#266)。这是仅锁文件的补丁，不是托管Control部署，也不宣称设备群补救已完成。
- Claude发现与doctor共享具有严格UTF-8、JSON对象及字段类型验证的1 MiB限制注册表读取器 (#267)。它拒绝符号链接、非普通文件、身份替换及超限增长，关闭已打开描述符，并保留健康行及权限诊断。POSIX使用nonblocking/no-follow打开检查；兼容Python 3.9的Windows回退不保证等效POSIX标志或通用文件系统读取时限。
- 兼容性技能快照保持0.3.2，最低运行时0.9.1及完整功能运行时1.0.1。这些独立兼容性版本不替代已发布的1.0.3安全建议，Python升级也不更新独立管理的技能。

## 安装与升级边界

使用现有安装管理器；包发布不授权设备群安装或静默替换其他安装：

```bash
pipx upgrade session-peer
# New Unix / WSL installation with optional Relay and MCP:
pipx install 'session-peer[relay,mcp]==1.0.4'
```

核心要求Python 3.9+，MCP要求3.10+，Relay接收端/服务端使用Unix或WSL和Python 3.11+。服务管理的接收端需要服务PATH中的Codex或运营人员拥有的codexBin绑定。dry run解析目标，不证明原生副作用或模型ACK。此版本不扩大SSH、配对或运营人员绑定权限。[v1.0.3安全说明](v1.0.3.md)、现有允许列表及配对审核要求、已验证的不可变单文件资产仍适用；已发布的公告/CVE历史不是新的v1.0.4披露或状态复验。
