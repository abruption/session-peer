# v1.3.3维护准备

于2026-10-30以已发布的v1.3.2为基准准备。在当时的准备检查点，v1.3.3尚未发布，仅作为候选版本。集成源码基准是版本准备前的`ec2f7fc808f1e22519348091d51c28a2fd522caf`，并非最终发布提交。本工作仅准备可供审查的变更，不授权合并、创建标签或发布。

## 变更

- #349 / #352: 将PR模板的默认引用改为不会关闭issue的`Refs`，明确标示有意完成，并要求相关验证与版本依据。只读警告使用受信任main的代码和有限的PR正文判定规则。它不执行正文，不写入issue状态，也不是GitHub完整的关闭引用解析器，更不保证issue不会关闭。
- #350 / #353: 扩展Ubuntu/macOS上常规启用GIL的CPython 3.14 CI。核心覆盖Ubuntu/macOS的3.9/3.13/3.14，并保留Windows 3.13；MCP保留3.10/3.13/3.14的SDK下限1.30.0与最新兼容1.x配置，共12个单元；Relay覆盖3.11/3.13/3.14，共6个单元。3个打包与安装单元是Ubuntu 3.13、Ubuntu 3.14和macOS 3.14。分类器包含3.14，Python下限仍为核心3.9、MCP 3.10、Relay 3.11。参见[源码测试矩阵](https://github.com/abruption/session-peer/blob/ec2f7fc808f1e22519348091d51c28a2fd522caf/tests/README.md)。
- #351 / #354: 当前README的发布说明不再固定某个最新版本，另行添加带日期的v1.3.2发布记录。保留历史准备记录，明确既有发布后检查表，并纠正四种语言Direct指南中过时的未发布表述。
- 将兼容副本及将来的`SKILL.md`支持资产同步至独立发布的[Python技能v0.4.1](https://github.com/abruption/session-peer-skill/releases/tag/v0.4.1)。这是兼容副本更新，并非发布新技能或更新另行安装的技能。

## 范围与发布门禁

3.14检查属于测试夹具及软件包验证，并非新的实际原生代理、Windows 3.14或free-threaded Python验收。版本更新和文档变更不增加运行时认证、协议、传递或ACK行为。未知结果、禁止自动重发和实验功能的既有边界保持不变。

上述集成源码基准的[CI](https://github.com/abruption/session-peer/actions/runs/40982760413)和[CodeQL](https://github.com/abruption/session-peer/actions/runs/40982759604)均成功。这些结果不能替代准备提交或最终受保护main源码的检查。 首先在[初始CI](https://github.com/abruption/session-peer/actions/runs/40880779432)中通过新增的10个3.14单元后，才加入分类器，随后[更新后的完整CI](https://github.com/abruption/session-peer/actions/runs/40882642483)也成功。

保留已发布v1.3.2的标签、资产和带日期记录。审查准确的准备提交并要求该提交的检查成功，之后的发布步骤前还须确认受保护main的CI成功。另行授权的发布必须将包含`SHA256SUMS`与`release-provenance.json`的7个固定资产，与准确标签、源码及经过认证的attestation对照，测试全新环境安装，并保留PyPI环境必需的人工批准。省略私有PyPI登录或连接复查不代表免除该批准。取得实际GitHub和PyPI依据后，采用既有发布后文档检查表；不得提前宣称可用。

本准备不执行服务部署或重启、全局安装或独立技能发布。Node Control部署以及接收端和技能环境更新，仍为需要另行授权的运维工作。
