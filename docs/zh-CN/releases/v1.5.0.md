- 依赖维护包括#386 GitHub Actions更新、#383 Hatchling 1.33.0、#385 Vitest 5.1.0，以及#382 Vite 8.3.6和@rolldown/pluginutils 1.0.1。构建、CI和开发工具与无外部依赖的基本CLI及运行中服务的环境相互区分。
- #379仅更新测试依赖Paramiko 5.1.0及对应的测试断言。Paramiko仍仅用于测试，生产SSH行为不变。

## 兼容性与验证边界

基本Python 3.9、可选MCP的Python 3.10及Relay的Python 3.11下限不变。Node引擎保持`^22.13.0 || ^24.0.0`，`@types/node`仍为24，`better-sqlite3`仍为12.6.2。Control保持非公开版本0.1.0，不包含在Python wheel/sdist中；服务部署是独立操作。

构建解释器边界：[Hatchling 1.32.4](https://pypi.org/pypi/hatchling/1.32.4/json)及[Hatchling 1.33.0](https://pypi.org/pypi/hatchling/1.33.0/json)的公开元数据均要求Python 3.10+。这是既有构建工具要求，并非提高基本运行时下限。Python 3.9的基本安装使用通用wheel或独立文件路径；直接构建sdist需要Python 3.10+构建解释器。本次准备不宣称已测试Python 3.9的sdist构建。

MCP候选方案在macOS/Linux与Python 3.10/3.13/3.14上配置四个组合（`minimum`、`latest1`、`minimum2`、`latest2`），共24个CI单元。各组合保留解析得到的版本和运行时依赖审计报告，但不会测试所有传递依赖包各自的最低版本。这是检查配置，并非声明待运行的CI已通过。须取得确切准备HEAD及最终受保护main提交的结果。客户端／协议测试与限制参见[MCP指南](../mcp.md#sdk2-compatibility-candidate)。

64 KiB结果限制是上限，并不保证接受所有更小的结果。SDK 2即便连接旧协议，也会在大小计算中包含新版服务器身份元数据，因此可能保守拒绝接近上限的结果。项目内部结果JSON及批准、提交、消费、ACK的区别不变。不宣称完成新的真实代理、SSH、Windows、真实OAuth或既有数据库验证。#387/#388及研究Draft #246/#248不在此次范围内。
