## 变更

- #341 / #342：保留接收端启动时的`ready:true`，增加`directReadyConfirmed:false`，以区分本地监听器建立与远程可达性。TLS完成本身不能证明配对完成、原生目标访问或ACK。
- 显式启用的`--diagnostic-events`增加Direct回调及TLS观测，以及有上限的每个接收端的`accepted`、`tlsCompleted`、`tlsFailed`计数器。`accepted`和`peer_tls`阶段合计每60秒最多记录2条；TLS成功和失败共享后者的阶段限制。正常关闭时额外尝试记录1次包含零计数的`summary`，重复关闭不会再次尝试。固定字段不包含地址、对端/会话ID、消息数据或异常原文。日志失败不会替换原始握手异常。现有同步stderr输出在目标阻塞时没有强制超时机制。
- 实验性TCP探测脚本处理Python 3.9/3.10中的`asyncio.TimeoutError`，并在Python 3.9/3.13上运行了回环无响应回归测试。手动的双Mac及tailnet实验与CI分开；`experiments/`不包含在wheel/sdist中。请参阅[实验记录](https://github.com/abruption/session-peer/blob/dac1c30b1553136b9379be0c6d94eef34ccbad51/experiments/macos-direct-listener/README.md)。
- #343 / #345：将Node Control的`better-auth`和`@better-auth/core`固定版本从1.7.5更新至1.7.7，并对齐适配器及telemetry版本。上游将1.7.7列为[GHSA-965c-763c-88jm](https://github.com/advisories/GHSA-965c-763c-88jm)（严重）、[GHSA-r4xp-prcw-77qf](https://github.com/advisories/GHSA-r4xp-prcw-77qf)（高）及[GHSA-44jh-23m7-hpcf](https://github.com/advisories/GHSA-44jh-23m7-hpcf)（低）的首个修复版本。
- #344 / #345：同步SIGINT测试夹具，仅在进入受保护的读取区间后发送READY。它处理macOS Python 3.13中观测到的信号终止(-2)与预期已处理退出130之间的竞争；变更针对测试同步，不改变产品信号行为。不使用固定sleep或弱化断言替代该边界，也未确定历史CI失败的准确原因。

- #346 / #347：将可选MCP SDK要求提高至`mcp>=1.30,<2`。核心Python 3.9下限及MCP Python 3.10+标记保持不变。POSIX CI包含8个单元：Mac/Linux、Python 3.10/3.13，以及精确下限`1.30.0`或最新兼容`1.x`这2种SDK配置。间接依赖仍按通常规则解析；下限配置不代表验证所有软件包的最低版本。已安装SDK的标准输入输出（`stdio`）契约检查不能证明HTTP/OAuth暴露或可利用性。

PR #345的两项门禁修复已作为分别审查过的提交合并，PR #347的MCP下限及CI配置也已合并。审查的PR #347提交通过了包括全部8个MCP单元在内的32项检查；自动Codex代码及安全审查也分别完成且无发现。这些PR结果不能替代受保护最终main的验证或发布证据。合并发布准备PR前仍须确认当前main检查成功。

## 原因与兼容性边界

所有者允许Python.app接收入站连接后，两台Mac均使用原先已发布的v1.3.1 Homebrew Python 3.14.9运行时、相同的tailnet绑定地址及各自相同的端口，完成了Direct配对和已认证probe。试验使用新的身份，原生调用为0次，不需要转发进程或替代解释器。这一结果支持macOS应用程序防火墙等待批准是本次事件的阻断原因；连接并非由诊断代码恢复。此前的阴性、签名及转发对照是历史观测，不是必需的补救办法，也不是对所有macOS、Tailscale或Python问题的通用诊断。

Direct绑定、TLS与认证检查、截止时间、配对状态及禁止自动重试的行为均保持不变。不自动修改防火墙、访问策略或选择运行时，也不增加平台或通用ACK支持。未重试或重置现有用户的pending状态。原生代次标识、handoff、存储及启动验收条件(#180/#181/#268/#304/#306/#307)和Side Session、steering研究仍为独立工作。

可选Relay接收端模块的变更包含在wheel/sdist中，不嵌入独立脚本`session_peer.py`。应用诊断功能需要更新接收端自身的软件包和环境，并明确重启其进程；仅更新独立脚本不会更新这些模块。此次发布不执行运行环境更新或重启。

检查的Control源码使用SQLite及`bearer`、`deviceAuthorization`插件，未使用公告中的Magic Link/OAuth Proxy/PostgreSQL路径；未证实部署环境中的可利用性。Node Control依赖修复不包含在Python wheel/sdist中，需另行批准服务部署。请审查上游OAuth验证标识符前缀变更，并协调共享验证存储的服务器升级；更新后，正在进行的OAuth登录可能需要重新开始。此次准备不执行运行环境部署、会话吊销或数据迁移。

兼容技能保持v0.4.0，最低运行时0.9.1 / 文档CLI功能覆盖基准1.3.0；接收端`codexBin`的最低版本仍为1.0.1。未变更的SHA-256为`debedd472e3b0c0c6844fb63f7fb2f17cb6c6cc8c3e981e9afd2531a35327af7`。运行时发布不会更新独立管理的技能或部署正在运行的服务。
