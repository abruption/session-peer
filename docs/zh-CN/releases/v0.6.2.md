# session-peer 0.6.2

此版本在重复保存的线程具有明确的唯一存活写入器时选择活动的 Codex 主目录，并使 SSH 账户选择和连接失败对调用方可见。

## 变更

- 通过确切的线程写入器锁、内核建议锁探测以及两次稳定的 `lsof` 所有者观察，验证包含目标 UUID 的每个已知 Codex 主目录。恰好一个同一用户的存活写入器可以选择目标；竞争、不完整或不断变化的证据将在排队前失败。
- 在调用 `codex queue` 之前立即重新验证所有竞争的候选主目录，并在 `codexHomeResolution` JSON 中公开带 schema 版本的决策和有界证据。
- 当自动检测到的返回路由指向发送机器时，生成本地回复命令，避免不必要的自我 SSH 登录。
- 对于远程投递，赋予显式 `USER@HOST` 优先级。否则，通过 `ssh -G` 使用与连接相同的别名和选项解析有效账户，并在 JSON 中报告 `sshUser` 及其来源。
- 对 SSH 身份验证、主机密钥、超时以及其他传输失败进行分类。身份验证失败指向 `USER@HOST` 或别名的 SSH `User` 设置；session-peer 不会猜测账户或使用其他用户名重试。
- 在探测远程独立版本时保留 SSH 失败详细信息，而不是将每次连接失败都报告为安装缺失。

## 兼容性与限制

- 显式 `--codex-home` 仍是最强的目标选择器，并会绕过自动多主目录活动解析。发现仍受限于所选/默认主目录、已配置主目录以及受支持的 Orca 账户主目录。
- 自动存活写入器选择需要目标端上的 POSIX 建议锁和 `lsof`。当必须解析重复保存的主目录时，缺失工具、权限失败或冲突证据将遵循故障关闭。
- 解析出的 SSH 用户是配置证据，并非身份验证一定会成功的证明。Session-peer 不会发现凭据或更改 SSH 配置。
- 已排队的消息仍不能证明消费或确认。回复等待、远程路由验证和更广泛的诊断仍保留在 v0.7 路线图中。

## 升级

使用管理该安装的包管理器：

```bash
pipx upgrade session-peer
uv tool upgrade session-peer
python -m pip install --upgrade session-peer
```

独立安装可以运行 `session-peer update`。当捆绑的 Claude skill 也需要刷新时，从 v0.6.2 检出中重新运行 `install.sh`。
